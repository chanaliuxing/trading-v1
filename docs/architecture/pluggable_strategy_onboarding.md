# Pluggable Strategy Onboarding Contract

This checklist is mandatory for every new strategy instance before it is allowed
onto the paper or production runtime surface. A strategy that cannot satisfy the
contract must remain shadow-only.

## Required Identity

Every strategy instance must have a durable identity. Do not use only
`strategy_id + symbol` as a lane key.

Required fields:

- `account_id`
- `strategy_id`
- `strategy_instance_id`
- `symbol`
- `asset_type`
- `session_policy`
- `flow_type`
- `order_role`
- `lot_id` for position-owning flows
- `position_owner_key` for restart, flatten, protection, and fill attribution

`strategy_instance_id` must be stable across restart. If a strategy is cloned for
testing, the clone must receive a different `strategy_instance_id`.

## Session Policy

Each strategy must declare one policy:

- `RTH_ONLY_EQUITY`: entry blocked outside RTH; close-only and flatten may run
  for owned positions.
- `EXTENDED_EQUITY`: entry allowed in configured PRE/POST/OVERNIGHT sessions
  when broker truth, runtime freshness, and risk are good.
- `OPTIONS_RTH_ONLY_DEFAULT`: options entry blocked outside RTH unless an
  explicit extended-options policy exists.
- `TEST_EXTENDED`: off-hours tests allowed only under explicit account, symbol,
  and strategy risk caps.

EOD/session policy must be scoped by `account_id + strategy_instance_id + symbol`.
It must not create a platform-wide lock unless the blocker is a true global halt.

## Tradability

Strategies must request authorization from `TradabilityService` before every
entry, scale-in, exit, protective, close-only, and flatten flow.

Entry flows:

- `ENTRY`
- `SCALE_IN`

Override-capable flows:

- `EXIT`
- `SCALE_OUT`
- `STOP_LOSS`
- `TAKE_PROFIT`
- `TRAILING_STOP`
- `STRATEGY_FLATTEN`
- `PROTECTIVE_REPAIR`

Emergency flow:

- `ACCOUNT_EMERGENCY_FLATTEN`, only with explicit emergency/manual/admin scope.

Strategies must not treat `production_state.go_no_go=go` as execution authority.
Execution must evaluate the exact tradability scope again.

## Owner Lane

Orders, fills, protection, flatten actions, and replay must preserve owner lane:

- `account_id`
- `strategy_id`
- `strategy_instance_id`
- `symbol`
- `lot_id`
- `position_owner_key`
- `order_role`

Unknown owner fills must go to `UNKNOWN_OWNER` or manual review. They must not be
assigned by symbol, active strategy, order-ref prefix, or substring matching.

Flatten and close-only flows must inherit the owner lane from the position or
durable order row. They must not create a different restart lane.

Protective orders must also have a durable cleanup path. If broker truth and the
strategy ledger prove the owner lane is flat, any live stop-loss or take-profit
order for that lane is stale and can open a reverse position. Paper strategies
may enable `reconciliation.runtime.flat_protective_auto_cancel_enabled`; the
runtime reconciler then cancels only exact broker-order-id matches after DB,
broker position, and broker open-order evidence are present. The default remains
report-only for environments that have not opted in.

Paper deployments can also enable
`production.position_safety_supervisor.flat_live_safety_order_auto_cancel_enabled`.
This is the startup/readiness cleanup path for broker-live close orders that no
longer have an open `core_order` row but still have an exact durable
`broker_order_id` row. It must never cancel from symbol-only evidence.

`core.core_position` is a restart cache, not an ownership source. A stale
non-flat cache row may be cleared only when broker truth has no aggregate
position for the symbol, `core.position_ledger_current` is flat for the exact
`strategy_id + symbol` owner lane, and there are no nonterminal orders for that
same lane. Broker aggregate flat evidence alone must never overwrite a virtual
strategy position.

## Broker Truth And Protection Refs

New stock plugins must use order refs that can be attributed without symbol-only
heuristics.

`strategies.stocks_kernel.execution.order_identity` is the single parser and
builder surface for stock-kernel order refs. Do not add local ad hoc parsers in
strategy modules, broker truth modules, recovery modules, or tests.

Accepted entry/flatten refs must be generated by the execution kernel and have a
durable binding. Protection refs must use the explicit owner format:

```text
sl:<account_id>|<strategy_instance_id>|<symbol>|...
tp:<account_id>|<strategy_instance_id>|<symbol>|...
```

Broker truth sync may treat an unbound protection ref as known only when the
owner fields are complete and `strategy_instance_id` exactly matches the current
strategy and the broker symbol agrees with the owner symbol. It must ignore
another strategy instance's protection refs for the current strategy's mismatch
detection. It must not infer ownership from symbol, order-ref prefix,
substring, or active strategy.

Malformed protection refs and protection refs whose embedded symbol conflicts
with the broker order symbol remain orphan orders and must fail closed.

## Recoverable Kill Switches

Some symbol kill switches are allowed to self-release only after runtime evidence
proves the original unsafe condition has converged.

Flat-convergence release requires all of these:

- position safety is `go`
- active manual lock count is zero
- active quarantine count is zero
- position safety has no record for the symbol
- live broker truth is `go`
- broker has no position for the symbol
- broker has no open order for the symbol

This release path currently covers:

- `unsafe_position_without_protection`
- `live_position_missing_protection`
- `flatten_not_converged_timeout`

Do not add a new recoverable reason unless it has a focused unit test and the
release predicate is backed by broker truth and position safety artifacts.

## Same-Symbol Strategy Policy

Two strategy instances trading the same account and symbol are not automatically
allowed to enter concurrently. The default is conservative account-symbol
isolation:

- one strategy instance with a live position or open protection orders can block
  another strategy instance's entry on the same account/symbol
- this is a scoped block, not a global halt
- `production_state.go_no_go=go` can coexist with `entry_go_no_go=partial`

If a new strategy intentionally requires parallel same-symbol entries, it must
declare and test the account/symbol risk policy explicitly. Do not rely on
different `strategy_id` values alone as permission to overlap exposure.

## Manual Lock Behavior

Manual and recovery locks must be scoped whenever owner identity is complete.

Owner-scoped flatten or close-only locks block entry only for the matching
account, strategy instance, symbol, and lot. They must not become
`GLOBAL_HALT`.

Global halt remains required for:

- broker truth missing, stale, or not broker-backed
- position safety missing, stale, or truly unsafe
- runtime freshness stale
- manual recovery required
- unreconciled order truth
- unresolved account/symbol ledger divergence
- safety kernel global emergency halt

## Manifest Requirements

Each strategy config must include:

- unique `strategy_instance_id`
- explicit `account_id`
- explicit symbols and asset types
- session policy
- tradability reporting enabled
- owner-lane fields in order extras
- expected data subscriptions
- risk caps
- production permission tier

Missing manifest fields fail the strategy manifest gate.

## Observability

Every strategy heartbeat must include:

- `strategy_id`
- `strategy_instance_id`
- `symbol`
- current session
- tradability decision authority
- flow type
- allow/deny
- blockers
- overrides
- owner identity completeness
- reason

Production state may report `entry_go_no_go=partial`. That means some scopes are
blocked and some are tradable. It is not a platform execution authorization.

## Minimum Tests

Add or update tests for every new strategy:

- manifest gate accepts the strategy only with full identity
- tradability evaluator allows configured sessions and blocks disallowed sessions
- execution entry requires `TradabilityDecision.allow`
- manual lock blocks only matching `strategy_instance_id`
- same-symbol strategy instance is not blocked by another instance unless policy
  explicitly uses account-symbol isolation
- same-symbol account isolation blocks another strategy instance when policy is
  conservative and one lane has live position/protection orders
- fill attribution preserves owner lane after restart
- broker truth sync accepts exact own `sl:/tp:` protection refs and ignores
  foreign owner-lane protection refs
- malformed or symbol-mismatched protection refs remain orphan orders
- flatten inherits owner lane and clears close-only locks when flat
- stale flatten timeout kill switch releases only after broker and position
  safety prove flat convergence
- production state shows scoped blockers, not a global halt, for session/manual
  entry blockers
- no-live unit tests do not connect to IBKR

## Release Gate

Before enabling paper or production:

```bash
TRADING_TEST_ALLOW_LIVE_IBKR=0 venv/bin/python -m pytest -q tests/unit/safety/test_no_live_ibkr_in_unit_tests.py
TRADING_TEST_ALLOW_LIVE_IBKR=0 venv/bin/python -m pytest -q tests/unit/services
TRADING_TEST_ALLOW_LIVE_IBKR=0 venv/bin/python -m pytest -q tests/unit/exec
TRADING_TEST_ALLOW_LIVE_IBKR=0 scripts/run_ib_reconnect_regression.sh fast
git diff --check
```

Runtime verification:

- one `run_system.py` process only
- paper mode uses `127.0.0.1:4002`
- `production_state.global_halt=false`
- `safety_go_no_go=go`
- scoped blockers explain any `entry_go_no_go=partial`
- both signal and execution audit include the same `strategy_instance_id`
- no symbol-only attribution markers appear
- for same-symbol strategy pairs, verify whether the intended policy is
  conservative isolation or explicitly permitted parallel exposure
