# Trace and ID Spec

## Purpose
Define strict ownership, format, and propagation rules for IDs used in strategy/execution/reconciliation.

## ID Inventory
- `strategy_id`: static logical strategy identifier from config.
- `strategy_run_id`: generated when strategy instance starts or reloads.
- `trigger_id`: generated at market-event ingress; synthetic if legacy path.
- `decision_id`: generated by strategy decision logic.
- `intent_id`: generated by execution ingress from idempotency key.
- `order_id`: generated by execution persistence.
- `broker_order_id`: broker-provided identifier.
- `parent_order_id`: netted parent internal order ID.
- `fill_id`: broker exec id or deterministic fallback hash.
- `trace_id`: end-to-end correlation ID.
- `causation_id`: immediate parent event ID.

## Generation Rules
- UUIDv7 is the default format for generated IDs.
- Ownership:
  - strategy lifecycle service owns `strategy_run_id`
  - market ingress owns `trigger_id`
  - strategy owns `decision_id`
  - execution ingress owns `intent_id`
  - order persistence owns `order_id`
  - broker adapter owns `broker_order_id` and preferred `fill_id`
- If `trace_id` is absent at ingress, generate synthetic UUIDv7 and set `trace_source=synthetic`.

## Propagation Rules
- Critical events must carry: `strategy_id`, `decision_id`, `trace_id`, `order_id`.
- `trace_id` never changes within one decision lineage.
- `causation_id` must point to parent event in `core_order_event`.

## Idempotency
- Required key: `strategy_id + strategy_run_id + decision_id + symbol + normalized_target_qty + ts_bucket`.
- Duplicate key returns previous `intent_id` and does not place new live order.

## Netted Accounting
- Invariant: `parent_fill_qty = Σ child_fill_qty ± residual`.
- Residual allocation order: highest remaining unfilled child first, then stable tie-break by child intent timestamp.

## Lifecycle
- `strategy_run_id` rotates on:
  - process restart of strategy instance
  - hot reload
- `strategy_run_id` does not rotate on transient broker reconnect.
