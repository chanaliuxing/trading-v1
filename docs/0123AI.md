## 启用大脑 loop（auto_loop）的前提，系统在各个时段做什么，特别是夜间与周末如何管理机器学习。
内容基于我们拍板的
  配置与最近落地的改动（预检降级、预算、限频与门控、事件触发、A/B 管理等）。

  全局行为（任何时段都生效）

  - 常驻组件
      - 控制事件消费者：订阅 Kafka internal.control；OOF 完成等事件到达时，立刻刷新 afterhours 计划（不等下一时段）。
      - 并发与上限：llm_trader.max_concurrent=1；Prompt challenger 注入可控（Paper=启用；Prod=视负载与审批）。
  - 数据与门控
      - 数据就绪/质量门控：RTH 内快速回补（fast path）+ 夜间系统回补（OOF 质量差触发）；DQ 黑名单在计划归一化时自动过滤。
      - 训练预算：hpo_budget（max_rounds、time_budget_min、mem_budget_gb、trial/training窗口/符号TopK）。
      - Round 0 预检降级：一进入重活前就“降维开跑”（1符号/30天/10 trials/n_jobs=1/threads=2–4；网格先裁≤200组合；float32 分
        块载入）。
      - 部署硬门槛：OOS min_sharpe=1.40、max_mdd=0.10、min_trades=80、min_coverage=0.85、min_pf=1.20、
        min_expectancy_usd>0、min_return≥0，未达不落地。
  - 风控与限频
      - risk_policy 限频：同一“事实签名”（risk_config+reflection.facts+当日交易聚合）且未过最小间隔（~3h）则跳过，避免凌晨
        无意义重复。
      - 周末守护 TTL：learn 至少间隔 60 分钟再触发，不以“进程是否退出”作为唯一条件。
  - 审批与角色
      - Paper：autosettings.enabled=true/require_approval=false（达标即应用）。
      - Prod：require_approval=true（只写审计/候选，审批后落地）。

  时间段行为

  - 07:00–09:30 MORNING
      - 计划与准备：大脑 propose_plan("morning")，归一化（间隔下限、符号填充、DQ 过滤、AB 权重），风险预交易守门（必要时
        pause/manage_only）。
      - prompt 覆盖：按 plan 的 execution_prompt_id 生成覆盖映射（ID 白名单；默认禁 raw 文本）。
      - 启动盘前 bot（严格 bounded：cycles 或 close_at）；导出健康/事件快照；无重型 ML。
  - 09:30–16:00 INTRADAY
      - 计划与运行：propose_plan("intraday") → 归一化 → 风险守门 → 启动/对齐 bot。
      - 风险与对冲：Guardian/kill-switch 触发时可写 overlay/options_hedge 计划，并在 auto_execute=false 下 dry-run 审计
        （Pilot 后可小额开启）。
      - 实时观测：每小时记忆快照；工具看门狗；事件导出。
      - ML 重活不在此时段；但若夜间 OOF 事件迟到，消费者会即时刷新计划（轻量级）。
  - 16:00–20:00 AFTERHOURS
      - 轻任务：计划/对齐/审计；按 TTL 触发一次 OOF flow（若日间缺失或质量差）。
      - 准备夜间学习：采集当天决策/一致性/市场上下文，沉淀为 reflection 输入。
  - 20:00–次日 07:00 OVERNIGHT（核心学习时段）
      - OOF 流水线（XGB+LSTM）
          - 生成两条 OOF → 质量评估（AUC/IC/coverage）→ 质量差则小回补/策略微调重评（TTL 次数有限）→ 选/更新融合策略权重
            （policy 驱动）。
          - 发布 OOF 完成事件（Kafka+ai_events.jsonl），消费者收到后即时刷新计划。
      - Alpha Loop（Walk-Forward HPO）
          - Round 0 预检降级（预算优先）→ 运行回测/HPO → 不达标进入“预算内自适应重试”（最多 4 轮，逐轮放宽/收缩符号、窗口、
            trial 数），MemGuard/并发=1 始终开启。
          - 达标才落地到 config.yml（Paper 直落，Prod 审批）；否则只审计并提出保守 pending_actions。
      - 强化学习（可选）
          - 夜间训练+评估 gate；仅当 gate 通过时才建议 enable_rl，否则建议保持关闭。
      - Prompt 演进
          - 反思（consistency_job）→ prompt_evolver 生成战术建议 → 合成一个新 Prompt ID 写入白名单 → 次日作为 challenger 参
            加 AB（权重默认 0.7/0.3）。
      - 组合与对冲
          - 组合权重规划与 overlay/options 计划（先 dry-run），审计与事件落盘。
      - 数据落盘与报告
          - memory episode、日报（含每轮 HPO 指标/内存峰值/网格剪裁/门控结果/是否落地）；失败则 stop-loss 与下一步建议。
      - 退出条件
          - 达成门槛提前退出，或耗尽 time_budget/min_rounds 后止损退出；不会无限循环。
  - 周末/节假日 WEEKEND（学习守护）
      - 仅学习：不启动盘中交易序列；weekend_supervisor 每 ≥60 分钟触发一次 learn（带 TTL 锁与事实签名限频）。
      - 与夜间 OVERNIGHT 相同的学习链路与预算/门控；OOF/HPO/RL/Prompt/对冲全走“证据驱动 + 预算内自适应重试”，产物落盘与事件
        发布。
      - 避免“无交易历史”的重复风控问询：facts_sig+最小间隔生效。

  - 参数：OOS 门控达标（+审批条件）才写回 config.yml；未达标不落地，仅审计+保守 pending_actions（如提高 conf_floor、缩
    小 sizing）。
  - Prompt：夜间生成的新 ID 自动作为次日 challenger 参加 AB（白名单 ID，禁 raw 文本），不改变 champion 的稳定性与风险敞口。
  - 融合模型：OOF 对比与 policy 更新后，执行层读取融合权重；次日按新权重产生信号。
  - RL：仅在 gate 为真时才切换 enable_rl；否则保持关闭。
  - 风控/对冲：Guardian/kill-switch 时段内可触发干预或对冲；对冲默认 dry-run，在 Pilot 通过后小额实单。

  验证与可观测

  - 产物目录：runs/ai_trader/当日/（brain_plan_.json、reflection.json/…_dxp.json、prompt_suggestions.json、oof_eval/、
    ensemble_compare/*、alpha_loop_round_k.json、daily_report.md、events/hedging/guardian 日志等）。
  - 事件：OOF/HPO/RL 完成通过 Kafka 发布；消费者日志可见“即时刷新计划”。
  - 审计：risk_policy/skipped_same_facts；HPO gate reasons；网格剪裁 before/after；mem_peak_mb；是否落地与回滚线索。
  - SLO：风险问询夜里≤3次/日；OOM=0；OOF 事件→计划刷新延迟<10s；回路成功率>80%。

  一句话总结

  - auto_loop 常驻按时段路由，白天以“交易与风险”为主，夜间与周末以“学习与优化”为主；所有落地动作都受预算、限频与硬门槛约束；结果能通过事件驱动“即时进入”次日计划，同时又不会自旋或打爆资源。
