## 二、4B-1：HPO / 回测 ➜ 写 ExperimentRecord / StrategyManifest

### 4B-1.1 约定几个关键 ID

先约定三个最重要的 ID（建议保持简单、一致）：

* `run_id`：每次 HPO/backtest 产出的“策略运行”的唯一 ID

  * 建议形式：`{symbol}_{yyyyMMdd}_{horizon}_{short_name}_{hash}`
  * 例：`NVDA_20250310_10m_v3fast_7f3a2c`
* `strategy_id`：可以等于 `run_id`，或者用于把多个 run 归到一个长线策略族
* `experiment_id`：如果你一次 HPO 里试了很多 trial，可以视整次 HPO 为一个 experiment，`run_id` 是里头的 best trial

> **简单做法**：先不纠结 experiment vs run，直接以 `run_id == strategy_id` 落地，后面再抽象。

### 4B-1.2 在 HPO 结束处填充 `StrategyManifest` + `ExperimentRecord`

假设你有类似这样的 HPO 结果结构（伪代码）：

```python
@dataclass
class HPOResult:
    best_model: Any
    best_params: Dict[str, Any]
    metrics: Dict[str, float]
    feature_names: List[str]
    label_id: str
    horizon: str
    symbol: str
    table: str
    # ...
```

4A 里 Claude 应该已经给你类似的类型：

```python
# strategies/manifest.py
@dataclass
class StrategyManifest:
    strategy_id: str
    run_id: str
    model_type: str
    storage_uri: str         # 模型文件路径
    feature_names: List[str]
    label_id: str
    horizon: str
    symbol: str
    table: str
    created_at: str
    backtest_metrics: Dict[str, float]
    config: Dict[str, Any]   # 包含 HPO 设置、训练计划等
```

我们要在 HPO 完成后：

1. **保存模型到磁盘**（或 S3/MinIO，先本地就好）
2. 构造一个 `StrategyManifest`
3. 构造一个 `ExperimentRecord` / `ExperimentManifest`（包含更完整的上下文）
4. 调用 `ExperimentRegistry.append(record)` 写入 JSONL/目录

### 4B-1.3 具体落地伪代码（改 `wf_hpo.py` 的收尾部分）

```python
from datetime import datetime
from pathlib import Path
import joblib
import json

from strategies.manifest import StrategyManifest
from experiments.registry import ExperimentRegistry, ExperimentRecord  # 4A 里应该已经有

def run_hpo_and_register(...):
    # 1. 跑完 HPO，得到 best result
    hpo_result: HPOResult = run_hpo(...)  # 你现有逻辑

    # 2. 生成 run_id
    run_id = make_run_id(
        symbol=hpo_result.symbol,
        horizon=hpo_result.horizon,
        label_id=hpo_result.label_id,
        model_type=hpo_result.best_params.get("model_type", "xgb"),
    )

    # 3. 保存模型 (本地版本)
    model_dir = Path("models") / hpo_result.symbol / run_id
    model_dir.mkdir(parents=True, exist_ok=True)
    model_path = model_dir / "model.joblib"
    joblib.dump(hpo_result.best_model, model_path)
    storage_uri = str(model_path)

    # 4. 构造 StrategyManifest
    manifest = StrategyManifest(
        strategy_id=run_id,
        run_id=run_id,
        model_type=hpo_result.best_params.get("model_type", "xgb"),
        storage_uri=storage_uri,
        feature_names=hpo_result.feature_names,
        label_id=hpo_result.label_id,
        horizon=hpo_result.horizon,
        symbol=hpo_result.symbol,
        table=hpo_result.table,
        created_at=datetime.utcnow().isoformat(),
        backtest_metrics=hpo_result.metrics,
        config={
            "hpo_params": hpo_result.best_params,
            "hpo_config": hpo_result.hpo_config,      # 如果有
            "training_plan": hpo_result.training_plan # 如果有
        },
    )

    # 5. 写 manifest.json（方便单独查看）
    with (model_dir / "manifest.json").open("w", encoding="utf-8") as f:
        json.dump(dataclasses.asdict(manifest), f, ensure_ascii=False, indent=2)

    # 6. 构造 ExperimentRecord（4A 里已经有类型）
    exp_record = ExperimentRecord(
        run_id=run_id,
        symbol=hpo_result.symbol,
        table=hpo_result.table,
        horizon=hpo_result.horizon,
        label_id=hpo_result.label_id,
        metrics=hpo_result.metrics,
        strategy_manifest=manifest,
        created_at=datetime.utcnow().isoformat(),
        # 这里可以塞更多：PIResult.feature_recipe / dataset_quality 等
        meta={
            "feature_recipe": hpo_result.feature_recipe,
            "dataset_quality": hpo_result.dataset_quality,
        },
    )

    # 7. 通过 registry 写入 index(JSONL / 目录)
    registry = ExperimentRegistry(root="experiments")  # Claude 应该已经写了
    registry.append(exp_record)

    return exp_record
```

> 核心思想：
> **从现在开始，每次 HPO 完成，不只是“返回一个 best_model”，而是“生成一个完整的 StrategyManifest + ExperimentRecord”并写入 registry。**
> 之后 AI 大脑 & live trading 全都只认这些 run_id/manifest。

## 三、4B-2：模型运行时 / Loader（让 manifest 真的能“跑”）

有了 `StrategyManifest` 之后，要让 live 系统做到：

* 给你一个 `run_id` 或 `StrategyManifest`
* 你能拿到一个 **统一接口的对象**，比如：

```python
class StrategyRuntime(Protocol):
    def predict(self, X: pd.DataFrame) -> np.ndarray:
        ...

    @property
    def feature_names(self) -> List[str]:
        ...
```

### 4B-2.1 定义 Runtime 类型 & 工厂函数

```python
# strategies/runtime.py

from dataclasses import dataclass
from typing import Any, List
import joblib
import xgboost as xgb
from sklearn.base import BaseEstimator
import pandas as pd
import numpy as np

from strategies.manifest import StrategyManifest

@dataclass
class LoadedStrategy:
    manifest: StrategyManifest
    model: Any

    def predict(self, df: pd.DataFrame) -> np.ndarray:
        # 1) 按 manifest.feature_names 取列并排序
        X = df[self.manifest.feature_names].astype("float32")

        # 2) 按 model_type 分派
        mt = self.manifest.model_type

        if mt in ("xgb", "xgboost"):
            dmatrix = xgb.DMatrix(X)
            return self.model.predict(dmatrix)

        # sklearn 家族
        if isinstance(self.model, BaseEstimator):
            return self.model.predict_proba(X)[:, 1] if hasattr(self.model, "predict_proba") else self.model.predict(X)

        # fallback：直接调用 model.predict
        if hasattr(self.model, "predict"):
            return self.model.predict(X)

        raise TypeError(f"Unsupported model type for runtime: {type(self.model)}")

def load_strategy(manifest: StrategyManifest) -> LoadedStrategy:
    model = joblib.load(manifest.storage_uri)
    return LoadedStrategy(manifest=manifest, model=model)
```

> 后续如果你有 torch / lightgbm / catboost，只要在这里加分支即可。
> 所有 live 代码只跟 `LoadedStrategy` 交互，不关心底层是啥。

## 四、4B-3：接入 Live Orchestrator & AI 大脑

目标是：

* **离线阶段**：HPO 写好 ExperimentRecord + StrategyManifest
* **开盘前**：AI 大脑看历史 performance / 当前目标，从 ExperimentRegistry 中选出一组 run_id
* **盘中**：Orchestrator 按这组 run_id 加载模型 ➜ 用实时 features 预测 ➜ 经过 risk gate ➜ 产生订单

### 4B-3.1 大脑输出结构（BrainDecision）

你在 4A 里应该已经有类似的 schema，例如：

```json
{
  "decision_id": "20250310-preopen-NVDA",
  "mode": "select_strategies",
  "symbol": "NVDA",
  "allowed_runs": [
    {"run_id": "NVDA_20250305_10m_v3fast_7f3a2c", "weight": 0.6},
    {"run_id": "NVDA_20250227_10m_conservative_21d9ab", "weight": 0.4}
  ],
  "notes": "Prefers more recent high-Sharpe runs; volatility elevated so mix with conservative."
}
```

### 4B-3.2 Orchestrator: 维护一个 `active_strategies` 映射

在你的 live orchestrator（假设叫 `ai_trader/orchestrator.py`）中，加一层：

```python
# ai_trader/orchestrator.py

from strategies.runtime import load_strategy, LoadedStrategy
from experiments.registry import ExperimentRegistry

class LiveOrchestrator:
    def __init__(self, ...):
        self.registry = ExperimentRegistry(root="experiments")
        self.active_strategies: Dict[str, List[LoadedStrategy]] = {}  # symbol -> [LoadedStrategy]

    def apply_brain_decision(self, decision: BrainDecision) -> None:
        symbol = decision.symbol
        runs = decision.allowed_runs

        loaded: List[LoadedStrategy] = []
        for item in runs:
            run_id = item["run_id"]
            rec = self.registry.get(run_id)  # 4A: 从 index 里查 ExperimentRecord
            manifest = rec.strategy_manifest
            loaded.append(load_strategy(manifest))

        self.active_strategies[symbol] = loaded
```

### 4B-3.3 盘中 tick/bar 处理逻辑

原来你的逻辑大概是：

```python
def on_bar(self, symbol: str, bar: Bar, features: pd.Series, gates: Dict[str, Any]):
    # 这里以前可能直接 call LLM 决策 or 规则策略
    ...
```

现在我们扩成：

```python
def on_bar(self, symbol: str, bar: Bar, features: pd.Series, gates: Dict[str, Any]):
    strategies = self.active_strategies.get(symbol) or []
    if not strategies:
        return  # 没有被大脑选中的策略，直接不交易

    df = pd.DataFrame([features])  # 单行 DataFrame

    raw_signals = []
    for strat in strategies:
        preds = strat.predict(df)  # np.ndarray, shape (1,)
        score = float(preds[0])
        raw_signals.append(
            {
                "run_id": strat.manifest.run_id,
                "model_type": strat.manifest.model_type,
                "score": score,
            }
        )

    # 然后你可以有一个统一的信号融合逻辑
    final_decision = self._aggregate_signals(
        symbol=symbol,
        bar=bar,
        signals=raw_signals,
        gates=gates,
    )

    self._execute_decision(symbol, final_decision)
```

`_aggregate_signals` 可以很简单：

* 按大脑给的 weight 做加权平均
* 与 risk gate（RVOL、spread、max position）结合
* 把最后结果（比如 long/short/hold + size）交给已有的 execution engine

## 五、推荐的实施顺序（避免一次性炸裂）

你现在的状态：4A 已经搭好数据结构，**非常好**。我建议 4B 分三小步来做：

### Step 1：离线闭环（不接 live，只接 HPO）

1. 在 HPO / backtest pipeline 的末尾，按上面的伪代码：

   * 生成 `run_id`
   * 保存模型 `model.joblib`
   * 写 `manifest.json`
   * 通过 `ExperimentRegistry.append()` 写 `ExperimentRecord` 到 JSONL
2. 写一个简单的 `offline_playground.py`：

   * 手动从 registry 里 `.list_best(symbol="NVDA", horizon="10m")` 取几个 run
   * 用 `load_strategy()` load 出来
   * 在某段历史 bars 上跑一遍 predict，确保结果正常、不报错

> 这个阶段**完全不涉及 AI 大脑、也不涉及下单**，只解决“策略能不能被 load + predict”的问题。

### Step 2：接入 AI 大脑（但只模拟）

1. 用 registry 提供的数据构造一个简单的 context，喂给大脑，让它输出 `allowed_runs`。
2. 写一个 `brain_simulator.py`：

   * 读某天的历史 K 线
   * 用大脑 output 的 run_id 设置 `active_strategies`
   * 模拟 `on_bar()` 跑完整天，输出信号/虚拟 PnL
   * 不连 IBKR，只打印/存日志

> 这个阶段验证的是：**大脑选策略 + runtime 预测 + 聚合逻辑**是否跑通。

### Step 3：接入 live / paper trading

1. 在现有 live orchestrator 中：

   * 增加 `apply_brain_decision()` 和 `active_strategies` 映射
   * 在每天开盘前跑一遍大脑，设置 active_strategies
2. 先接 **paper trading** 或 “只下 very small size / 仿真账户”
3. 加一层保护：如果加载策略失败 / 预测报错，自动 disable 该 run_id，避免实盘炸掉。
