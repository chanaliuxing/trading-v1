# 1) 更新 Grafana 数据源（含 Loki→Tempo 的 trace 关联）

```yaml
apiVersion: 1
datasources:
  - name: Loki
    uid: loki
    type: loki
    access: proxy
    url: http://loki:3100
    isDefault: true
    jsonData:
      maxLines: 5000
      # 从日志 JSON 里提取 trace_id，并提供两个链接：
      # 1) 打开 Tempo 查看该 trace
      # 2) 回到本仪表盘并设置变量 var-trace_id
      derivedFields:
        - name: trace_id
          matcherRegex: '"trace_id":"([a-f0-9]{32})"'
          datasourceUid: tempo
          url: "$${__value.raw}"            # 点击 → 在 Tempo 打开该 trace
        - name: goto_dashboard
          matcherRegex: '"trace_id":"([a-f0-9]{32})"'
          url: "/d/trading-trace/trading-trace-and-logs?var-trace_id=$${__value.raw}"  # 点击 → 回到本仪表盘并带入变量
  - name: Tempo
    uid: tempo
    type: tempo
    access: proxy
    url: http://tempo:3200
  - name: ClickHouse
    uid: ch
    type: grafana-clickhouse-datasource
    access: proxy
    jsonData:
      defaultDatabase: trading
      xAxis: time
    secureJsonData:
      host: http://<your-clickhouse-host>:8123
      username: default
      password: ""
```

> 注意：`<your-clickhouse-host>` 改成你环境能连到 ClickHouse 的地址。

## 说明与小贴士

* **Panel #10（堆叠时序）**：按 `reason` 聚合的时间序列，快速看哪个原因在主导。
* **Panel #11（Top-N 原因表）**：以当前时间范围统计总次数，默认取 Top 10。
* **Panel #12（按组件拆分）**：哪一层拦截最多（Strategy / Overlay / SimAdapter 限价 / 等等）。
* **Panel #13（样本日志）**：点开任意行可看到 `reason_detail`、`sig/conf/limit_price/bar_vol/...`。
* **Panel #14（按策略拆分的速率）**：多策略时，定位是哪个策略在大量被拦截。

> 若你的日志字段名不同（例如没有 `strategy_id`），把相应 LogQL 的 `| json | strategy_id != ""` 片段删掉即可。
> 若你看到 `topk(...)` 报告宏变量问题，把 `[${__range_s}s]` 替换成具体窗口（如 `[1h]`）快速验证；多数 Grafana 版本已支持该宏。
