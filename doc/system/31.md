好的，我来拍板：在“执行安全内核”之上，优先把**强一致撤单/改单状态机（Cancel/Replace State Machine, CRS）**补齐——这是避免“幽灵订单”、止损保护缺口、以及 IB 接口偶发异常的最关键一环。下面给你**可直接粘贴**的最小可用骨架（不生成文件），与你上一个“安全内核”代码无缝对接。

---

# 目标与要点（超短版）

* **强一致**：撤单/改单不是“发一次就算”，而是直到**收到权威完成信号**（状态流 + open_orders 二次确认）才算成功。
* **三段式**：`REQUESTED → PENDING_ACK → FINALIZING`（轮询确认）→ `DONE/FAILED`，超时自动**指数退避重试**。
* **兜底策略**：撤单失败时——
  1）若是**保护单**（止损/止盈）→ 先确保**另一腿已取消**；
  2）若仓位暴露 → **紧急平仓 Stop-MKT**；
  3）领养遗留单（open_orders）避免“幽灵”。
* **OCO 不变量**：同组仅1腿存活；一腿成交→另一腿**必须取消成功**。
* **指标**：耗时、重试、升级、失败原因、在途撤单计数。

from prometheus_client import Counter, Gauge, Histogram

MET.update(dict(
  crs_cancel_inflight = Gauge("crs_cancel_inflight","inflight cancels"),
  crs_cancel_req      = Counter("crs_cancel_requested_total","cancel requested",["kind"]),  # ENTRY/STP/TP/OTHER
  crs_cancel_ok       = Counter("crs_cancel_ok_total","cancel ok",["kind"]),
  crs_cancel_fail     = Counter("crs_cancel_fail_total","cancel fail",["kind","reason"]),

  crs_replace_req     = Counter("crs_replace_requested_total","replace/modify requested"),
  crs_replace_ok      = Counter("crs_replace_ok_total","replace ok"),

## 三、核心：CRS 状态机（可直接贴入 “安全内核” 文件，类内引用 `self.adapter` 与 `self.cfg`）

```python
import random
from dataclasses import dataclass
from enum import Enum, auto

class CRSState(Enum):
    REQUESTED = auto()
    PENDING_ACK = auto()
    FINALIZING = auto()
    DONE = auto()
    FAILED = auto()

@dataclass
class CancelJob:
    order_id: int
    kind: str         # ENTRY/STP/TP/OTHER（用于指标分流）
    attempts: int = 0
    state: CRSState = CRSState.REQUESTED
    t0: float = 0.0   # 启动时间
    last_ts: float = 0.0
    reason: str = ""

class CancelReplaceSM:
    """
    强一致撤单/改单状态机：
      cancel(order_id, kind) -> bool
      replace(order_id, **fields) -> bool
    依赖:
      - self.adapter.cancel / self.adapter.modify
      - self.adapter.open_orders() 权威快照
      - 上游状态流 (exec.order.status.v2) 会异步到达，CRS 不直接消费消息，只做主动轮询与超时控制
    """
    def __init__(self, kernel: "SafetyKernel"):
        self.k = kernel   # 引用安全内核，方便访问 cfg/adapter/MET

    async def cancel(self, order_id:int, kind:str="OTHER") -> bool:
        job = CancelJob(order_id=order_id, kind=kind, attempts=0, state=CRSState.REQUESTED)
        MET["crs_cancel_req"].labels(kind=kind).inc()
        MET["crs_cancel_inflight"].inc()
        try:
            backoff = 0.2
            job.t0 = job.last_ts = time.time()
            while job.attempts < self.k.cfg.cancel_max_attempts:
                job.attempts += 1
                await self.k.tb_cancel.wait()
                ok = await self.k.adapter.cancel(order_id)
                if not ok:
                    MET["crs_cancel_retry"].inc()
                    await asyncio.sleep(backoff)
                    backoff = min(backoff*2, 2.0)
                    continue

                job.state = CRSState.PENDING_ACK
                # 等状态 ACK 窗口
                deadline = time.time() + self.k.cfg.cancel_ack_timeout_s
                while time.time() < deadline:
                    # 快路径：看看 open_orders 里是否还在
                    if not await self._still_open(order_id):
                        job.state = CRSState.FINALIZING
                        break
                    await asyncio.sleep(self.k.cfg.cancel_poll_interval_s)

                # FINALIZING：二次确认窗口
                if job.state == CRSState.FINALIZING:
                    fin_deadline = time.time() + self.k.cfg.cancel_finalize_timeout_s
                    while time.time() < fin_deadline:
                        if not await self._still_open(order_id):
                            job.state = CRSState.DONE
                            MET["crs_cancel_ok"].labels(kind=kind).inc()
                            MET["crs_cancel_latency"].observe((time.time()-job.t0)*1000.0)
                            return True
                        await asyncio.sleep(self.k.cfg.cancel_poll_interval_s)

                # 走到这里说明 ACK 或 FINALIZING 未确认成功 → 重试
                MET["crs_cancel_retry"].inc()
                await asyncio.sleep(backoff + random.uniform(0, 0.1))
                backoff = min(backoff*2, 3.0)

            # 超过最大尝试
            job.state = CRSState.FAILED
            job.reason = "max_attempts"
            MET["crs_cancel_fail"].labels(kind=kind, reason=job.reason).inc()
            return False
        finally:
            MET["crs_cancel_inflight"].dec()

    async def replace(self, order_id:int, **fields) -> bool:
        MET["crs_replace_req"].inc()
        backoff = 0.2
        attempts = 0
        t0 = time.time()
        while attempts < self.k.cfg.replace_max_attempts:
            attempts += 1
            await self.k.tb_modify.wait()
            ok = await self.k.adapter.modify(order_id, **fields)
            if ok:
                MET["crs_replace_ok"].inc()
                return True
            MET["crs_replace_fail"].labels(reason="modify_failed").inc()
            await asyncio.sleep(backoff + random.uniform(0, 0.1))
            backoff = min(backoff*2, 3.0)
        return False

    async def _still_open(self, order_id:int) -> bool:
        try:
            # 这里用全量 open_orders()，生产里可维护本地缓存并周期同步以降频
            opens = await self.k.adapter.open_orders()
            return any(o.order_id == order_id for o in opens)
        except Exception:
            # 查询失败时，保守地认为“仍然打开”，避免误判
            return True
```

## 四、把 CRS 接到“安全内核”（3 处替换）

### 1）在 `SafetyKernel.__init__` 里加：

```python
self.crs = CancelReplaceSM(self)
```

### 2）把你内核里**所有直接调用** `self.adapter.cancel(oid)` 的地方，替换为：

```python
ok = await self.crs.cancel(oid, kind="ENTRY")   # 入场单
# or kind="STP" / "TP" 对保护腿
```

例如 `_cancel_all()` 改为：

```python
async def _cancel_all(self, plan:Plan):
    ids = list(plan.entry_order_ids)
    if plan.stop_order_id: ids.append(plan.stop_order_id)
    if plan.tp_order_id:   ids.append(plan.tp_order_id)
    for oid in ids:
        kind = "ENTRY"
        if plan.stop_order_id == oid: kind = "STP"
        elif plan.tp_order_id == oid: kind = "TP"
        ok = await self.crs.cancel(oid, kind=kind)
        if not ok:
            MET["kern_err"].labels(op="cancel_fail").inc()
```

### 3）把 `modify(...)` 的地方替换为 CRS 的 `replace`：

```python
await self.crs.replace(plan.stop_order_id, qty=need_qty)
await self.crs.replace(plan.tp_order_id, qty=need_qty)
```

## 五、OCO 不变量与兜底逻辑（两条“红线”）

把这段加在 `_ensure_oco()` 最末尾，作为**一致性巡检**的兜底（可复用现有 `_inspector()` 调用）：

```python
# 若发现一腿已成“FILLED/INACTIVE”，另一腿仍 open → 必须强撤
if plan.stop_order_id and await self.crs._still_open(plan.stop_order_id) and \
   plan.tp_order_id and not await self.crs._still_open(plan.tp_order_id):
    await self.crs.cancel(plan.stop_order_id, kind="STP")

if plan.tp_order_id and await self.crs._still_open(plan.tp_order_id) and \
   plan.stop_order_id and not await self.crs._still_open(plan.stop_order_id):
    await self.crs.cancel(plan.tp_order_id, kind="TP")

# 红线：首填后保护窗口超时仍未 attach → 紧急兜底
if plan.first_fill_ts_ms and not plan.protection_attached:
    dt_ms = time.time()*1000 - plan.first_fill_ts_ms
    if dt_ms > 1000:  # 1s SLO
        await self.emergency_flatten(plan)
```

## 六、启动顺序与最小自测

1. **先**启动你的 IB 适配/模拟（或继续使用上次的 `MockIB`）。
2. **再**启动“安全内核”加载 CRS：能看到指标端口（9105）。
3. 向 `risk.decision.v2` 发一个批准消息（入场 LMT）。
4. 伪造 `exec.fill.v2`（首填）→ `_ensure_oco()` 挂保护腿。
5. 伪造一条腿成交（或直接在适配里模拟 open_orders 只剩一腿）→ 巡检触发另一腿强撤。
6. 故意让 `adapter.cancel` 返回 `False` 数次 → 观察 `crs_cancel_retry_total` 增长，成功后 `crs_cancel_latency_ms` 有观测；超过 `cancel_max_attempts` → `crs_cancel_fail_total{reason="max_attempts"}` 增长，同时（若暴露）`emergency_flatten` 触发。

---

## 七、为什么这一步必须现在做

* 真实市场里**最痛的事故**不是“少赚”，而是**保护单丢失/幽灵单**带来“多开/反向”风险；CRS 是把这类黑天鹅概率降到最低的“硬核闸门”。
* 它**不改变**你的策略与风控层接口，只把执行路径**变可靠**；失败有**明确升级路径**（重试→强撤→兜底平仓）。
* 有了它，你可以更大胆地上**动态止损/追踪改价**，因为撤改动作有了强一致保障。
