# 一、Grafana 大盘（Prometheus）

## 怎么用

* 数据源选你的 **Prometheus**。
* 粘贴下面 JSON 导入；仪表会自动识别我们在代码里暴露的指标：

  * 账本（Portfolio）：`pf_*`
  * 风控（Risk）：`risk_*`
  * IB 账户桥：`ib_account_*`、`ib_position_*`

> 变量：`strategy`（从 `pf_capital_available{strategy=...}` 自动抽取），`account`（从 `ib_account_cash{account=...}` 抽取）。

### 建议告警（Grafana Alert / PromQL）

* **风控延迟过高**
  `histogram_quantile(0.95, sum by (le)(rate(risk_eval_latency_ms_bucket[5m]))) > 400` 持续 2 分钟
  动作：告警到 Pager；自动把 `max_concurrent_plans` 下调 50%（可通过 StateBus）。
* **资金预留失败激增**
  `increase(pf_reserve_rejected_total[10m]) / increase(pf_reserve_requested_total[10m]) > 0.2`
  动作：暂停大额策略组，拉取账本与 IB 可用资金核对。
* **可用资金低水位**
  `pf_capital_available{strategy="$critical"} < 0.1 * strategies_capital_limit{strategy="$critical"}`
  动作：切 `TRADING_GLOBAL=PAUSE`，排查异常预留或挂单未释放。

> 注：如果某些 `_bucket` 指标还没出现，是正常的（Prom 直方图在进程热身后才会有数据）。大盘会自动显示其它曲线。

# 二、GameDay 故障演练清单（灰度前必做）

> 在 **Staging** 或 **小资金实盘**进行；一项一项过，全部通过后再扩大权重。

## 0. 演练前准备

* ✅ 打开 Grafana 大盘，上述 4 个分区都应有数据。
* ✅ 确认能一键切换 **Kill-Switch**：`RUN/PAUSE/FLATTEN`（StateBus）。
* ✅ 准备 Kafka 工具（如 `kafkacat/kcat`）用于注入/暂停话题。

---

## 1) **IB 断线**（网络闪断 30–60 秒）

* **触发**：防火墙阻断 `tcp/7497` 或直接断 TWS 网络分享（Paper 可拔网线模拟）。
* **预期**：

  * IBInsyncAdapter 重连协程在 ≤2s 触发重连；
  * 事件桥发送中断但不崩溃；
  * 执行内核不再尝试下单/改单（被 Redis 限流排队并超时丢弃）；
  * 风控继续批准/拒绝，但**不会下发**到执行（内核打印“连接不可用/限流失败”）。
* **通过标准**：无崩溃；风险/账本/策略持续运行；恢复连接后 1 分钟内执行回到正常速率。
* **回滚**：恢复网络；确认 `openTrades()` 可读，订单状态开始刷新。

## 2) **撤单失败 / OCO 破裂**

* **触发**：手动在 TWS 取消其中一条 OCO 腿，同时阻塞 API 2–3 秒（模拟竞争窗口）。
* **预期**：

  * CRS 巡检在 1–5s 内发现另一腿未撤，触发**强一致撤**；
  * “孤立腿”在下一轮被取消或标记 `STALE_CLOSED`。
* **通过标准**：大盘“资金事件”图不出现异常的重复预留；订单无“反向开仓”。
* **回滚**：如有残留手动撤销；核对账本释放。

## 3) **Kafka 卡顿 / Topic 积压**

* **触发**：降低 Kafka broker 带宽或暂停消费者（如暂停 Risk/Portfolio），让 `exec.fill.v2` 积压。
* **预期**：

  * 执行内核不依赖 `fill` 也能保持 OCO（不会重复补单）；
  * 账本的预留释放可能滞后，但**不会再次批准超额**（预留是幂等）。
* **通过标准**：无异常 NACK；恢复消费者后，账本释放事件与状态回补正确。
* **回滚**：恢复消费；观察 10 分钟内积压清零。

## 4) **ClickHouse 读失败 / 数据缺口**

* **触发**：关掉 CH 30 秒，或让 Facade 查询报错（防火墙阻断 8123）。
* **预期**：

  * 策略 **DQ Gate** 生效：本轮跳过决策，硬止损兜底不触发下单；
  * 大盘的“Intent 进入速率”下降，但系统无报错风暴。
* **通过标准**：没有因为数据缺口而产生订单；恢复后策略自动继续。
* **回滚**：恢复 CH；确认 `bars()` 正常、策略恢复发意图。

## 5) **并发大单风暴 / 限流校验**

* **触发**：同时触发 10–20 个策略发单（可以用策略 Shadow Mode 注入）。
* **预期**：

  * Redis 桶：`place/modify/cancel` 命中限流，部分排队到超时丢弃，内核记录“rate-limited”；
  * Risk 审批通过率下降，但**无 pacing 错误**；
  * 账本预留/释放保持平稳。
* **通过标准**：IB 不报 `pacing violation`；Grafana 延迟在可接受范围（风控 p95 < 400ms）。
* **回滚**：降低策略并发/调大桶参数。

## 6) **全局急停 / Panic Flatten**

* **触发**：设置 `TRADING_GLOBAL=FLATTEN`。
* **预期**：

  * 风控拒绝所有新意图；
  * 执行内核：取消挂单 + 市价平仓；
  * 账本在订单终态后释放全部预留；
  * 大盘“可用资金”上升到上限附近，“UPNL”归零。
* **通过标准**：2 分钟内系统无持仓、无挂单。
* **回滚**：切回 `RUN`；小额测试单验证恢复。

## 7) **账本数据库异常（PG 不可用）**

* **触发**：暂停 PG；
* **预期**：

  * Risk `reserve()` 事务失败 → 直接 `REJECTED(reserve_failed)`；
  * 执行内核不下单；
  * 恢复后自动恢复。
* **通过标准**：无“未预留下单”的情况；系统不崩。
* **回滚**：恢复 PG；检查 `reservations` 一致性。

## 8) **Redis 宕机（限流失效）**

* **触发**：停 Redis；
* **预期**：

  * 令牌桶 `acquire` 失败 → 内核视为**拒绝**（保护模式），而不是无脑直冲；
  * 风控/账本仍正常。
* **通过标准**：无 pacing 错误；下单速率显著下降。
* **回滚**：恢复 Redis；观察速率恢复。
