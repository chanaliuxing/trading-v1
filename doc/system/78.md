# 0) 目标与退出标准

**目标**

* 用**同一套代码路径**跑：历史回测（Backtest）、事件回放（Replay）、仿真撮合（PaperSim）、影子交易（ShadowLive）。
* 复用 P4–P9 的所有环节（就绪门 / Admission / 断路器 / 预留 / OCO / 账本），仅将**券商适配层**切换为模拟撮合器。
* 可**确定性重现**：同 seed、同参数、同数据 → **完全一致**的订单/成交/PNL 序列。
* 大规模：能做**参数网格 / 滚动回测**与**批量策略**并行。

**P10 退出标准（全部满足=完成）**

1. **同源码**下，Backtest 与 ShadowLive 的**决策一致率 ≥ 99%**（价差<1 tick，触发时刻<1s）；
2. PaperSim 的**成交均价**与真实历史成交基准（1m/5m 聚合校验）误差 ≤ **1%/1tick**（取较严）；
3. OCO/反手/时间止损逻辑在模拟中**0 违规**，与实盘编舞一致；
4. Portfolio（P7）在模拟下的 NAV 曲线与“用同价标记”的实时基准差异 ≤ **2‰**；
5. 任意一次回测均可**run_id** 重跑复现（bitwise 等价的订单/成交日志）。

# 1) 运行形态与“同 API”开关

四种模式共享**策略 API**（DSL 引擎 / StrategyAlgorithm），通过**环境开关**切换：

| 模式         | 数据源                                   | 执行适配器                 | 时钟        | 用途        |
| ---------- | ------------------------------------- | --------------------- | --------- | --------- |
| Backtest   | CH 历史（bars_250ms/1s/5s, ticks_raw 可选） | SimAdapter（撮合模型）      | EventTime | 研究/参数寻优   |
| Replay     | 实盘“事件日志”或 CH 复写                       | SimAdapter（仅回放，不二次下单） | LogTime   | 事故复盘/一致性  |
| PaperSim   | 实时 250ms bars                         | SimAdapter（仿真撮合）      | WallClock | 影子金丝雀     |
| ShadowLive | 实时 250ms bars                         | 双路：SimAdapter & IBKR  | WallClock | 线上 A/B 比对 |

**切换点**：仅替换 `BrokerAdapter` 为 `SimAdapter`，其它环节（P5 特征、P6 执行状态机、P7 账本、P9 Admission）**原封不动**。

# 2) 数据契约与时钟

* **事件时间（EventTime）**为王：回测/回放均以 `bar.window_end` 或 `tick.ts_event` 为驱动，不允许 lookahead。
* **数据层级**：优先 `bars_250ms → 1s → 5s`；如需微观触发（stop/limit intrabar 触发次序），可启用 `ticks_raw`。
* **交易日历**：使用统一 `calendar`（市场开闭/半日）决定可下单时段与撮合可用性。
* **公司行为**：CH 提供 `corp_actions`（split/dividend），Backtest/Replay 统一**前复权**或**现金入账**（可选）。

# 3) 模拟撮合器（SimAdapter）——与 IBKR Adapter 同接口

```python
class SimAdapter(BrokerAdapter):
    async def send(self, req) -> BrokerAck: ...
    async def cancel(self, oid) -> None: ...
    async def replace(self, oid, new_px, new_qty) -> BrokerAck: ...
    async def open_orders(self) -> List[BrokerOpenOrder]: ...
    async def subscribe_exec(self, on_status, on_fill): ...
```

## 3.1 撮合基元（可配置，带 deterministic RNG seed）

* **簿模型**：Top-of-book 或 2–5 档近似（可选）。默认 **Top-of-book + 体积模型**：

  * 每个窗口（250ms/1s）给定 `trade_vol` 与 `spread`；
  * 深度估计：`depth = k · trade_vol`（k≈1.5–3，可分买/卖）。
* **限价单（LMT）**

  * 价格穿越时成交：

    * 多单：`limit >= low_intrabar`；空单：`limit <= high_intrabar`；
  * **排队位置**：入队位置 `q0 = ρ·depth`（ρ∈[0,1] 来自 seed）；
  * 成交量按“对手盘流入量”消化队列：`fill = min(q_remaining, flow_in)`；支持部分成交。
* **市价单（MKT）**

  * 以 `mid ± ½*spread` 基准；
  * **冲击成本**：`impact = γ·(qty/depth)^α`（α≈0.5–1，γ 可按标的流动性分层）；
  * 成交价 = 基准 ± impact。
* **止损/止损限价（STP/STPLMT）**

  * 触发：多仓止损在 `low_intrabar <= stop`，空仓在 `high_intrabar >= stop`；
  * STP → 转市价按 MKT 规则；STPLMT → 触发后按 LMT 规则，若触发窗内未成交可延续。
* **OCO**

  * 按 P6 的 OCO 看门狗逻辑执行“一腿触发另腿取消”；**撮合层不绕开**策略。
* **时间止损**

  * 撮合时钟到达期限 → Cancel + MKT 平仓。

> 所有随机性只来自 `ρ`、`impact` 的扰动，统一 `run.seed` 控制；**同 seed 完全一致**。

## 3.2 延迟与错误模型

* **网络/券商延迟**：ACK 延迟 `t_ack ~ U[10,30]ms`（可配）；
* **撮合延迟**：撮合完成回报 `t_fill ~ U[5,20]ms`；
* **拒单模型**：价格越带、停牌/SSR/LULD、账户/策略配额等 → 与 P6/P9 相同拒单码；
* **限流**：超 `pacing_ms` → `DELAYED` 状态回报；
* **故障注入**（可选）：一定概率掉 ACK、短时不可成交、价差扩宽，用于鲁棒性测试。

# 5) 特征与“就绪门”（P5 复用）

* Backtest 运行时：

  * **两种策略**

    1. **离线预计算**：先用 CH 物化任务计算 `features_*`；回测读取成品特征（快）；

* “就绪门”逻辑**保持一致**：历史不足/落后 → 当次 skip。

# 6) 成本、合规与现金事件

* **佣金/费用**：按 IBKR 或自定义费表（分层：per share / per notional / min fee），入账到 `cash_events`。
* **借券/融资**：按日费率、标的等级（易借/难借）模拟，T+1 记入 `cash_events(kind='BORROW')`。
* **分红**：从 `corp_actions` 导入；多仓 +，空仓 -（按股数乘息）。
* **滑点**：MKT/触发单的冲击成本模型，参数可按 ATR/成交量分层。

# 7) 配置与可复现性

**运行配置（YAML）**

```yaml
run_id: auto                 # = hash(code_rev,param_hash,data_rev,seed,timerange)
mode: backtest|replay|papersim|shadow
seed: 20251002
universe: [AAPL, MSFT, NVDA]
timerange: {start: 2025-08-01T13:30:00Z, end: 2025-08-15T20:00:00Z}
cadence_overrides:
  meanrev_v2:A: 5
  trend_v1:B: 10
sim:
  lob: top_of_book
  depth_k: 2.0
  impact: {gamma: 0.8, alpha: 0.7}
  ack_ms: [10,30]
  fill_ms: [5,20]
costs:
  commission: {per_share: 0.0035, min: 0.35}
  borrow_bps: {default: 50, hard_to_borrow: 400}
  fees: {sec: true, ta: true}
```

**run_id 组成**
`run_id = sha1(code_rev + param_hash + data_rev + seed + timerange + universe)`

* `code_rev`：Git 提交；`param_hash`：DSL/策略参数哈希；`data_rev`：CH 分区水印；
* 所有输出（订单/成交/PNL/指标）带 `run_id`，可一键对比/复现。

# 8) 输出与评估

**ClickHouse 输出表**

* `sim_orders`（结构与 `orders_ch` 一致，额外字段 `run_id, mode`）

**评估指标**

* **绩效**：Ann. Return、Vol、Sharpe、Sortino、MaxDD、Calmar、WinRate、Payoff、Turnover、Holding Time
* **执行**：VWAP slippage、到价率、拒单率、平均排队深度、OCO 触发比
* **稳定性**：参数扰动敏感度（±10%）、不同种子方差、不同成本曲线稳健性

**一致性衡量（与实盘）**

* 决策一致率（信号是否同向同价带触发）
* 成交均价与滑点差异（按 1m/5m 基准）
* OCO/反手编舞差异计数（目标=0）

# 9) 网格/滚动回测（Batch & Walk-Forward）

* **参数网格**：将 DSL 参数 JSON 化，每个组合一个 `param_hash` 与 `run_id`；并行跑（多进程/多机）。
* **Walk-Forward**：`train_window → validate_window → slide`；参数选择依据：最大化 OOS Sharpe/Calmar 并约束 Turnover/RejectRate。
* **缓存**：共享特征与聚合结果（避免重复计算）；CH 结果复用。

---

# 10) CI / 回归（Golden Run）

* 选 5–10 个代表性场景（高波动、熔断、缺口、窄盘、新闻冲击）作为 **Golden Datasets**；
* 每次改动触发 **回测回归**：关键指标偏移 ≤ 5% 才允许合并；订单/成交 JSON Diff ≤ 白名单阈值。
* **元测试**（Metamorphic）：

  * 成交量×2、价差×2 → 不应改变决策方向（在策略容忍范围内）；
  * 延迟+50ms → 决策落点变化不应超过 1 cadence；
  * 成本+2× → 策略胜率下降但夏普不应崩溃。

# 11) 演练与验收（60–90 分钟）

1. **Backtest vs Shadow**：选 3 标的、2 周区间；对比决策一致率 ≥ 99%，成交均价误差 ≤ 1tick；
2. **OCO/反手**：在回测中复现 3 种场景（V 反转、震荡、急跌），模拟与实盘编舞完全一致；
3. **成本/合规**：开启费表、借券息、SSR/LULD 规则 → 结果与“理想免成本版”对比合理；
4. **大规模网格**：同时跑 100 组参数（并行），CPU 利用率稳定、无掉任务；
5. **重现性**：记录 `run_id`，更换机器/重跑一次 → 订单/成交逐行一致；
6. **回放复盘**：导入一天实盘事件日志，Replay 模式重建订单/成交 → 与线上审计对齐。

# 12) 风险与边界

* **簿模型简化**会限制极微观精度（毫秒排队/隐藏量）——我们通过**参数可调**的深度与冲击模型 + 影子对比来校准；
* **公司行为与数据修订**：务必固定 `data_rev`（CH 分区 snapshot）避免“数据漂移”；
* **随机性**只在撮合扰动，统一 `seed` 控制，任何其它路径不得引入非确定性（如 `time.time()` 直接参与逻辑）。
* **lookahead 风险**：特征与触发必须基于 `≤ window_end` 的信息，回测框架要有**自动哨兵**检查。
