好，进入 **P6：执行引擎（Execution Engine）**。
这是一份可直接落地的**完整实现规范**（不生成文件）：数据模型 → 生命周期与状态机 → 消息契约 → 风控前门与预留 → OCO/反手/算法单 → 适配 IBKR/纸交 → 幂等与对账/重启领养 → 观测与验收。与我们已完成的 **P4（账户/断路器）**、**P5（250ms 聚合/特征/就绪门）**无缝衔接。

# 0) 范围与退出标准

**目标**
把来自策略/DSL 的 `DecisionEnvelope` 转译为**可审计、可恢复**的订单与保护腿，确保：

* 任何时刻**不超账户可用资金**、不越策略/标的 cap、尊重断路器；
* **OCO/反手**编舞原子化，部分成交能**按比例动态调整保护腿**；
* **幂等**（重复意图/重试不重复下单）、**Exactly-Once**（状态与成交不重放）；
* 进程重启能**领养开着的订单**，恢复路由与保护。

**P6 退出标准（全部达成=完成）**

1. 单/批订单在 **风控前门 → 预留 → 券商 ACK/REJ → FILL → 释放**链路闭环；
2. **OCO 不变量**（任何时刻保护腿与仓位匹配、仅一腿触发）连续 1 天 **0 违规**；
3. **反手原子**（flatten→build→protect）在网络抖动/部分成交下 2 次演练均成功；
4. **重启领养**：杀进程并重启后，能**完全恢复**订单/保护腿/映射，且不重复下单；
5. 观测到位（延迟、拒单率、保护修正次数、领养成功率）并有告警。

  broker_order_id TEXT,                     -- 临时 id

CREATE INDEX ON orders (strategy_id, symbol, created_ts DESC);
CREATE INDEX ON orders (state);
CREATE INDEX ON orders (oco_group_id);

CREATE TABLE fills (
  id BIGSERIAL PRIMARY KEY,

  ts TIMESTAMPTZ NOT NULL,

  liquidity TEXT,                            -- ADD/REMOVE/UNKNOWN

  oco_group_id TEXT PRIMARY KEY,

# 3) 执行生命周期与状态机

```
NEW → (RiskApprove+Reserve) → SUBMIT → ACK → 
  ├→ PARTIAL ↔ MODIFY (可选) → FILLED
  ├→ CANCEL_REQ → CANCELLED
  └→ REJECTED
```

* **原子反手（Reverse Atomic）**
  `reverse_flatten(平旧)` 完成 → `reverse_build(建新)` → `ensure_protect(挂保护)`

  * 整个流程在**互斥锁**下执行；任一步失败，**回滚到“仅无方向风险”**（最坏：平仓后停在空仓，KillSwitch）。

# 4) 决策转译：`DecisionEnvelope → ExecutionPlan`

**净目标算法**

```
delta = target_qty - current_pos_qty
if delta == 0 → 无动作
if delta 与 当前在挂(同向) 可合并净额（避免多单）
```

**反手处理**

* 若 `current_pos_qty * target_qty < 0` 且 `reverse_atomic=true` → 生成两步计划：

  1. `flatten`（以 MKT/LMT+保护撤销的方式）；
  2. `build`（按新方向下单）；
  3. `ensure_protect`（首次成交即挂 OCO）。

**TTL/新鲜度**

* 超过 `ttl_ms` 的 envelope **丢弃**（审计记原因）。

**伪码**

```python
plan = []
if reverse_atomic and pos.qty * env.target_qty < 0:
    plan.append(OrderRequest(... reason="reverse_flatten", qty=-pos.qty, style=MKT_or_LMT))
    plan.append(OrderRequest(... reason="reverse_build",   qty=env.target_qty, style=env.style, oco_group_id=new_uuid()))
else:
    delta = env.target_qty - pos.qty
    if delta != 0:
        plan.append(OrderRequest(... reason="target_delta", qty=delta, style=env.style, oco_group_id=maybe_uuid()))
# 保护腿由 ensure_protect 在首次 fill 后挂出
```

# 5) 风控前门 & 资金预留（融合 P4）

在 **提交券商之前**，逐单执行：

1. **Global Breaker** 检查：`level>=1` 且为开仓/加仓 → 拒绝（只允许减仓/保护）。
2. **账户可用资金**：用 `AccountStateMonitor.available_cap`；
3. **策略/标的 cap**（含动态 cap 曲线）；
4. **合规清单**：停牌/SSR/LULD/黑名单；
5. **价格护栏**：`|limit - ref_px| ≤ max_dev_bp`；MKT 单启用**价格带保护**（详见 §6）。
6. **预留**：按名义 * (1+buffer_bp) 预留，成功才提交。
7. **幂等**：检查 `idempotency_key` 是否已存在；存在则**幂等返回**（不再次下单）。

# 6) 价格保护、撤改单与 OCO 管理

## 6.1 价格保护（MKT Banding）

* 对 MKT：提交前计算 `band = ref_px ± band_bp`，若 NBBO 超出带宽 → 转为 **STP-LMT** 或拒单；
* 对 LMT：对比 `limit_px` 与 `ref_px` 超阈 → 拒单/改价（Reg-Lite 一次）。

## 6.2 OCO 管理（首次成交即挂）

* 规则：**首次 fill（abs(filled_qty_from_zero)>0）** → 立即挂 `stop/take`，方向与仓位相反；
* **按比例调整**：每次部分成交 → 保护腿 `qty = abs(pos_qty)`；
* **一腿触发**：另一腿**立即取消**；重试失败 → Watchdog 强撤；
* **时间止损**：从首次 fill 时间起计时，到点执行：取消所有挂单 + MKT 平仓。

**关键伪码**

```python
async def ensure_protect(symbol, pos_qty, cfg, oco_group_id):
    if pos_qty == 0: await cancel_oco_if_exists(oco_group_id); return
    side = -1 if pos_qty > 0 else +1
    sl_px, tp_px = compute_protect_prices(cfg)        # 支持 ATR/固定/跟踪
    await upsert_oco(oco_group_id, side, abs(pos_qty), sl_px, tp_px)

async def on_fill(order, fill):
    await update_position(fill)
    if is_first_fill(order.symbol):
        await ensure_protect(symbol, current_pos_qty(symbol), oco_cfg, oco_group_id)
    else:
        await adjust_oco_qty(oco_group_id, abs(current_pos_qty(symbol)))
```

# 7) 算法单（Meta Order：TWAP/VWAP/POV）

* **拆单编排**（MetaOrderHandler）：

  * 根据 `intent.qty`、时段与节奏把单拆为 `n` 个 slice；
  * **每 slice** 都是一个 `OrderRequest`，有独立 `idempotency_key = decision:slice_i`；
  * **每 slice 成交**后触发 `ensure_protect`（已成交部分立即有保护）。
* **容错**：行情急变/断路器 → 取消剩余 slice；已成交部分保留保护或直接清仓（策略可配）。

# 8) 券商适配层（BrokerAdapter）

统一接口：

```python
class BrokerAdapter:
    async def send(self, req: OrderRequest) -> BrokerAck: ...
    async def cancel(self, broker_order_id:str) -> None: ...
    async def replace(self, broker_order_id:str, new_px:float, new_qty:float) -> BrokerAck: ...
    async def open_orders(self) -> List[BrokerOpenOrder]: ...
    async def subscribe_exec(self, on_status, on_fill): ...
```

**IBKR 细节**

* `orderRef = idempotency_key`（便于重启领养）；
* `permanentId` 作为 `ib_perm_id`；
* TWS 限流/流量控制 → **指数退避** + **序列化**（每策略 `pacing_ms`）；
* 拒单分类：价格越带/合规拒单/连通性 → 分别走**改价/丢弃/重试**。

**Paper/Replay**

* 完全实现同样接口，撮合规则：`LMT` 与当前 `mid/last` 比较，`MKT` 直接按 `mid+slippage` 成交；
* **相同状态机**与审计，便于回测/影子一致。

# 9) 幂等、重试与错误处理

* **幂等**：`idempotency_key` 唯一；重复提交 → 返回已存在订单的引用；
* **提交重试**：网络错误 → 指数退避 `100ms * 2^k`（上限 2–3s），最多 5 次；
* **改价策略（Reg-Lite）**：一次性向更紧价位靠拢（≤ `max_dev_bp`），若仍拒 → 拒单并审计；
* **失败隔离**：单策略 `pacing_ms` 与**互斥锁**，避免同标的并发风暴；
* **错误分级**：`RETRYABLE`（网络/限流） vs `FATAL`（价格越界/合规）。

# 10) 启动对账与领养（Reconciliation）

**目标**：重启后把券商在挂/未完结的订单**收编**到本地状态机。

步骤：

1. `open_orders()` 获取券商在挂；
2. 按 `orderRef=idempotency_key` 精确匹配；若缺失 → **模糊匹配**（symbol/side/px/qty/时间窗）；
3. 写回 `orders.state = ACK/PARTIAL`、`broker_order_id/ib_perm_id`；
4. 查询历史成交（若可得），**补写 fills** 与 `filled_qty/avg_px`；
5. 重建 `oco_links` 与保护腿；**幽灵订单**（DB 有、券商无） → 标 `STALE_CLOSED` 并关闭。

**守恒检查**：仓位 = ∑成交；保护腿数量 = `abs(pos_qty)`；函数式不变量不通过 → 触发 OCO 看门狗重建。

# 12) 关键伪码（粘贴即用骨架）

## 12.1 提交流程

```python
async def submit_plan(plan: List[OrderRequest]):
    for req in plan:
        # 风控前门 + 预留
        ok, why = await approve_and_reserve(req)
        if not ok:
            await audit("REJECT_BEFORE_SEND", req, why)
            continue
        # 幂等
        exists = await orders_repo.find_by_idem(req.idempotency_key)
        if exists:
            await audit("DUP_SKIP", req, exists.id)
            continue
        # 发送
        try:
            ack = await broker.send(req)
            await orders_repo.insert_from_req(req, state="ACK", broker_order_id=ack.oid, ib_perm_id=ack.pid)
            await audit("ACK", req, ack)
        except Retryable as e:
            await orders_repo.insert_from_req(req, state="STALLED", error=str(e))
            await retry_queue.push(req)
        except Fatal as e:
            await orders_repo.insert_from_req(req, state="REJECTED", error=str(e))
            await ledger.release(req.idempotency_key)  # 释放预留
```

# 13) 演练脚本（最短 40 分钟）

1. **OCO 保护**：做一笔入场 → 检查首次成交到 OCO 挂出 < 500ms（目标）；手动取消一腿 → 5s 内自动重建。
2. **反手原子**：持仓多头时发空头目标 → 观察 flatten→build→protect 的三步；中途中断网络 10s → 恢复后仍达成无方向敞口。
3. **重启领养**：提交 3 笔在挂并部分成交 → 杀进程 → 重启 → 检查全收编且不重复下单。
4. **幂等重试**：注入短时网络错误 → 相同 `idempotency_key` 重试不重复；恢复后状态一致。
5. **断路器**：提升 `DD_day` 到 1.2% → 新开单全部被 breaker 拒绝，仅允许减仓与保护。

# 14) 风险与反模式

* **保护腿滞后**：必须以**首次 fill**为触发；若依下单时机可能出现“裸敞口”；
* **顺周期改价**：频繁 price-chasing 易引发滑点与拒单率上升，采用 **Reg-Lite（仅一次）**；
* **幂等泄漏**：任何路径都必须写入 `idempotency_key`；IBKR `orderRef` 必须=它；
* **强平式降档**：动态 cap 下调不应强平，执行器只做“**只减不增**”；
* **定时器风暴**：OCO/时间止损请用**单飞轮协程**，按组聚合周期性检查，避免 per-order 细粒度定时器爆炸。
