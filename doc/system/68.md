# P4：账户/保证金**实时账本** + **全局断路器**（实盘安全必做）

目标：把**IBKR 实时保证金/购买力**接入为**权威资金来源**，并在**账户层**设置硬断路器（回撤/拒单/LULD/SSR/停牌总线），与我们已有的**策略资金池、Reservation、动态 cap**联动，做到“**任何时刻不超杠杆、不越红线、可一键拉闸**”。

## 1) 模块与数据契约

### 1.1 AccountStateMonitor（新）

* **职责**：每 5s 拉取 IBKR 账户快照，落地 PG/CH，并发布到 StateBus。
* **关键字段（示例，按你们 ib_client 映射）**

  * `NetLiquidation`、`AvailableFunds`、`ExcessLiquidity`、`InitMarginReq`、`MaintMarginReq`、`BuyingPower`
  * `Currency`、`AccountCode`、`Timestamp`
* **降级策略**：拉取失败>3 次 → 写 `market_rule=PAUSE_NEW_ORDERS` 标志（只允许减仓/保护）；恢复 5 分钟后自动解封。

### 1.2 CapitalLedger（扩展）

* **资金等式（实时）**

  ```
  available_cap = min(
      BuyingPower * broker_safety_mult,
      NetLiquidation - InitMarginReq
  ) - reservations_live - buffer_cost
  ```

  * `broker_safety_mult` 取 0.9–0.95（防券商端口径差）；
  * `buffer_cost` = 佣金/滑点缓冲（如 10–20bp 的名义预留）；
  * 每策略资金池上限 = `min(strategy_cap_final, available_cap_allocated_to_strategy)`；分配规则继承“动态 cap 曲线”。

### 1.3 GlobalBreaker（新）

* **硬断路器源**：

  * 账户维度：`DD_day >= X%`、`reject_rate >= 1%`、`ib_disconnects` 连续 >N、`available_cap < floor`；
  * 市况维度：指数跌幅阈值、广泛 LULD/SSR 比例；
* **动作矩阵**：

  * 等级 1（黄）：禁止新单、允许减仓；
  * 等级 2（橙）：KillSwitch 指定策略集合；
  * 等级 3（红）：账户级 KillSwitch（撤单/平仓/释放/暂停），进入冷却 60–120 分钟。

> 断路器状态写入 StateBus（带过期时间），执行器与策略端都**被动尊重**。

---

## 2) 流程接线（落到代码路径）

1. **Pre-Trade Gate（风控前门）**

   * 读取 `AccountStateMonitor.latest()` → 计算 `available_cap`；
   * 若 `available_cap < needed_cap(order)` → `REJECT{reason=insufficient_account_cap}`；
   * 若 `GlobalBreaker.level >= 1` → `REJECT{reason=breaker}`（或仅 stop new opens）。

2. **Reservation（下单即预留）**

   * 预留金额 = `abs(qty*limit_px)* (1 + buffer_bp)`；
   * 预留前再次对比 `available_cap`（**账户级**）与 `per_strategy_cap`（**策略级**）。

3. **Post-Trade 更新**

   * 成交/撤单 → 释放预留 → 账本记录 → 更新策略资金使用率；
   * `AccountStateMonitor` 的快照会反映券商侧保证金变化，**不等待**再下次下单时才感知。

4. **Breaker 自动化**

   * Prom 规则：

     * `rolling_dd_1d > 1%` 连续 3 分钟 → 置 `level=2`；
     * `reject_rate_5m > 2%` → `level=1`；
     * `available_cap < 1.2 * reservations_live` → `level=3`（防“借新补旧”）。
   * 写入 StateBus 并广播到仪表盘（醒目红牌）。

---

## 3) 持久化与可回放（PG/CH）

* **PG（权威）**：

  * `account_snapshots`：每 5s 一行（account, ts, fields…）
  * `breakers`：变更日志（level、原因、触发规则、操作者/自动、冷却截止）
* **CH（报表/回溯）**：

  * `account_snapshots_ch`（ReplacingMergeTree）供 T+0/T+1 报表与事故复盘
  * 报表加两条：`杠杆倍数 = Gross/NetLiq`、`保证金占用比 = InitMargin/NetLiq`

## 4) 验收剧本（30–45 分钟）

1. **可用资金闸**

   * 人为把 `BuyingPower` Mock 降到极小 → 新单被 `insufficient_account_cap` 拒绝；
2. **保证金飙升**

   * 模拟高波动导致 `InitMarginReq` 快速上升 → 触发 `available_cap < reservations_live` → 断路器 3 级；
3. **券商断连**

   * 断开 IBGW 连接 2 分钟 → Monitor 连续失败 → `PAUSE_NEW_ORDERS` 生效；
4. **全局回撤**

   * 写入 `DD_day=1.5%` 测试值 → 自动降档 + 断路器 2 级，恢复后冷却期内不升档。
