# Data Plane v1.0（IBKR→Kafka→ClickHouse）

## 0. 目标与 SLO

* **实时性**：tick 入库 p95 ≤ **300ms**；5s bar 产出延迟 p95 ≤ **400ms**（含本地缓冲）。
* **鲁棒性**：网抖/乱序/短断连不丢数、不重复；**可回放**、**可回补**。
* **可恢复**：数据桥/聚合器重启后，**5s 窗口上下文不丢**（Redis/Tokens），继续滚动。
* **一致性**：5s→10s/1m 由 CH 物化视图聚合，口径固定；回补数据与实时一致可区分（`calc_mode`）。

---

## 1. 组件与职责

### 1.1 IB Bridge（ibkr-bridge）

* 使用 `ib_insync`：

  * **Tick-By-Tick（Trades）**：`reqTickByTickData`（trades）；产生 `md.tick.v2`（trade）。
  * **Top of Book（BBO）**：`reqMktData`（bid/ask）；合并入 `md.tick.v2`（quote 部分，去抖后发）。
  * 可选 **RealtimeBar(5s)**：仅作为对照/兜底，不作为主口径。
* **去抖与采样**：

  * trade：逐条透传；
  * quote：价/量不变不发，**变动≥1 tick 或 size 改变**才发。
* **幂等**：`idempotency_key = f"tick:{symbol}:{ts_us}:{seq}"`（`seq` 为本地单调递增）；消息 Key = `symbol`。
* **容错**：与 TWS/IBGW 的断线自动重连，指数退避；**断连期间缓冲**（内存 + 溢出到磁盘可选）。

### 1.2 Bar Aggregator（bar-agg）

* **输入**：`md.tick.v2`（Kafka）；
* **状态**：每 symbol 的窗口上下文（`open/high/low/close/vol/vwap`、`ts_start/ts_end`）存**Redis**：

  * Key：`bar5s:{symbol}`，Value：JSON（当前滚动窗口）+ `wm_ts`（watermark）。
  * TTL：`2 * window + 60s`，重启时可无缝续上。
* **抖动/乱序**：

  * **时间窗口**：固定 5s 桶（UTC 对齐，0,5,10,…）。
  * **Watermark**：允许迟到 ≤ **2000ms** 的 tick 进入当前/前一窗口；更迟标记 `late`（不改历史窗口，由**回补**处理）。
  * **本地缓冲**：**窗口结束 + 200–400ms** 再发 `md.bar.5s.v2`（吸收最后的迟到与抖动）。
* **产出**：`md.bar.5s.v2`（Kafka），字段我们已定：`ts_start/ts_end/ohlcv/vwap/rth/source/calc_mode`。

### 1.3 Gap Filler（backfill）

* **探针**：每 `30s` 扫描：按 `symbol` 检查当日 5s 序列是否**连续**（ClickHouse 查询）。
* **缺口**：发现缺口区间 → 触发 **IBKR 历史拉取**（`reqHistoricalData`，1min bars 或 5s 分辨率，视账户权限），插值/聚合出 5s，写入 CH，标记 `calc_mode='backfill'`。
* **合并**：避免覆盖实时：回补写入**相同窗口键**（`symbol, ts_start`），表引擎 `ReplacingMergeTree(event_id)` 去重，**以较新一条覆盖**（`_version` 或 `calc_mode` precedence）。

### 1.4 CH Writer（kafka→CH）

* 建议**自研消费者**批量写（而不是 CH Kafka 引擎），理由：控制幂等键/失败重试更细；
* 批量策略：`rows=5k 或 500ms` flush，失败指数退避；
* `md.tick.v2`、`md.bar.5s.v2` 各自独立消费组。

## 2. Kafka 主题与分区

| Topic              | Key      | 建议分区                       | 备注                      |
| ------------------ | -------- | -------------------------- | ----------------------- |
| `md.tick.v2`       | `symbol` | `P = max(4, ⌈symbols/50⌉)` | 按 symbol 均匀；同 symbol 有序 |
| `md.bar.5s.v2`     | `symbol` | 与 tick 相同或更少               | 由 aggregator 产出         |
| `md.backfill.ctrl` | `symbol` | 1                          | 回补任务/结果反馈（可选）           |

**压缩**：`lz4`；**acks**：`all`；**幂等生产者**：开启（Kafka 自带）。
**重放**：保留至少 **3 天**，便于重建/稽核。

## 3. ClickHouse 表与物化视图（与前文一致）

### 3.1 `qsys.md_tick_v2`（ReplacingMergeTree）

主键：`(symbol, ts)`；去重键：`event_id`
常用列：`ts, symbol, px, qty, bid, ask, bid_sz, ask_sz, rth, source, event_id, idemp_key`

### 3.2 `qsys.bar_5s_v2`

主键：`(symbol, ts_start)`；列：`ts_start, ts_end, ohlcv, vwap, rth, source, calc_mode, event_id`

### 3.3 物化视图：`bar_10s_v2`, `bar_1m_v2`

* 以 5s 聚合为准；OHLC 用 `argMin/argMax`，VWAP 用加权；
* 示例（1m）：

```sql
CREATE MATERIALIZED VIEW qsys.mv_bar_1m_v2
TO qsys.bar_1m_v2 AS
SELECT
  symbol,
  toStartOfMinute(ts_start) AS ts_start,
  addSeconds(ts_start, 60)  AS ts_end,
  anyHeavy(rth) AS rth,
  argMin(open, ts_start)  AS open,
  max(high)               AS high,
  min(low)                AS low,
  argMax(close, ts_start) AS close,
  sum(vol)                AS vol,
  sum(close*vol)/nullIf(sum(vol),0) AS vwap,
  'AGG' AS source,
  'agg' AS calc_mode,
  anyLast(event_id) AS event_id
FROM qsys.bar_5s_v2
GROUP BY symbol, ts_start;
```

## 4. Redis 状态（保障“无缝续聚合”）

* `bar5s:{symbol}`：

```json
{
  "bucket": "2025-10-02T15:04:55Z",   // 当前窗口开始
  "open": 221.10, "high": 221.50, "low": 221.05, "close": 221.32,
  "vol": 12000, "vwap_num": 2.6e9, "vwap_den": 12000,
  "wm_ts": "2025-10-02T15:04:58.500Z"  // Watermark（迟到上限）
}
```

* 更新规则：

  * tick 到达 → 判断所属桶；若 `tick.ts <= wm_ts + 2s` 则并入；
  * 窗口结束 `+ 200–400ms` → 发 bar、**删除**或**滚动**到下一桶；
  * 重启：读 Redis 恢复最后桶，继续追加；若 Redis 为空，**从 CH 拉最近 1–2 桶兜底**。

---

## 5. 抖动 / 乱序 / 重复处理

* **时间戳准则**：以 **Bridge 接收时间** 作为 `ts_us`（若 IB 带明确成交时刻且可信，可二者并存：`src_ts_us`）。
* **乱序**：以 `wm_ts` + 2s 作为迟到阈值；过阈的 tick：写 `md.tick.v2` 但**不改 bar**（交给回补）。
* **重复**：利用 `idemp_key` + CH `ReplacingMergeTree(event_id)` 去重；Kafka producer 幂等开启。

---

## 6. 回补（Backfill）细节

* **缺口检测 SQL**（当日某 symbol）：

```sql
SELECT
  arraySort(groupArray(toUnixTimestamp(ts_start))) AS a,
  arrayFilter((x,y) -> y-x > 5, a, arrayConcat([0], a[1:])) AS gaps
FROM qsys.bar_5s_v2
WHERE symbol={sym}
  AND trade_date = today()
SETTINGS max_threads=1;
```

* **策略**：

  * 优先尝试 **IBKR 历史 1min** → 再分割成 5s（近似）；
  * 如权限可用 **5s 历史** 直接写；
  * 回补写入 `calc_mode='backfill'`；与实时冲突时以更**新**的事件为准（`event_id`/`_version`）。
* **速率**：回补写入每批 ≤ 5k 行，节流避免与实时冲突。
* **熔断**：回补失败 ≥ 5 次 → 标记 symbol `DATA_DEGRADED`，控制面报警并可触发**只许平仓**。

## 9. 运行与运维

* **Pre-flight**（已在安全内核中定义）：IB/Kafka/CH/Redis 全通过才启动；
* **滚动升级**：先停 Bridge，agg 等待窗口 flush，读 Redis 恢复，**零丢桶**；
* **Drain 模式**：`/control/data/drain?symbol=…`：停止新订阅，仅完成当前桶并 flush；
* **重放**：从 Kafka offset 重放到另一个 CH 表，做审计或重建（配 `WHERE trade_date=today()`）。

## 10. 伪代码骨架（关键流程）

### 10.1 Bar Aggregator 主循环

```python
class BarAggregator:
    def __init__(self, redis, prod, max_late_ms=2000, emit_buffer_ms=300):
        self.r = redis; self.k = prod
        self.max_late = max_late_ms; self.emit_buf = emit_buffer_ms

    def on_tick(self, tick):
        sym, ts = tick.symbol, tick.ts  # utc microsec
        bucket_start = floor_to_5s(ts)
        state = self.r.get_json(f"bar5s:{sym}") or self._new_state(bucket_start)
        if ts > state["bucket"] + 5_000ms + self.max_late:
            # too late: 不写入当前/历史窗口（交给回补）
            return
        if bucket_start != state["bucket"]:
            # 旧桶 → 如果已过 emit_buf 则发出旧桶；然后滚动新桶
            if now() >= state["bucket"] + 5s + self.emit_buf:
                self._emit(sym, state)
            state = self._new_state(bucket_start)
        self._accumulate(state, tick)
        state["wm_ts"] = max(state["wm_ts"], ts)
        self.r.set_json(f"bar5s:{sym}", state, ttl=15s)

    def _emit(self, sym, st):
        bar = to_bar(st)  # ohlcv/vwap
        self.k.publish("md.bar.5s.v2", key=sym, value=bar)
        self.r.del(f"bar5s:{sym}")
```
