# 一、三周落地节奏（可并行）

## Week 1｜安全内核 + 数据最小竖切

1. **Safety Core（必须优先）**

   * 执行器硬化：首填即挂 OCO、三层止损（硬停/追踪Stop-LMT/Time-Stop）、撤改节流、订单巡检协程。
   * 风控账本：`core_strategy/core_strategy_ledger/core_order_reservation/core_order/core_fill/core_position` 建表与存储过程：

     * `core_sp_risk_approve_and_reserve`
     * `core_sp_release_on_terminal`
     * `core_sp_sweep_stale_reservations`
   * PG Advisory Lock 串行化审批（策略×symbol 粒度）。
   * Kill-Switch + Pre-flight（阻塞式健康检查）。

2. **Data Plane（最小可跑）**

   * IBKR Bridge（trade+quote，250ms；quote 去抖），md.tick.v2 → Kafka。
   * Bar Aggregator：tick→5s（watermark=2s，本地缓冲 200–400ms；Redis 续聚合）；md.bar.5s.v2 → Kafka。
   * CH Writer：bar_5s_v2 入库；1m 物化视图。
   * 监控：Kafka lag、bar emit p95、回补开关位。

**里程碑 M1（T+5~7天）**

* 5s bar 稳定入库，`emit_latency_ms_p95 < 400`；
* OCO 挂载成功率 = 100%，无保护窗口 = 0；
* 审批→预留→下单→终态释放闭环通过联测（账不黑）。

## Week 2｜引擎骨架 + CH DAL + 策略调度

1. **引擎 Runtime Skeleton v1**

   * Per-Strategy 独立调度（最小 5s，可 10/20/60s）、ReadyCheck（数据/特征/快照/系统态）、智能跳过、自适应退避。
   * 事件合约：`engine.order.request.v2` → `risk.decision.v2` → `exec.order.status/fill.v2` → `portfolio.snapshot.v2`。
   * Context API：`history/features_intraday/features_snapshot` + 下单（MKT/LMT/STP_LMT）。

2. **CH DAL**

   * bars_5s/bars_1m/intraday/snapshot 查询模板，PREWHERE + 限时 800ms + 本地 RingCache；批量按 `IN {syms}` 合并。
   * 降级回退：CH 慢/不可达时仅跑缓存与 Kafka 实时，ReadyCheck 智能跳过。

3. **最小策略模板 & 单测**

   * ORB/Pullback Demo（5s 节奏，单 symbol），Mock CH/Kafka/时间，验证幂等与只发一次。

**里程碑 M2（T+10~12天）**

* 两个策略并行跑（5s 与 20s），互不影响；
* `strategy.skips_total{reason="DATA_GAP_5S"}` 可控；
* 引擎发布的下单意图与风控/执行事件链路稳定。

## Week 3｜对账 2.0 + 回补 + 控制面最小集

1. **Reconciliation 2.0**

   * 孤儿领养（permId→orderRef→模糊匹配）、幽灵清理、上下文重建、补挂 OCO。
   * 安全阈：price_tolerance_bps、adopt_window_min、max_actions_on_start，带审计。

2. **Gap Filler**

   * 缺口探针 SQL；IB 历史拉取（1m/5s）→ 5s 插值写入 CH（calc_mode=backfill）。
   * 回补成功率 ≥ 99%，失败熔断与报警。

3. **Dashboard 最小集（只读即可）**

   * 健康/模式（halt/flatten-only 显示）、策略 cadence/skip、数据缺口热力图、回补状态/OCO 成功率。

**里程碑 M3（T+15~18天）**

* 冷启动 ≤ 5 分钟恢复交易状态；
* 当日缺口自动回补成功率 ≥ 99%；
* 控制面能观测核心 SLO 与红灯。

# 二、上线与灰度策略（面向真实账户）

1. **阶段 0：影子模式（1~2 天）**

   * 实时跑全链路，但 Execution 改写到“影子执行器”（不发 IB），核对订单序列/风控决定/对账逻辑。

2. **阶段 1：实盘只许平仓/小额试点（2~3 天）**

   * `trading_mode=FLATTEN_ONLY` + 少数 symbol；监控 OCO 成功率、账本漂移=0。

3. **阶段 2：小资金开放新单（策略资金池 1–5%）**

   * 分策略逐步放开；回撤联动 Kill-Switch；观察 `stop_to_market_upgrade_total`。

4. **阶段 3：扩大覆盖 & 打开回补常态化**

   * 观察 MTTD/MTTR、数据缺口与回补健康；达标后恢复正常资金水位。

**回退预案**

* 任一红线触发（见“验收门槛”）→ 自动 `flatten-only`，人工确认后恢复。
* 执行侧异常 → 立即升级保护为 `Stop-MKT`。

# 三、明确验收门槛（每阶段必须过）

* **执行安全**：OCO 挂载成功率=100%；无保护窗口=0；撤改节流生效；幂等去重生效。
* **风控一致**：`reserved_vs_release_diff_usd=0`；并发同 symbol 仅一单被批准；拒单带原因。
* **数据稳定**：`emit_latency_ms_p95 < 400`；`bar5s_gap_count=0`（或全被回补）；
* **恢复能力**：重启≤5 分钟完成对账，仓位/OCO 一致；
* **策略运行**：5s/20s 节奏均衡，`on_microbar` p95 < 200ms；智能跳过只在数据/特征缺失时出现；
* **监控告警**：Prom 指标全上线，Grafana 面板可见，报警路由到 On-call。

# 五、必须先做/做对的 10 件事（Checklist）

1. **PG DDL + 存储过程**全部创建并加最小权限；
2. **Advisory Lock** 在审批路径真实生效（并发压测验证只有一条 APPROVED）；
3. **OCO 首填即挂**，失败自动重试→失败升级 Stop-MKT；
4. **订单巡检** 3–5s 周期运行，能自动补齐 OCO/清理僵尸单；
5. **md.bar.5s.v2** 延迟 p95 < 400ms，watermark=2s 生效；
6. **Redis 续聚合** 验证：kill-9 后重启不丢“半桶”；
7. **回补** 缺口自动探测+写入 calc_mode='backfill'，成功率≥99%；
8. **ReadyCheck** 覆盖 bars/feature/snapshot + 智能跳过原因上报；
9. **策略幂等**：同一回调内重复信号只发一次请求；
10. **Pre-flight/Kill-Switch** 有效：任一依赖不健康即拒绝启动/只许平仓。

# 六、风险与缓释

* **券商接口抖动**：执行器设置最小改价/撤改节流 + 巡检 + 保护升级为市价。
* **数据缺口**：watermark + 本地缓冲 + 回补 + 告警；策略层智能跳过。
* **并发冲关**：PG 锁 + 幂等键 + 限流（全局/每策略）。
* **回测/实盘偏离**：合一事件序列、限价撮合规则对齐（下一阶段完善）。
* **误配置**：参数守门（上下界/步长），危险参数需停盘后生效。
