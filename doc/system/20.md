# 策略引擎 v1 规范（Inversion of Control）

## 0. 目标与 SLO

* **每策略独立节奏**：最小 **5s** 可调（10s/20s/1m…），互不影响。
* **决策延迟**：`on_microbar` 执行 p95 **< 200ms**（数据已就绪时）。
* **就绪守门**：数据不足**智能跳过**；跳过有理由、可观测。
* **幂等与单次动作**：同一次触发最多产生**1 个**下单意图。
* **热更新**：参数热更/策略热插拔，**不打断**在途安全保护。
* **恢复**：重启后能恢复策略上下文（最近决策点/参数哈希/随机种子等），持续运行。

## 1. 插件式 Strategy API（策略作者面向的接口）

```python
class StrategyAlgorithm:
    # ---- 生命周期 ----
    def initialize(self, ctx): 
        """
        只调用一次：读取参数、注册订阅（symbol/resolution），
        初始化本地状态（如上次 swing 点位、因子缓存等）。
        ctx.config: 当前策略参数（含限额/风控阈值/执行参数）
        ctx.logger, ctx.metrics 可用
        """

    def on_bar_5s(self, ctx, bar): 
        """
        5s 触发点（若设置 cadence=5s）：
        bar: {symbol, ts_start, ts_end, open/high/low/close/vol/vwap, calc_mode}
        ——建议仅做轻量逻辑与触发条件检测，把重计算留给离线/快照。
        """

    def on_timer(self, ctx): 
        """
        非行情条件触发的定时器（例如 20s 策略的心跳），
        可用于时间止损/窗口管理/补发检查等。
        """

    def on_order_update(self, ctx, status): 
        """订单状态变化（SUBMITTED/PARTIAL/FILLED/REPLACED/CANCELLED/REJECTED）。"""

    def on_fill(self, ctx, fill): 
        """成交回报，适合更新内部仓位/均价估算与 OCO 本地镜像。"""

    def on_position_update(self, ctx, pos_snapshot):
        """来自 Portfolio Service 的权威仓位/PNL 更新。"""

    def on_shutdown(self, ctx): 
        """释放资源、落持久化状态（最后决策点、runtime 计数等）。"""

    # ---- （可选）信号辅助：准备好的历史/特征读取 ----
    # ctx.history(symbol, window='60m', res='5s'|'1m'|'1d')
    # ctx.features(symbol, at='now'|'ts', fields=[...])
```

### 1.1 引擎注入的 `ctx` 能力（策略可用 API）

* **数据读取**

  * `ctx.history(symbol, window, res)`：ClickHouse 历史 Bar（带 RingCache）
  * `ctx.features(symbol, fields, at)`：特征快照 / 近时序
  * `ctx.snapshot(symbol)`：组合/仓位/均价/现金
* **下单与风险参数**

  * `ctx.order.limit(symbol, side, qty, px, tags=[])`
  * `ctx.order.market(symbol, side, qty, tags=[])`
  * `ctx.order.stop_limit(symbol, side, qty, stop_px, limit_px, tags=[])`
  * `ctx.order.cancel(order_id)`
  * `ctx.order.flatten(symbol)`
  * 所有 order API 内部都会生成 `engine.order.request.v2`，并自动挂上：

    * `idempotency_key`、`strategy_id`、`params_hash`、`notional_hint_usd`、`slippage_buffer_bps`
* **调度**

  * `ctx.next_wakeup(seconds)`：在当前回调结束后请求下一次唤醒（用于 20s、1m 策略）
  * `ctx.now()`：UTC 时间
* **状态**

  * `ctx.state`：策略持久本地状态（dict），引擎在 `on_shutdown` 时落盘/Redis 备份
  * `ctx.config`：当前策略参数（热更新时替换，包含 `cadence_s`、资金上限、止损模板等）
* **工具**

  * `ctx.logger`, `ctx.metrics`（Prometheus 包装）
  * `ctx.rand`（固定种子 RNG，保障回测/实盘一致）

## 2. 策略注册与装载（热插拔/参数哈希）

* `strategies.yml`（或 DB 表）声明：

  * `strategy_id`, `module.class`, `symbols`, `cadence_s`（每策略独立）
  * 风控上限：`max_capital_usd`, `max_pos_qty`, `max_daily_loss_usd`
  * 执行参数：追踪止损模式、OCO 止盈等（与执行内核兼容的键）
* 引擎启动：

  1. 解析配置 → **计算 param_hash**（稳定序列化+哈希）
  2. 反射加载 `module.class` → 实例化 → `initialize(ctx)`
  3. 为每个 `strategy_id` 创建**独立 Task**（asyncio）
* 热更新：

  * 新参数 → 先调 `validate(config)` 守门 → 更新 `ctx.config` & `param_hash`
  * 若修改 `symbols/cadence_s`：**Drain** 旧调度（完成当前回合后切换）
  * 危险参数（止损/风控阈值）→ 需要 `halt` 或**只在空仓时**生效

## 3. 调度与 ReadyCheck

### 3.1 ReadyCheck（智能跳过）

每次触发（bar/timer）前执行：

* **交易时段**：校验 RTH/节假日；不在时段 → `SKIP_TRADING_WINDOW`
* **数据可用性**：

  * `bars_5s`：近 `N` 根存在（`N` 由策略声明），缺口 → `SKIP_DATA_GAP_5S`
  * `features_intraday`：必需字段非空、非 NaN → `SKIP_FEATURES_MISSING`
* **系统健康**：Kafka/CH 延迟阈值、执行模式（`halt/flatten-only`）→ `SKIP_SYSTEM_DEGRADED`
* **仓位/风险**：触及全局或策略暂停标志 → `SKIP_STRATEGY_HALTED`

> 任何跳过都**发 metrics**：`engine_strategy_skips_total{strategy,reason}` 自增。

### 3.2 调度模型

* **Per-Strategy Worker**：每策略独立 asyncio Task（或独立进程，按规模切换），互不共享事件循环。
* **节奏类型**

  * `cadence='5s'`：订阅 `md.bar.5s.v2` 的 symbol 集合，bar 到达触发 `on_bar_5s`
  * `cadence='20s'|1m`：使用 `on_timer`，内部 `ctx.next_wakeup(20)`；可同时接收 5s bar 作为参考
* **自适应退避**：

  * 若 `CH查询 p95 > 800ms` 或超时 → 临时把 `cadence` 提升至 `2x`（如 5s→10s），直到恢复
  * 单策略**决策超时**（> 1s）→ 警告并退避一次

---

## 4. 幂等与“只发一次”

* 引擎为每次 `on_*` 回调生成 `decision_id`，挂到所有该回合产生的订单意图上。
* 同一 `decision_id` 内**最多允许一次**订单请求（reject 其余）；否则提示策略“冗余信号”。
* 事件产出：

  * `engine.order.request.v2`（包含 `idemp_key`, `decision_id`, `params_hash`, `tags`）
  * 若 ReadyCheck 不通过 → 不产出请求，仅上报 `skip` 指标。

## 5. ClickHouse DAL 读接口（规范 + SQL 模板）

### 5.1 接口

```python
class CHDal:
    async def bars(self, symbols: list[str], since: str, until: str, res: str='5s') -> dict[str, DataFrame]
    async def last_n(self, symbol: str, n: int, res: str='5s') -> "np.ndarray|DataFrame"
    async def features_intraday(self, symbol: str, fields: list[str], window: str='30m') -> DataFrame
    async def daily_snapshot(self, symbols: list[str], asof: str|None=None) -> DataFrame
```

* **实现要求**

  * 使用 `PREWHERE symbol IN (...) AND ts_start >= ...`（极大降低扫描）
  * **RingCache**：内存 LRU（symbol,res）→ 最近一次结果缓存 `ttl=2s`
  * **合并查询**：同一策略一次把多 symbol 合并请求，减少往返
  * **超时**：`query_timeout_ms=800`；超时走**降级**（返回缓存/空+跳过）

### 5.2 SQL 模板（示例）

**5s bar（最近 N 根）**

```sql
SELECT symbol, ts_start, ts_end, open, high, low, close, vol, vwap
FROM qsys.bar_5s_v2
PREWHERE symbol = {sym}
WHERE ts_start >= now() - INTERVAL {N}*5 SECOND
ORDER BY ts_start ASC
```

**1m bar（区间）**

```sql
SELECT symbol, ts_start, open, high, low, close, vol
FROM qsys.bar_1m_v2
PREWHERE symbol IN {syms:Array(String)}
  AND ts_start BETWEEN {since:DateTime} AND {until:DateTime}
ORDER BY symbol, ts_start
```

**特征（近 30 分钟）**

```sql
SELECT ts, {fields...}
FROM qsys.feat_intraday_v2
PREWHERE symbol = {sym}
WHERE ts >= now() - INTERVAL 30 MINUTE
ORDER BY ts
```

**日快照（昨收/当日 ATR/波动分位等）**

```sql
SELECT symbol, asof_date, atr_1d, vol_rank_20d, beta, ...
FROM qsys.feat_daily_snapshot_v2
PREWHERE symbol IN {syms:Array(String)}
  AND asof_date = {asof:Date}  -- 默认为 today()
```

## 6. 策略资金池/风控对接（引擎侧保障）

* 引擎在发出 `engine.order.request.v2` 前自动计算 `notional_hint_usd`，并附 `slippage_buffer_bps`（默认 8–10 bps，可由策略覆盖）。
* 每策略**统计**当日累计下单名义/成交名义，供 Dashboard 呈现（不参与 PG 账本，账本以 PG 为准）。
* 若策略侧定义 `max_open_orders` 或 `max_symbol_concurrency`，引擎先做**本地节流**，避免无意义请求打到风控层。

## 7. 策略模板（最小示例）

```python
class ORBPullback(StrategyAlgorithm):
    def initialize(self, ctx):
        self.syms = ctx.config["symbols"]
        self.win = ctx.config.get("lookback_n", 24)   # 24 * 5s = 2min
        self.th_bps = ctx.config.get("pullback_bps", 15)

    def on_bar_5s(self, ctx, bar):
        if not ctx.ready():   # 引擎在 ctx 注入 ReadyCheck 结果
            ctx.metrics.inc("engine_strategy_skips_total", {"strategy": ctx.sid, "reason": ctx.skip_reason})
            return
        df = ctx.history(bar["symbol"], window="10m", res="5s")
        if df is None or len(df) < self.win: 
            ctx.skip("DATA_WINDOW_SHORT"); return

        # 简化触发：向上突破后回撤 th_bps
        zz = df["close"].to_numpy()
        hi = zz[-self.win:].max()
        if (hi - zz[-1]) / hi * 1e4 >= self.th_bps:
            qty = ctx.sizing.fixed_usd(10_000, price=bar["close"])
            ctx.order.limit(bar["symbol"], side="BUY", qty=qty, px=bar["close"])
```

> **说明**
>
> * `ctx.ready()` & `ctx.skip(reason)` 由引擎实现；
> * 真实策略会把“重计算”离线化（夜间/休市后计算参数），盘中只做触发判定。

## 8. 热更新/Drain 流程

* 控制面 `PUT /strategies/{id}` → 写入新参数并设置 `pending_version`
* 引擎监听参数变化：

  1. 给该策略设置 `DRAINING` 标记：等待当前 `on_*` 完成
  2. 若该策略**空仓**：立即应用；若**有仓**：只更新与执行无关参数（例如因子阈值），执行/风控参数延后至**平仓后**生效
  3. 更新 `param_hash`，记审计

## 10. 端到端路径（文字时序）

```
md.bar.5s.v2 → [Engine Dispatcher] → StrategyWorker(S_i)
  → ReadyCheck(bars/features/system/pos) OK?
    ├─ NO: metrics.skip(reason)；结束
    └─ YES: StrategyAlgorithm.on_bar_5s(ctx, bar)
          └─ ctx.order.limit(...) → emit engine.order.request.v2
              → RiskService (PG 预留+锁) → APPROVED?
                 ├─ NO: risk.decision.v2(DENY) 回流，策略 on_order_update 可见
                 └─ YES: exec 下单 → 首填 OCO → status/fill 回流
                       → Portfolio 更新 → Strategy on_position_update/on_fill
```

## 11. 验收（M2 补充用例）

* **E1：每策略独立周期**：S1=5s、S2=20s；两者 `engine_strategy_actual_cadence_s` 稳定各自目标±1s。
* **E2：智能跳过**：拔掉某 symbol 的 5s 流 → 产生 `SKIP_DATA_GAP_5S`；恢复后自动继续。
* **E3：幂等单次动作**：同一触发条件重复命中 → `engine_dedup_suppressed_total` > 0，而 `engine_emit_requests_total` 增量=1。
* **E4：自适应退避**：注入 CH 延迟 → `engine_cadence_auto_backoff_total` 自增，cadence 从 5s 暂时变为 10s。

## 12. 与我们已定模块的对齐

* **数据面**：只读 `qsys.bar_5s_v2 / bar_1m_v2 / feat_*`，读不到→**跳过**而非阻塞。
* **风控/账本**：所有意图先走 `risk.decision.v2` 审批 + 预留；最终释放由执行器终态驱动。
* **执行安全内核**：止损/OCO/追踪全部在执行层实现，策略只给**意图与约束参数**。
* **IB 适配层**：引擎无需感知 IB 细节，专注信号与意图。
