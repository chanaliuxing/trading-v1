目标：把你在第 7 步得到的高质量 5s/10s Bars，稳定生成**无前视**（no look-ahead）的常用技术/微观结构特征，并通过 ClickHouse 做 **滚动计算 + 晚到重算 + 回补**，再**发布到 Kafka** 供策略在 5-10s 节奏下直接消费。下面内容均为**可直接粘贴**的规范与 SQL/伪代码（不生成文件）。

# D) 特征计算 SQL（滚动窗口，无前视，质量 gating）

> 说明
>
> * **无前视**：所有窗口都以 `ROWS BETWEEN N PRECEDING AND 1 PRECEDING` 或 `CURRENT ROW`，并且 RSI/ATR 用 **上一 close** 参与 TR 计算。
> * **质量 gating**：只在 qscore≥阈值且无 gap_flag 的窗口产出；否则该行可置为 NULL 或直接跳过插入。
> * **晚到重算**：仅重算“最近 N 分钟且过水位”的窗口。

**（5s 版本，10s 把表名改成 `bars_10s`、`features_10s` 即可）**

```sql
-- 参数
SET param_window_atr = 14;
SET param_window_rsi = 14;
SET param_qscore_thr = 70;

INSERT INTO features_5s
SELECT
  b.symbol,
  b.ts_start,
  b.ts_end,
  max(b.ver) AS ver,
  toUInt8(0) AS is_backfill,

  b.open, b.high, b.low, b.close, b.vwap, b.volume, b.trades,

  -- 收益：使用 lag(close) 避免前视
  (b.close / lagInFrame(b.close, 1) OVER w - 1) AS ret_1,
  (b.close / lagInFrame(b.close, 5) OVER w - 1) AS ret_5,

  -- 移动均值 / 标准差 / zscore（基于 close）
  avg(b.close) OVER w_5  AS sma_5,
  avg(b.close) OVER w_20 AS sma_20,
  avg(b.close) OVER w_60 AS sma_60,

  stddevSamp(b.close) OVER w_20 AS std_20,
  stddevSamp(b.close) OVER w_60 AS std_60,
  if(stddevSamp(b.close) OVER w_20 = 0, NULL,
     (b.close - avg(b.close) OVER w_20) / nullIf(stddevSamp(b.close) OVER w_20, 0)) AS zscore_20,

  -- ATR14：TR = max(high-low, abs(high-prev_close), abs(low-prev_close))
  avg(
    greatest(
      b.high - b.low,
      abs(b.high - lagInFrame(b.close, 1) OVER w),
      abs(b.low  - lagInFrame(b.close, 1) OVER w)
    )
  ) OVER w_atr AS atr_14,

  -- RSI14：窗口内涨跌的均值（简化版，不用 Wilder 平滑）
  100.0 * avgIf(up, up > 0) OVER w_rsi
         / nullIf(avgIf(up, up > 0) OVER w_rsi + avgIf(dn, dn > 0) OVER w_rsi, 0) AS rsi_14,

  -- 微观结构：点差/不平衡/中间价
  if(b.bid_last>0 AND b.ask_last>0, b.ask_last - b.bid_last, NULL) AS spread_last,
  if(b.bid_last>0 AND b.ask_last>0 AND bs+as > 0,
     (bs - as) / (bs + as), NULL) AS imbalance_last,
  if(b.bid_last>0 AND b.ask_last>0, (b.bid_last + b.ask_last)/2, NULL) AS mid_last,

  q.qscore AS qscore

FROM (
  -- 只抓"过水位"且最近 horizon minutes 的 bars（见第7步）
  SELECT *
  FROM bars_5s
  WHERE ts_end < now() - INTERVAL {waterline:UInt32} SECOND
    AND ts_end >  now() - INTERVAL {horizon:UInt32} MINUTE
) AS b

JOIN (
  -- 质量 gating（qscore >= 阈值，且无 gap）
  SELECT symbol, ts_start, ts_end, anyLast(ver) AS ver,
         max(qscore) AS qscore
  FROM mv_bars_5s_quality
  WHERE ts_end < now() - INTERVAL {waterline:UInt32} SECOND
    AND ts_end >  now() - INTERVAL {horizon:UInt32} MINUTE
    AND qscore >= {qthr:Int32}
  GROUP BY symbol, ts_start, ts_end
) AS q
ON b.symbol=q.symbol AND b.ts_start=q.ts_start

-- 为窗口函数提供 Frame（按 symbol 时间有序）
WINDOW
  w     AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN 60 PRECEDING AND CURRENT ROW),
  w_5   AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN 4  PRECEDING AND CURRENT ROW),
  w_20  AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN 19 PRECEDING AND CURRENT ROW),
  w_60  AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN 59 PRECEDING AND CURRENT ROW),
  w_atr AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN {atrN:UInt32}-1 PRECEDING AND CURRENT ROW),
  w_rsi AS (PARTITION BY b.symbol ORDER BY b.ts_start ROWS BETWEEN {rsiN:UInt32}-1 PRECEDING AND CURRENT ROW)

-- 需在 SELECT 顶部定义的临时列（up/dn/bs/as），可以用子查询或 CTE，这里内联演示：
SETTINGS async_insert=1, wait_for_async_insert=0;
```

> 上面需要在查询开头（或包一层外 SELECT）先计算 `up/dn/bs/as`：
>
> * `up = greatest(b.close - lagInFrame(b.close,1) OVER w, 0)`
> * `dn = greatest(lagInFrame(b.close,1) OVER w - b.close, 0)`
> * `bs = assumeNotNull(b.bid_last) > 0 ? 1 : 0`/请改为实际 `bid_size`，如无则设 `NULL`
>   为了简洁，上面省略了这几列的具体展开；实际落地可将 RSI 的 avgIf 内直接写 `greatest(...)` 表达式。

**参数替换建议（你们的批任务/调度器传参）：**

* `{waterline}` = `features.recompute.waterline_delay_s`
* `{horizon}`   = `features.recompute.horizon_minutes`
* `{qthr}`      = `features.qscore_threshold`
* `{atrN}` / `{rsiN}` 分别来自 `features.windows`

# E) 晚到重算 / 回补重算（批任务）

# G) 策略侧对接（5–10 秒节奏下“拿来即用”）

* 策略 `Initialize()` 时：

  * 订阅 `md.features.{5s|10s}.v1`，并初始化 **RingBuffer**（保存近 N 根用于判定/回测一致性）。
  * 冷启动从 CH 批量回读 `features_*` 历史，补齐初值（如 SMA60/ATR14 的 warmup）。
* 决策 `OnBar5s()`：

  * 直接读取最新一条特征（附带 `qscore`）。
  * 若 `qscore < threshold` 或有 NULL 关键特征 → **跳过本轮**（与你第 6 步 `has_enough_data()` 一致）。
* 多策略**独立节奏**：每个策略订阅自己需要的分辨率；互不影响。

---

# H) 无前视与一致性说明

* **无前视**：所有窗口使用 `lagInFrame` 访问**上一根**收盘，ATR 的 TR 包含 `prev_close`，RSI 由窗口内涨跌的**平均**构成；不引用未来数据。
* **一致性**：Bars 发生 **ver** 变化（晚到修正）→ features_* 再次 INSERT…SELECT 生成**更高 ver** 行；查询端取**最新 ver** 或 `FINAL` 可见最新结果；Kafka 发布端按 `ts_end` 递增推送最新版本。

# I) 基线告警与可观测性

**ClickHouse**

* `SELECT count() FROM features_5s WHERE ts_end>now()-300 AND isNaN(close)` → 数据异常
* `SELECT max(ver)-min(ver) FROM features_5s WHERE ts_end>now()-300` → 晚到强度
* `system.metric_log` 关注 `KafkaConsumersLags`, `InsertedRows` 速率

**Prometheus**

* `features_publish_lag_ms`（features_* 最新 ts_end → Kafka 推送延迟）
* `features_rows_recomputed_total`（过去 N 分钟内被覆盖的窗口数）
* `features_missing_required_total`（策略侧因关键特征缺失而跳过次数）
