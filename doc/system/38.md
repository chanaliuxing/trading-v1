# P0（上线前必做，缺任何一项都可能出事故）

1. **事件契约冻结（Schema Freeze + Partition 策略）**

   * 现状：主题/字段我们口头对齐了，但没**固定版**与**分区键**规范。
   * 要做：

     * 固定 `order.intent.v1 / risk.decision.v2 / exec.order.status.v2 / exec.fill.v2 / broker.account.v1 / broker.position.v1 / md.bar.5s.v2 / md.bar.5s.repair.v1 / portfolio.snapshot.v1` 的字段表；
     * **分区键**：

       * 交易链路：统一用 `decision_id`（或 `order_ref`）做 key，确保**同计划有序**；
       * 市场数据：用 `symbol` 做 key，避免跨分区乱序；
     * 每条消息都带 `schema_v`、`metadata.idempotency_key`、`metadata.producer`。
   * 验收：一页“契约表”+ 示例 JSON；Kafka 中 key=上述字段；消费者端**不再做条件分支**适配历史版本。

2. **幂等与去重：DB + Kafka 双层**

   * 现状：PG DDL 我给了，但未确认你已建好；Kafka 侧未加“去重键”缓存。
   * 要做：

     * PG：`reservations(strategy_id,order_ref) UNIQUE`、`fills (order_id, ts, qty, price) PK` 落地；
     * 消费者：对 `exec.fill.v2` 做**内存去重**（permId/time/qty）+ 最长 24h TTL；
     * 执行内核：所有下单**必须**带 `orderRef = idempotency_key`。
   * 验收：重复回放同一批事件 → DB 无重复记录，功能无副作用。

3. **全局 Kill-Switch / Panic-Flatten（急停）**

   * 现状：有 `emergency_flatten(plan)`，但缺**全局**开关。
   * 要做：

     * StateBus 增加 `TRADING_GLOBAL=PAUSE|RUN|FLATTEN`；
     * 风控/执行内核在每次循环读取；`FLATTEN` 则**禁止新单**+ 取消全部挂单+ 市价平仓。
   * 验收：在测试环境切到 `FLATTEN`，所有策略在 1–2s 内停单并清仓。

4. **数据质量闸门（DQ Gate）**

   * 现状：聚合器与 Facade 已有基本处理，但缺**策略入口强约束**。
   * 要做：

     * 策略引擎在每个 cadence 前检查：时间连续、`o<=h>=l<=c`、无 NaN/Inf、过去 N 根覆盖率≥95%；
     * 不满足 → 本轮**跳过**决策并上报指标；
     * 统一**时钟源**（NTP 校时），拒绝系统时钟偏差>200ms 的节点。
   * 验收：断 IB 或注入坏数据 → 策略“安全跳过”，不产生订单。

5. **IB 节流与配额保护（Pacing & Throttling）**

   * 现状：本地 TokenBucket 有，但跨进程无共享限流。
   * 要做：

     * 把 place/modify/cancel 的令牌桶放到 **Redis/PG advisory lock** 上（全局共享）；
     * 配默认上限：`place≤15/s`、`modify≤20/s`、`cancel≤20/s`，秒级窗口；
     * 超限时**排队**，超过 1s 仍无令牌 → 放弃本次修改并记录。
   * 验收：压测下改单风暴 → IB 无 pacing 错误，CRS 重试率不异常。

6. **冷启动对账（Reconciliation 2.0）**

   * 现状：CRS 自带 open_orders 领养，但没把“**历史持仓**与**未平订单**”完整还原。
   * 要做：

     * 启动时：

       * 从 `broker.position.v1` 抓取最新**账户持仓**（或直接调用 IB），合并 `fills` 表重算本地仓位；
       * 从 `open_orders()` 与 TWS open orders 生成 `order_map`；
       * 无法匹配 `orderRef` 的 → 按（symbol/side/价位/时间窗）**模糊匹配**并标记 `reconciled=true`。
   * 验收：先跑→停止→手动改几笔→重启→系统与 IB/TWS 状态一致，无“幽灵单/幽灵仓位”。

7. **风控“每策略资金上限”强约束生效**

   * 现状：Portfolio + Risk 最小版已跑，但未验证**并发穿透**。
   * 要做：

     * `reserve()` 事务里加**FOR UPDATE** 读 `HELD` 聚合（我已写），压测并发意图；
     * Risk 端对**单策略最大并发计划数**、**最大挂单名义**增加阈值。
   * 验收：并发 10 条大额意图 → 仅前 N 条被批准，其余被拒绝（insufficient_capital）。

# P1（强烈建议在灰度前完成）

8. **RTH/交易日历统一组件**

   * 统一一个 `is_rth(utc_ts, symbol)` 服务/库，支持节假日、半日、盘前/盘后开关；聚合器/风控/策略统一使用。
   * 验收：美股假日/早收盘当天，系统**不**发单且不误判数据有效性。

9. **ClickHouse 运维基线**

   * 分区：`PARTITION BY toYYYYMMDD(ts_start)`；
   * 引擎：`ReplacingMergeTree(bar_seq)`（你已用）；
   * TTL：原始 5s 保留 30–90 天，分钟/日线衍生表可长存；
   * 合并：设置 `max_bytes_to_merge_at_min_space_in_pool` 等，避免午间 merge 抢 IO；
   * 监控：写入 QPS、merge backlog、replica lag（如有）。
   * 验收：全天运行，CH 没有明显 backlog；查询 p95 在可接受范围内（5s 读取 < 50ms）。

10. **日志关联与审计（Trace-ID）**

* 所有日志携带 `decision_id`、`order_ref`、`strategy_id`，形成贯通链路；
* 关键操作（放行、下单、撤单失败、平仓）写入**审计日志**（不可变存储）。
* 验收：给出一个 `decision_id`，能在 Kibana/Grafana Loki 一键查到“从意图到成交”的全链路。

11. **策略“影子模式 / 模拟成交”**

* 在真实行情+真实风控下跑**影子策略**：只发 `order.intent.v1`，被 Risk 拒或批准都**不执行**，记录本会成交的价；
* 用于新策略/新止损策略灰度评估。
* 验收：开市 1–2 天影子回测指标与真实执行指标都能拉出来比对。

12. **GameDay 故障演练**

* 设计 6 个场景：IB 断线、Kafka 卡顿、CH 宕机、策略抖动（暴增单）、撤单失败、数据缺口；
* 逐一演练：系统能**自动降级**（跳过/暂停/兜底）并告警。
* 验收：每个场景都有“预期报警”与“自动化处置”记录。
