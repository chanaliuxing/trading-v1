好，继续 **第 12 步：策略层“交易规则模板化（Rule DSL）”**。
目标：把**止损/止盈/分批加减仓/时间止损/反手编舞**这些“战术规则”从策略代码里抽离成**声明式配置（DSL）**，由一个**轻量规则引擎**解释执行；策略开发只写**信号**（方向 & 强度），风控与执行细节由统一规则库落地，**可回测/影子/实盘同源**。

---

# 1) 设计目标与边界

* **声明式**：用 YAML/JSON 定义规则，不把 OCO/平仓/分批逻辑写进策略代码。
* **可组合**：多条规则按**先后顺序**与**优先级**组合，互斥/短路，减少冲突。
* **可审计**：每次规则命中/不命中产生“决策轨迹”，便于回溯。
* **统一落地**：所有规则的结果都折叠为**目标净仓 target_qty**与**保护腿 oco_cfg**，经我们已有链路（仲裁→资金预留→执行）。
* **时间预算**：规则评估≤**2–5ms/策略·标的**（5s节奏足够）。

---

# 2) 运行时形态（策略代码如何用）

策略仍然实现 `OnFeatures(symbol, f)`，但**不直接**写止损/分批/反手。策略只给出信号：

```python
# 在 OnFeatures 内，仅产出“意图基准”
signal = {
  "side": +1,                  # +1 多 / -1 空 / 0 中性
  "strength": 0.7,             # 0~1 之间，供分批/杠杆线性映射
  "ref_px": f["mid_last"],     # 基准价格
  "risk_anchor": f["atr_14"],  # 风险锚（ATR、波动）
  "ts_end": f["ts_end"]
}
# 交给规则引擎
envs = await rules_engine.evaluate(self.ctx, "meanrev_template_v2", symbol, f, signal)
# 引擎返回 0~N 个 DecisionEnvelope（含 target_qty、ttl、order_style、oco_cfg）
for env in envs:
    await self.ctx.SubmitIntent(env)
```

# 3) DSL 结构（YAML 示例）

```yaml
# templates/meanrev_template_v2.yml
name: meanrev_template_v2
defaults:
  cadence_s: 5
  ttl_ms: 2000
  min_lot: 10                # 最小下单股数
  lot_round: 10              # 向下取整粒度
  max_layers: 3              # 分批上限
  base_risk_usd: 2000        # 单笔风险预算
  atr_k: 1.5                 # ATR sizing 系数
  time_limit_s: 900          # 时间止损
  trail_atr_mult: 1.4        # 跟踪止损 ATR 倍数
  reversal_atomic: true      # 反手原子编舞（先撤保护→平→建新→挂新保护）
rules:
  - id: quality_gate
    when:
      all:
        - f.qscore >= 70
        - f.gap_ratio <= 0.05
    then: continue           # 未通过则短路返回 []

  - id: sizing_layers
    when:
      any:
        - signal.side != 0
    compute:
      lot_abs: "floor( base_risk_usd / max(0.01, atr_k * f.atr_14) , lot_round )"
      layers: 
        - { trigger: "abs(f.zscore_20) >= 1.0", qty_mult: 1.0 }
        - { trigger: "abs(f.zscore_20) >= 1.5", qty_mult: 1.5 }
        - { trigger: "abs(f.zscore_20) >= 2.0", qty_mult: 2.0 }
    emit:
      type: target
      mode: net                  # 目标净仓模式
      qty: "clamp(lot_abs * qty_mult * sign(signal.side), -5000, 5000)"
      style:
        kind: LMT
        limit_px: "signal.ref_px"
      extras:
        ref_px: "signal.ref_px"
        edge_bp: "abs(f.zscore_20)*10"

  - id: hard_stop
    when:
      any:
        - "position.qty != 0"
    emit:
      type: protect
      oco:
        time_stop_s: "time_limit_s"
        trail_atr_mult: "trail_atr_mult"
        # 可选固定止损/止盈：sl_px/tp_px 也支持表达式，如：
        # sl_px: "position.avg_px - signal.side * 2.0 * f.atr_14"
        # tp_px: "position.avg_px + signal.side * 3.0 * f.atr_14"

  - id: reversal
    when:
      all:
        - "position.qty * signal.side < 0"    # 反向
        - "abs(signal.strength) >= 0.6"
    emit:
      type: reverse
      atomic: "reversal_atomic"               # 原子反手
      max_slippage_bp: 10
      style:
        kind: LMT
        limit_px: "signal.ref_px"
```

> 解释
>
> * `rules` 逐条按顺序执行；`quality_gate` 过滤；`sizing_layers` 可**发出多层**目标净仓；`hard_stop` 为现有仓位挂保护；`reversal` 若反向足够强则触发**原子反手**。
> * `compute` 与表达式：用安全表达式引擎（禁 I/O），变量域包含 `f`（features）、`signal`、`position`、`defaults`。
> * `emit.type`：
>
>   * `target` → 产出一个 `DecisionEnvelope`（目标净仓）；
>   * `protect` → 仅更新 `extras.oco_cfg`（首次成交后 executor 立即挂 OCO）；
>   * `reverse` → 生成“两步意图”：`flatten → build`（由引擎在一个**互斥锁**里编舞，且复用我们第 4 步“反手原子化”）。

# 4) 规则引擎：执行语义

1. **上下文装配**：

   * `f`：features 行；`signal`：策略给的信号；`position`：当前仓位视图（`qty/avg_px/upnl`）。
   * `limits`：来自风险/动态 cap：`cap_strategy`, `cap_symbol`, `min_lot`, `max_lot`。
2. **求值顺序**：

   * 依序执行 `rules`。`when` 不通过则跳过规则；`then: continue/stop` 控制短路。
   * `compute` 中的表达式求值，放入局部作用域。
3. **冲突合并**：

   * 同一 tick 内可能产生多条 `target`；**取最后一条**或做**优先级**（可配置 `priority`）。
   * `protect` 只更新 `oco_cfg`；`reverse` 覆盖前面的 `target`，因为它需要原子反手。
4. **硬护栏**：

   * `qty` 经 `min_lot`、`lot_round`、`per_symbol_cap`、`strategy_cap`、`Reservation` 等**二次裁剪**。
5. **输出**：

   * 返回 0~N 个 `DecisionEnvelope`。每个 envelope 附带：`decision_id/ttl/tif/order_style/extras.oco_cfg`。
6. **审计**：

   * 发出 `rule_trace`（JSON）：命中规则清单、变量快照、裁剪前后 qty、最终 oco_cfg；写入 Kafka `audit.rule_trace.v1` 与 CH。

# 5) 引擎骨架（可粘贴）

```python
# -*- coding: utf-8 -*-
import math, uuid
from typing import Any, Dict, List

SAFE_GLOBALS = {"abs":abs, "max":max, "min":min, "floor":math.floor, "ceil":math.ceil, "round":round, "sign":lambda x:(0 if x==0 else (1 if x>0 else -1)), "clamp": lambda v,lo,hi: max(lo, min(hi,v))}

class RuleEngine:
    def __init__(self, templates: Dict[str, dict], logger, metrics):
        self.tpl = templates
        self.log = logger
        self.m = metrics

    def _eval(self, expr: str, scope: dict):
        if isinstance(expr, (int,float,bool)) or expr is None: return expr
        if not isinstance(expr, str): return expr
        return eval(expr, {"__builtins__":{}}, {**SAFE_GLOBALS, **scope})

    async def evaluate(self, ctx, tpl_name: str, symbol: str, f: dict, signal: dict) -> List[dict]:
        t = self.tpl[tpl_name]
        defaults = t.get("defaults", {})
        rules = t.get("rules", [])
        pos = await ctx.Position(symbol)
        position = {"qty": int(pos.get("pos_qty",0) or 0), "avg_px": float(pos.get("avg_px") or 0.0)}
        scope = {"f":f, "signal":signal, "position":position, **defaults}

        trace = {"symbol":symbol, "hits": [], "vars": {}, "decisions": []}
        out_envs: List[dict] = []

        for r in rules:
            # when 判定
            ok = True
            cond = r.get("when")
            if cond:
                ok = self._check(cond, scope)
            if not ok:
                continue

            # compute
            comp = r.get("compute", {})
            for k,v in comp.items():
                if isinstance(v, list):
                    scope[k] = [self._map_expr(item, scope) for item in v]
                else:
                    scope[k] = self._eval(v, scope)

            # emit
            emit = r.get("emit", {})
            if emit:
                etype = emit.get("type")
                if etype == "target":
                    qty_expr = emit.get("qty", 0)
                    qty = int(self._eval(qty_expr, scope) or 0)
                    qty = self._lot_and_caps(qty, ctx, symbol)  # 二次裁剪（lot/cap）
                    if qty != position["qty"]:
                        env = self._mk_env(ctx, signal, symbol, emit, scope, qty)
                        out_envs = [env]  # 同一tick以最后的target为准（也可做priority）
                        trace["decisions"].append({"type":"target","qty":qty})
                elif etype == "protect":
                    # 更新 oco_cfg（随 envelope 带出）
                    env = self._mk_env(ctx, signal, symbol, {"style":{"kind":"NOOP"}}, scope, target_qty=position["qty"], protect=emit.get("oco",{}))
                    out_envs.append(env)
                    trace["decisions"].append({"type":"protect"})
                elif etype == "reverse":
                    env = self._mk_env(ctx, signal, symbol, emit, scope, target_qty= -position["qty"], reverse=True)
                    out_envs = [env]
                    trace["decisions"].append({"type":"reverse"})

            trace["hits"].append(r.get("id"))
            if r.get("then") == "stop":
                break

        # 审计
        await self._audit(trace)
        return out_envs

    def _mk_env(self, ctx, signal, symbol, emit, scope, target_qty: int, protect: dict=None, reverse: bool=False):
        style = emit.get("style", {"kind":"LMT","limit_px":"signal.ref_px"})
        limit_px = float(self._eval(style.get("limit_px","signal.ref_px"), scope))
        env = {
          "decision_id": str(uuid.uuid4()),
          "strategy_id": ctx.strategy_id,
          "symbol": symbol,
          "ts_bar_end_us": int(signal["ts_end"]),
          "target_qty": float(target_qty),
          "tif": "DAY",
          "order_style": {"kind": style.get("kind","LMT"), "limit_px": limit_px},
          "freshness": {"ttl_ms": int(scope.get("ttl_ms", 2000))},
          "extras": {
            "ref_px": float(signal["ref_px"]),
            "edge_bp": float(abs(scope.get("f",{}).get("zscore_20",0))*10),
            "oco_cfg": self._build_oco(scope, protect) if protect else self._default_oco(scope),
            "reverse_atomic": bool(reverse and scope.get("reversal_atomic", True))
          }
        }
        return env

    def _default_oco(self, scope):
        return {"trail_atr_mult": float(scope.get("trail_atr_mult", 1.4)), "time_stop_s": int(scope.get("time_limit_s",900))}

    def _build_oco(self, scope, oco_cfg: dict):
        out = {}
        for k,v in oco_cfg.items():
            out[k] = float(self._eval(v, scope)) if isinstance(v,str) else v
        return {**self._default_oco(scope), **out}

    def _map_expr(self, d: dict, scope: dict):
        # 递归计算列表里的对象（用于 layers）
        o = {}
        for k,v in d.items():
            o[k] = self._eval(v, scope) if isinstance(v,str) else v
        return o

    def _check(self, cond: dict, scope: dict) -> bool:
        if "all" in cond:
            return all(self._eval(e, scope) for e in cond["all"])
        if "any" in cond:
            return any(self._eval(e, scope) for e in cond["any"])
        return bool(self._eval(cond, scope))

    def _lot_and_caps(self, qty: int, ctx, symbol: str) -> int:
        # 取策略/标的 cap，最小交易粒度
        min_lot = ctx.Param("min_lot") or 1
        lot_round = ctx.Param("lot_round") or 1
        # round down to lot
        if qty > 0:
            qty = (qty // lot_round) * lot_round
        else:
            qty = - ((abs(qty) // lot_round) * lot_round)
        if abs(qty) < min_lot: return 0
        # 交给 Arbiter/Reserve 最终裁剪（此处可做估算，不越上限）
        return qty

    async def _audit(self, trace: dict):
        # 可写 Kafka 或 ClickHouse
        pass
```

> 注意：表达式求值使用了 `eval` 的**受限环境**（去掉 `__builtins__`），仅暴露我们白名单函数与变量；生产上建议替换为**安全表达式引擎**（如 `asteval`/自研 AST 解释器）。

# 6) 三个现成模板

## 6.1 突破分批（Breakout Stagger）

* 入场：`f.breakout_up == True` 时分三层 LMT 逐步追多；
* 保护：`trail_atr_mult=2.0`；时间止损 20 分钟；
* 反手：仅当 `f.trend_slope < 0 & f.rsi < 45` 且强度 >0.8。

## 6.2 均值回归（Mean Reversion）

* 入场：`|zscore_20|` 达 1.0/1.5/2.0 三档；
* 保护：固定 SL=2*ATR，TP=3*ATR，且跟踪止损 1.4*ATR 取较紧者；
* 反手：当 `zscore` 过中性到另一侧≥1.2，触发**原子反手**。

## 6.3 趋势跟随（Trend Following）

* 入场：`ema_fast > ema_slow & pullback_to_ema`；
* 加仓：每盈利 1*ATR 增加一层，最多 3 层；
* 减仓：回撤 1*ATR 砍半；
* 保护：`trailing = max(trailing, entry_max - 1.5*ATR)`；时间止损 45 分钟。

（以上都可用 DSL 表述，略去重复 YAML）

# 7) 回测/影子/实盘一致性

* 回测：Harness 用**同一规则引擎**解释 DSL，生成 envelope → 用影子撮合；
* 影子/实盘：生成 envelope 后走**同一链路**（仲裁→预留→执行）；
* TTL/节奏/防抖：由策略或模板 `defaults` 控制；
* OCO：由 `protect` / `default_oco` 在首次成交后交给 executor 自动挂载（我们第 4 步已实现）。

# 9) 护栏与反模式

* 规则**不得**直接触达券商/数据库；只生成 envelope。
* 禁用昂贵表达式（循环、列表推导、导入模块等）；表达式必须 O(1)。
* 规则冲突解决：同 tick 多 `target` 时只保留最后一个（或用 `priority` 字段显式排序）。
* 避免“计算漂移”：规则中的 ATR/EMA 周期与 features 保持一致，**不在规则里重新滚动计算**。
