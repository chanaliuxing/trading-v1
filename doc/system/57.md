# 2) ClickHouse 表结构（原始 → 聚合状态 → 最终 Bar）

> 设计要点
>
> * **Kafka 引擎表**仅作入口；**Materialized View** 把数据刷入 `MergeTree`。
> * `ticks_raw` 用 **ReplacingMergeTree**（主键= symbol, ts_ns, type, seq），便于**晚到/重放去重**。
> * 先落一个**聚合状态表**（`bars_5s_state`，`AggregatingMergeTree`），再用**定时 FINAL 化**写入 `bars_5s`（`ReplacingMergeTree` 带 `ver`），用于**晚到修正**。
> * **分区**按日，**TTL** 压缩冷数据，**Codec** 提升体积与读写性能。

### 2.1 Kafka 入口表 & 原始 Tick 表

```sql
-- 入口：从 md.ticks.v1 消费（Avro，记得在 server config 里设 schema.registry.url）
CREATE TABLE src_ticks_kafka (
    msg_id String,
    source String,
    symbol String,
    ts_ns UInt64,
    type Enum8('trade'=1,'quote'=2),
    price Nullable(Float64),
    size  Nullable(Float64),
    bid   Nullable(Float64),
    ask   Nullable(Float64),
    bid_size Nullable(Float64),
    ask_size Nullable(Float64),
    exchange Nullable(String),
    seq   Nullable(UInt64)
) ENGINE = Kafka
SETTINGS
    kafka_broker_list = 'KAFKA_BROKERS',
    kafka_topic_list = 'md.ticks.v1',
    kafka_group_name = 'ch_ticks_ingestor',
    kafka_format = 'Avro',
    kafka_num_consumers = 4,
    kafka_handle_error_mode = 'stream'; -- 不阻塞

-- 原始落地（去重用 ReplacingMergeTree）
CREATE TABLE ticks_raw (
    symbol LowCardinality(String),
    ts_ns  UInt64,
    type   Enum8('trade'=1,'quote'=2),
    price  Nullable(Float64),
    size   Nullable(Float64),
    bid    Nullable(Float64),
    ask    Nullable(Float64),
    bid_size Nullable(Float64),
    ask_size Nullable(Float64),
    exchange Nullable(String),
    seq   Nullable(UInt64),
    msg_id UUID,                     -- 从字符串转 UUID
    ingest_ts DateTime64(3) DEFAULT now64(),
    ver UInt64 DEFAULT toUInt64(ingest_ts)   -- 作为去重版本
)
ENGINE = ReplacingMergeTree(ver)
PARTITION BY toDate(toDateTime(ts_ns/1000000000))
ORDER BY (symbol, ts_ns, type, coalesce(seq, toUInt64(0)))
TTL toDateTime(ingest_ts) + INTERVAL 30 DAY
SETTINGS index_granularity = 8192;

-- 将 Kafka 入口刷到原始表（并做基础清洗）
CREATE MATERIALIZED VIEW mv_ticks_into_raw
TO ticks_raw AS
SELECT
    symbol,
    ts_ns,
    type,
    price, size, bid, ask, bid_size, ask_size, exchange,
    assumeNotNull(toUUIDOrNull(msg_id)) AS msg_id,
    now64() AS ingest_ts,
    toUInt64(ingest_ts) AS ver
FROM src_ticks_kafka;
```

### 2.2 聚合状态表（5s 窗口）

```sql
-- 辅助：窗口起止
CREATE FUNCTION win5s AS (x) -> toStartOfInterval(toDateTime64(x/1000000000, 9), INTERVAL 5 SECOND);

-- 聚合状态（AggregatingMergeTree，保存中间态，便于晚到合并）
CREATE TABLE bars_5s_state (
    symbol LowCardinality(String),
    win_start DateTime,
    win_end   DateTime,
    open_state     AggregateFunction(argMin, Float64, UInt64),  -- open = argMin(price, ts_ns)
    close_state    AggregateFunction(argMax, Float64, UInt64),  -- close = argMax(price, ts_ns)
    high_state     AggregateFunction(max, Float64),
    low_state      AggregateFunction(min, Float64),
    vwap_num_state AggregateFunction(sum, Float64),             -- sum(price*size)
    vwap_den_state AggregateFunction(sum, Float64),             -- sum(size)
    vol_state      AggregateFunction(sum, Float64),
    trades_state   AggregateFunction(count),
    bid_last_state AggregateFunction(argMax, Float64, UInt64),
    ask_last_state AggregateFunction(argMax, Float64, UInt64),
    ver UInt64
)
ENGINE = AggregatingMergeTree()
PARTITION BY toDate(win_start)
ORDER BY (symbol, win_start)
SETTINGS index_granularity=4096;

-- 将 ticks_raw 聚到 5s 状态（Materialized View，只算 trade/quote 对应字段）
CREATE MATERIALIZED VIEW mv_ticks_to_5s_state
TO bars_5s_state AS
SELECT
    symbol,
    toStartOfInterval(toDateTime(ts_ns/1000000000), INTERVAL 5 SECOND) AS win_start,
    win_start + INTERVAL 5 SECOND AS win_end,
    -- trade 侧
    argMinState(if(type='trade', price, NULL), ts_ns) AS open_state,
    argMaxState(if(type='trade', price, NULL), ts_ns) AS close_state,
    maxState(if(type='trade', price, NULL)) AS high_state,
    minState(if(type='trade', price, NULL)) AS low_state,
    sumState(if(type='trade' AND size>0, price*size, 0.0)) AS vwap_num_state,
    sumState(if(type='trade' AND size>0, size, 0.0)) AS vwap_den_state,
    sumState(if(type='trade' AND size>0, size, 0.0)) AS vol_state,
    countStateIf(type='trade') AS trades_state,
    -- quote 侧（取最后一笔）
    argMaxState(if(type='quote', bid, NULL), ts_ns) AS bid_last_state,
    argMaxState(if(type='quote', ask, NULL), ts_ns) AS ask_last_state,
    max(toUInt64(ingest_ts)) AS ver
FROM ticks_raw
GROUP BY symbol, win_start, win_end;
```

### 2.3 最终 5s Bar（可多次修正，按 `ver` 选择最新版）

```sql
CREATE TABLE bars_5s (
    symbol LowCardinality(String),
    ts_start DateTime,
    ts_end   DateTime,
    open  Float64,
    high  Float64,
    low   Float64,
    close Float64,
    vwap  Nullable(Float64),
    volume Float64,
    trades UInt64,
    bid_last Nullable(Float64),
    ask_last Nullable(Float64),
    mid_last Nullable(Float64),
    ver   UInt64,
    is_backfill UInt8 DEFAULT 0
)
ENGINE = ReplacingMergeTree(ver)
PARTITION BY toDate(ts_start)
ORDER BY (symbol, ts_start)
SETTINGS index_granularity=4096;

-- 定时（或手动）FINAL 化最近窗口（设置水位：bar 结束 + 2s 再落最终行）
-- 注意：ClickHouse 没有内置调度，可由外部 job 每秒执行一次下述 INSERT … SELECT
-- 示例：只处理最近 10 分钟内且已过水位的窗口
INSERT INTO bars_5s
SELECT
    symbol,
    win_start AS ts_start,
    win_end   AS ts_end,
    argMinMerge(open_state)  AS open,
    maxMerge(high_state)     AS high,
    minMerge(low_state)      AS low,
    argMaxMerge(close_state) AS close,
    if(vwap_den=0, NULL, vwap_num/vwap_den) AS vwap,
    vol                       AS volume,
    trades                    AS trades,
    argMaxMerge(bid_last_state) AS bid_last,
    argMaxMerge(ask_last_state) AS ask_last,
    if(bid_last>0 AND ask_last>0, (bid_last+ask_last)/2, NULL) AS mid_last,
    max(ver)                  AS ver,
    toUInt8(0)                AS is_backfill
FROM (
   SELECT
     symbol, win_start, win_end,
     open_state, close_state, high_state, low_state,
     vwap_num_state AS vwap_num_state,
     vwap_den_state AS vwap_den_state,
     vol_state      AS vol_state,
     trades_state   AS trades_state,
     bid_last_state, ask_last_state,
     ver
   FROM bars_5s_state
   WHERE win_end < now() - INTERVAL 2 SECOND   -- 水位（处理网络抖动/晚到）
     AND win_start > now() - INTERVAL 10 MINUTE
)
GROUP BY symbol, win_start, win_end
SETTINGS async_insert=1, wait_for_async_insert=0;
```

> 说明
>
> * 晚到 tick 会再次进入 `bars_5s_state`，下一轮 FINAL 化会产生一行**更高 ver** 的 bar，覆盖旧值（查询端 `FINAL` 或 `max ver` 读取）。
> * 想要 10s bar，只需把窗口函数改成 `INTERVAL 10 SECOND`，或者再建一套 `bars_10s_state / bars_10s` 与相应 MV。

# 3) 历史回补（Backfill）与重算

### 3.1 回补来源

* **优先**：IBKR 1s 历史（`reqHistoricalData`，barSize=1 sec，duration=1 day），对于 5s 可**五合一**；
* **理想**：若能拿到历史逐笔（部分账户/路由支持），直接灌 `ticks_raw`。

### 3.2 回补写入策略

* 回补数据**写入 `ticks_raw`**（推荐），触发相同聚合链；标记 `is_backfill=1` 仅在落 `bars_*` 时设置。
* 回补时 **ver** 用当前 `now64()`，天然大于原先在线 ver，**自动覆盖**。

**示例：把 1s bar 转为“伪 tick”写入**（Python 逻辑片段，供回补用）

```python
# 对每根 1s bar，生成一个 trade 伪tick在秒末，用 close/vol 代表
# msg_id 用 determinisitc UUIDv5(symbol+ts) 保证可幂等重放
pseudo_tick = {
  "msg_id": uuid5(NS_DNS, f"{sym}:{ts_end_ms}").hex,
  "source":"IBKR-HIST", "symbol": sym, "ts_ns": ts_end_ms*1_000_000,
  "type":"trade", "price": close, "size": volume, "bid": None, "ask": None,
  "bid_size": None, "ask_size": None, "exchange": "HIST", "seq": None
}
# 发到 md.ticks.v1，进入相同 ClickHouse 管道
```

### 3.3 重算范围

* 新回补后，执行一次针对回补区间的 FINAL 化：

```sql
INSERT INTO bars_5s
SELECT ... FROM bars_5s_state
WHERE win_start >= toDateTime('2025-10-01 00:00:00')
  AND win_end   <= toDateTime('2025-10-01 16:00:00')
GROUP BY ...
```

# 4) 内存热链路（策略 5s 决策）与回读

* **热链路**：策略引擎**不直接查 CH**。由一个轻量 `bar-publisher` 服务每秒查询 `bars_5s` 最近窗口（或订阅内部队列），**发布到 Kafka `md.bars.5s.v1`**；策略用我们已有的**事件总线**订阅，落到**每策略独立 RingBuffer**。
* **冷回读**：策略初始化/冷启动时，从 CH **批量读取 N 天** 5s bar 填充历史，以便计算 ATR/均线等；日内则依赖 Kafka 推流。

> bar-publisher 伪代码（每 1s 扫描新窗口/或扫描 ver 变化）：

```python
# 仅示意
last_ts_end = None
while True:
    rows = ch.query("""
      SELECT symbol, ts_start, ts_end, open, high, low, close, vwap, volume, trades, bid_last, ask_last, mid_last, ver
      FROM bars_5s
      WHERE ts_end > {last}
      ORDER BY ts_end ASC
      LIMIT 50000
    """, params={"last": last_ts_end or 'now()-60'})
    for r in rows:
        produce("md.bars.5s.v1", to_avro(r))
        last_ts_end = max(last_ts_end, r['ts_end'])
    sleep(1.0)
```

# 5) 质量评分（Data Quality Score）与“跳过决策”

> 我们给每个 `symbol, window` 打质量分，策略在 `has_enough_data()` 时引用，**分数低/缺口 → 跳过本轮**。

### 5.1 质量事件与维度

* **缺口率**：该 5s 窗口 trade tick 数 = 0（但上一/下一窗口有）
* **晚到修正率**：窗口在首次落地后 X 秒内 ver 发生变化
* **NBBO 覆盖**：quote 存在比例（该窗口有至少 1 条 quote）
* **时间漂移**：tick ts 与网关接收时间差超阈值的比例

### 5.2 ClickHouse 计算（示例视图）

```sql
CREATE MATERIALIZED VIEW mv_bars_5s_quality
ENGINE = ReplacingMergeTree()
PARTITION BY toDate(ts_start)
ORDER BY (symbol, ts_start)
AS
SELECT
  b.symbol, b.ts_start, b.ts_end, b.ver,
  (b.volume = 0) AS gap_flag,
  -- 简化：同窗口多 ver 则视为晚到
  (count() OVER (PARTITION BY b.symbol, b.ts_start) > 1) AS late_flag,
  (b.bid_last IS NOT NULL AND b.ask_last IS NOT NULL) AS nbbo_flag,
  -- 质量分（0~100）：你可按权重组合
  (100
    - 40*gap_flag
    - 30*late_flag
    - 30*(1 - nbbo_flag)
  ) AS qscore
FROM bars_5s AS b;
```

> 策略侧门槛（伪代码）：

```python
async def has_enough_data(symbol):
    # 最近 M 根 qscore >= 70 且无 gap_flag
    rows = await ch.query("SELECT avg(qscore) as q, max(gap_flag) g FROM mv_bars_5s_quality WHERE symbol=%(s)s AND ts_end>now()-INTERVAL 5 MINUTE", {"s":symbol})
    return rows[0]["q"]>=70 and rows[0]["g"]==0
```

# 8) 端到端流程（含水位/回补）

1. **IBKR tick (~250ms)** → `tick-normalizer`（统一成 Avro TickV1，补 seq/msg_id）→ **Kafka `md.ticks.v1`**
2. **ClickHouse** `src_ticks_kafka` → `mv_ticks_into_raw` → **`ticks_raw`**（去重）
3. `mv_ticks_to_5s_state` → **`bars_5s_state`**（窗口聚合状态）
4. **定时 FINAL**（水位=2s）→ **`bars_5s`**（`ReplacingMergeTree(ver)`，可被晚到覆盖）
5. **bar-publisher** 轮询 `bars_5s` → **Kafka `md.bars.5s.v1`**（策略订阅）
6. **历史回补**（1s bar→伪 tick）→ 同管道 → **重算**特定区间 → `ver` 覆盖
7. **质量评分** → 策略 `has_enough_data()` **决定是否跳过**本轮决策

---

## 常见坑与已有方案的呼应

* **晚到 / 抖动**：通过**两层聚合 + 水位 + ReplacingMergeTree(ver)** 解决，策略端始终拿**最新版**。
* **多分辨率**：同一套管道复制一份 10s 视图即可；或者把窗口参数化，生成多个 MV。
* **查询性能**：按日分区、(symbol, ts_start) 排序；近 10 分钟查询走热分区，`index_granularity` 8192 足够。
* **一致性**：策略热链路走 Kafka，不直接压 CH；冷启动/历史依赖 CH。
* **与你前 1–6 步**：

  * **Reg-Lite** 不因聚合改变；
  * **TTL 新鲜度**：bar → envelope 的打点基于 `ts_end`；
  * **仲裁/预留**：不受影响；
  * **OCO/执行矩阵**：独立层。
