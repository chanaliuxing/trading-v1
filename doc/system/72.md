好，进入 **P5：250 ms 数据聚合与抖动消除**。
下面是一份可直接落地的**完整实现规范**（不生成文件）：数据契约 → Redis 结构 → 聚合与水位 → 回填 → ClickHouse 表/物化视图 → 特征增量计算 → 每策略独立节奏与“就绪门” → 监控/告警 → 演练与验收。

# 1) 数据契约（Tick → Bar）

**事件时间（event-time）优先**，所有聚合按 `tick.ts_event`（券商时间或最接近成交时间），允许**迟到 L**（建议 1500–3000 ms）。
Tick 标准化字段：

```text
symbol, ts_event (ns/us/ms), src='ibkr', stream='TRADES|BIDS|ASKS',
price, size, trade_id(optional), seq(optional), bid(optional), ask(optional)
```

聚合窗口：`250ms` → 派生 `1s` → `5s` → `10s` → `1m`。
OHLC 规则（任何频率）：

* `open`=窗口内第一笔 `price`；`close`=最后一笔；
* `high/low`=窗口内 max/min；`volume`=∑size；`vwap`=∑(price*size)/∑size（若 size=0，用 last-known size=1 近似）。
  混合流：若无 trade，则以 `mid=(bid+ask)/2` 补，标记 `synthetic=1`。

**幂等键**：`(symbol, window_end, freq, src, ver)`；同一 `(symbol,window_end,freq)` 迟到修正用更大 `ver` 覆写。

---

# 2) Redis 热窗结构（低延迟聚合的“工作内存”）

* `RB:{symbol}`：环形缓冲队列（最近 10–15 s 的 ticks），元素 = `msgpack(tick)`，按 `ts_event` 写入；
* `WIP:{symbol}:{freq}`：当前未封窗窗口的 **聚合累加器**（hash），字段：`open,high,low,close,vol,notional,first_ts,last_ts,count,synthetic_cnt`；
* `WM:{symbol}`：**水位线**（watermark）记录：`last_emitted_end[freq], last_seen_event_ts, lateness_budget_ms`；
* 可选：`DLQ:TICKS` 流，用于异常 tick（时间倒退/价格异常）。

Redis 仅作**短期热窗**与水位缓存；**权威存储在 ClickHouse**。

---

# 3) 聚合器（Aggregator）与水位线（Watermark）

## 3.1 核心参数

```yaml
ingress:
  max_batch_ms: 50             # 读取 tick 的最大批间隔
  max_batch_size: 2000
watermark:
  lateness_ms: 1500            # 允许迟到 L
  max_catchup_ms: 5000         # 断流后最大追赶跨度
bars:
  freqs: [250ms, 1s, 5s, 10s, 1m]
  emit_on_close: true          # 窗口关闭即发
  backfill_on_late: true       # 迟到内重开窗修正
sanity:
  max_jump_bp: 500             # 单 tick 跳变上限（基于 rolling mid），超限入 DLQ
```

## 3.2 事件时间推进 & 窗口封口

* 维护 `WM.last_seen_event_ts`（按 `ts_event` 最大值推进）；
* **可安全封闭的窗口**：`window_end <= WM.last_seen_event_ts - lateness_ms`；
* 封窗→产出 bar，写 CH（`ReplacingMergeTree(ver)`）；迟到内到来的 tick → 重算该窗口并**更大 ver** 覆写。

## 3.3 伪码（精简）

```python
while True:
  ticks = read_from_ingress(max_ms=50, max_n=2000)         # IBKR → 正常化
  for t in ticks:
      if t.ts_event < wm.last_seen_event_ts - MAX_BACKWARD: put_dlq(t); continue
      wm.last_seen_event_ts = max(wm.last_seen_event_ts, t.ts_event)
      # 归入各频率的当前窗口累加器
      for f in FREQS:
          win = window_of(t.ts_event, f)                   # [start,end)
          acc = get_acc(symbol, f, win)
          acc.update_with(t)                               # O,H,L,C,vol,notional,...
  # 封窗
  safe_cutoff = wm.last_seen_event_ts - LATENESS_MS
  for f in FREQS:
      for win_end in ready_windows(symbol, f, safe_cutoff):
          bar = finalize(acc[symbol,f,win_end])
          ver = now_ms()                                   # 单调版本
          write_clickhouse("bars_"+f, bar, ver)            # 幂等覆盖
          drop_acc(symbol,f,win_end)
```

# 4) 开盘前/断流后的**回填 (Backfill)**

* **开盘前（T-5 分）**：对交易日白名单 `symbols`，从 IBKR 历史接口**拉 1s bars**（近 30–60 min）；写入 `bars_1s` 与 `bars_5s/10s/1m`（通过 CH 物化视图或离线聚合）；
* **断流恢复**：取“最后成功 `window_end` 之后”的缺口区间，**顺序拉取 1s** 回补，标记 `source='ibkr_hist'`、`synthetic=maybe`；
* 250 ms 级**不回填**（历史接口无 250 ms），直接从恢复时刻开始；这不会影响 5–10 s 决策，因为策略有**就绪门**与历史特征缓存。

**回填与幂等**：bar INSERT 带 `(symbol,window_end,freq,ver)`；回填的 `ver` 小于实时流水 `ver` 时不会覆盖。

# 5) ClickHouse 表（原子/可回放）

## 5.1 原始 tick（可选，便于审计）

```sql
CREATE TABLE ticks_raw (
  ts_event   DateTime64(6),         -- 事件时间
  ts_ingest  DateTime64(6) DEFAULT now64(6),
  symbol     LowCardinality(String),
  src        LowCardinality(String),   -- 'ibkr'
  stream     LowCardinality(String),   -- 'TRADES'|'BIDS'|'ASKS'
  price      Float64,
  size       Float64,
  trade_id   String,
  seq        UInt64,
  ver        UInt64
) ENGINE = MergeTree ORDER BY (symbol, ts_event);
```

## 5.2 Bars（250ms / 1s / 5s / 10s / 1m）

```sql
CREATE TABLE bars_250ms (
  window_start DateTime64(3),
  window_end   DateTime64(3),
  symbol       LowCardinality(String),
  open Float64, high Float64, low Float64, close Float64,
  volume Float64, notional Float64, vwap Float64,
  synthetic UInt8, src LowCardinality(String),
  ver UInt64, ingest_ts DateTime64(3) DEFAULT now64(3)
) ENGINE = ReplacingMergeTree(ver)
PARTITION BY toDate(window_end)
ORDER BY (symbol, window_end);
```

> 用相同结构分别建 `bars_1s`、`bars_5s`、`bars_10s`、`bars_1m`。

## 5.3 物化视图（可选：1s→5s/10s/1m）

如果聚合器已直接产出所有频率，可跳过；否则：

```sql
CREATE MATERIALIZED VIEW mv_1s_to_5s TO bars_5s AS
SELECT
  toStartOfFiveSecond(window_end) AS window_end,
  min(window_start) AS window_start,
  symbol,
  anyLast(src) AS src,
  argMin(close, window_end) AS open,
  max(high) AS high,
  min(low) AS low,
  argMax(close, window_end) AS close,
  sum(volume) AS volume,
  sum(notional) AS notional,
  if(volume>0, notional/volume, close) AS vwap,
  max(synthetic) AS synthetic,
  max(ver) AS ver
FROM bars_1s
GROUP BY symbol, window_end;
```

# 6) 特征管线（增量、可跳过）

## 6.1 特征清单（示例）

* 价格类：`ret_1s, ret_5s, zscore_20, ema_fast/slow, vwap_dev`
* 波动类：`atr_14 (基于1s或5s), σ_EWMA(30m)`
* 质量类：`gap_ratio, spike_flag, qscore`（0–100）

## 6.2 特征表（5s 粒度示例）

```sql
CREATE TABLE features_5s (
  ts_end   DateTime64(3),
  symbol   LowCardinality(String),
  close    Float64,
  vwap_5s  Float64,
  atr_14   Float64,
  ema_fast Float64, ema_slow Float64,
  zscore_20 Float64,
  qscore   UInt8,
  ver      UInt64,
  ingest_ts DateTime64(3) DEFAULT now64(3)
) ENGINE = ReplacingMergeTree(ver)
PARTITION BY toDate(ts_end)
ORDER BY (symbol, ts_end);
```

## 6.3 增量计算（伪码）

```python
# 输入：bars_1s/5s 流；维护每 symbol 的状态（EMA/Welford）
state = dict()
def on_bar_1s(symbol, bar):
  s = state.setdefault(symbol, init_state())
  s.update_ema(bar.close)
  s.update_atr(bar.high, bar.low, bar.close)
  if bar.window_end aligned with 5s:
      feat = make_features(s, bar)
      write_CH("features_5s", feat, ver=now_ms())
```

**数据就绪门**（Readiness Gate）：

* 对每个策略声明**所需最小历史**（例如：`ema_slow=60` 根 5s bar → 300 s）；
* 若 `now - features.ts_end > cadence_s + jitter` 或历史不足 → **本次策略跳过**（不产生意图）。

# 7) 每策略独立节奏（Scheduler）+ 跳过策略

调度器为**每个策略实例**维护独立 cadence：

```yaml
strategy_runtime:
  meanrev_v2:A: { cadence_s: 5,  max_lag_ms: 2000 }
  trend_v1:B:   { cadence_s: 10, max_lag_ms: 2500 }
  breakout_v1:C:{ cadence_s: 20, max_lag_ms: 3000 }
```

**执行循环（伪码）**

```python
async def strategy_loop(strategy_id, symbols, cadence_s, max_lag_ms):
  while running:
    t0 = now()
    for sym in symbols:
      feat = await fetch_latest_features(sym)         # 从 CH/Redis 缓存读
      if not ready(feat, need_history=strategy.need_history, max_lag_ms=max_lag_ms):
          metrics.skips.labels(strategy_id,sym,"not_ready").inc()
          continue
      await strategy.on_features(sym, feat)           # 进入 DSL Rule 引擎
    await sleep_until(t0 + cadence_s)                 # 独立节奏
```

**ready() 条件**（全部满足才执行）：

* `feat.ts_end >= now - max_lag_ms`（新鲜度）
* `feat.has_history >= strategy.need_history`（长度）
* `feat.qscore >= threshold` & `gap_ratio <= threshold`（质量门）

# 8) 监控 & 告警（关键 SLO）

**延迟**

* `bars_emit_lag_ms_p50/p95/p99`（`now - window_end`）
* 目标：p99 < **1000 ms**（含 250 ms 窗口 + 迟到修正）

**稳健性**

* `late_ratio`（迟到修正条数 / 总条数）< 5%
* `gap_rate`（缺窗率）< 0.1%
* `redis_ring_backlog_len`、`agg_batch_size`
* `ch_insert_errors_total`、`mv_mutations_backlog`

**质量**

* `spike_flags_total`、`qscore_avg`
* `synthetic_ratio`（用 mid 填充的占比）

**策略就绪**

* `strategy_skips_total{reason}`
* `per_strategy_cadence_jitter_ms_p95`

**告警阈值示例**

* `bars_emit_lag_ms_p99 > 1500` 持续 3 分钟 → 黄牌
* `gap_rate > 0.5%` 任意 5 分钟窗口 → 橙牌（暂停该 symbol 新策略意图）
* `ch_insert_errors_total` 连续增长 → 橙牌
* `strategy_skips_total{not_ready}` 快速攀升 → 检查回填/特征链

# 9) 演练与验收（P5 退出标准）

**A. 延迟与缺口**

* 播放实盘/回放流 30–60 分钟：`bars_emit_lag_ms_p99 < 1000 ms`，`gap_rate < 0.1%`
* 与 IBKR/TWS 的 1m 线对比：OHLC 偏差 ≤ **1 tick 或 1%**（取更严格）

**B. 回填**

* 开盘前 30–60 min 的 1s 回填**准时完成**；断流 2–3 分钟后**无缺窗**（1s 级别自动补齐）

**C. 策略就绪门**

* 人为让某 symbol 缺历史/落后 → 该策略实例**自动 skip**；历史补齐后**自动恢复**

**D. 资源/稳定**

* Redis、聚合器 CPU、CH 写入吞吐稳定无退化；DLQ < 0.1%
* 所有监控面板到位；阈值告警能触发

> 全部满足 → **P5 完成**；策略节奏保持 5–10 s（可 per-strategy 配置），同时你拥有 250 ms 级别的低抖动行情基座。

# 10) 与现有系统的对接

* **Phase1/2 替换**：以 Aggregator 产出的 `bars_*` 与 `features_*` 作为“唯一行情/特征源”；
* **DSL 策略引擎**：直接消费 `features_5s`（或 10s/1m 视策略需求）；
* **风控/断路器**：沿用 P4，保持“就绪门→风控前门→预留→执行”的顺序；
* **Exactly-Once**：bar 插入 `ReplacingMergeTree(ver)`，迟到重发以更大 `ver` 覆盖；特征同理。
