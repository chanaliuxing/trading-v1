# A. 最小可用纵向切片（MVS）一眼图（文字版）

```
IB TWS/Gateway (tick, order/fill)
   ↓ (250ms tick; 抖动)
[Tick Collector] → Redis(5s桶状态; watermark/emit_buffer)
   ↓
[5s Aggregator] → Kafka: md.bar.5s.v2
   ↓
[CH Writer] → ClickHouse (bar_5s_v2, bar_1m_v2, feat_intraday_v2)
   ↓
[Strategy Engine v1] (每策略独立 5s/10s/20s) 
   ↓  engine.order.request.v2
[RiskSvc + PG Ledger SPs]  审批 + 幂等预留 + 锁
   ↓  risk.decision.v2(APPROVED)
[Exec Safety Kernel] (OCO/追踪/节流/兜底)
   ↓
[IB Adapter]  ↔  IB (place/modify/cancel; reconnect/adopt)
   ↑ exec.order.status.v2 / exec.fill.v2
[Portfolio Service] -> position/pnl snapshot
   ↕
[Backfill Scheduler] ←→ ClickHouse / IB (缺口探针/回补/熔断)
[Prom/Grafana] 全链路指标
```

# B. 一锤定音的**建表与Topic**（ClickHouse & Kafka）

## B1. ClickHouse 表（生产参数）

**5s Bar（去重）**

```sql
CREATE TABLE qsys.bar_5s_v2
(
  symbol LowCardinality(String),
  ts_start DateTime64(3, 'UTC'),
  ts_end   DateTime64(3, 'UTC'),
  open Float64, high Float64, low Float64, close Float64,
  vol UInt64, vwap Float64,
  rth UInt8, source LowCardinality(String),   -- 'AGG'|'BACKFILL'
  calc_mode LowCardinality(String),           -- 'realtime'|'backfill'
  late_count UInt16,
  event_id UUID
)
ENGINE = ReplacingMergeTree(event_id)
PARTITION BY toDate(ts_start)
PRIMARY KEY (symbol, ts_start)
ORDER BY (symbol, ts_start)
TTL toDate(ts_start) + INTERVAL 30 DAY
SETTINGS index_granularity=8192;
```

**1m Bar（汇总写入，或由物化视图滚动聚合）**

```sql
CREATE TABLE qsys.bar_1m_v2 (...) ENGINE = ReplacingMergeTree(event_id)
PARTITION BY toDate(ts_start) PRIMARY KEY (symbol, ts_start) ORDER BY (symbol, ts_start)
TTL toDate(ts_start) + INTERVAL 90 DAY;
```

**分钟内特征（可选）**

```sql
CREATE TABLE qsys.feat_intraday_v2
(
  symbol LowCardinality(String),
  ts DateTime64(3,'UTC'),
  atr_1m Float64, ema1m_20 Float64, vwap Float64, adx_1m Float64, ...
)
ENGINE = ReplacingMergeTree()
PARTITION BY toDate(ts) PRIMARY KEY (symbol, ts) ORDER BY (symbol, ts)
TTL toDate(ts) + INTERVAL 30 DAY;
```

> 注：我们用 `ReplacingMergeTree(event_id)` 抗重；5s 生产写 `calc_mode='realtime'`，回补写 `calc_mode='backfill'`。

# F. **SLO 与 PromQL（直接可用）**

**核心 SLO**

* `unprotected_window_seconds == 0`（任何订单首填后 1s 内有保护）
* `bar_emit_latency_ms{symbol}.p95 < 150`
* `engine_strategy_exec_latency_ms{strategy}.p95 < 200`
* `oco_attach_success_rate > 99.5%`
* `backfill.success_rate > 99%`

**PromQL 片段**

```promql
# OCO 附挂成功率（5m）
sum(rate(order_oco_attach_success_total[5m])) /
clamp_min(sum(rate(order_oco_attach_success_total[5m])) + sum(rate(order_oco_attach_fail_total[5m])), 1)

# 5s bar 发出延迟 p95（ms）
histogram_quantile(0.95, sum(rate(bar_emit_latency_ms_bucket[5m])) by (le))

# 策略实际节奏
avg_over_time(engine_strategy_actual_cadence_s[10m])

# 预留未释放异常
sum(ledger_reserved_usd) by (strategy)

# 回补限流比例（1h）
sum(increase(backfill.rate_limited_total[1h])) / clamp_min(sum(increase(backfill.retry_total[1h])) ,1)
```

# G. **首日上线烟测清单（逐项打钩）**

1. **连接**：IB 心跳 OK；Kafka 集群 Healthy；Redis/CH/PG 连接成功
2. **数据**：5s bar 事件 `md.bar.5s.v2` 有流；`late_count` 偶发但不持续；CH 实时可查
3. **引擎**：策略实际节奏=配置±1s；`skips_total` 仅偶发（数据不足/非 RTH）
4. **风控**：`approve_and_reserve` 命中 `APPROVED`；账本 `reserved_usd` 与 `HELD sum` 差额=0
5. **执行**：首填→OCO≤1s；追踪改价不超频；终态释放
6. **回补**：探针有缺口→调度回补；`rate_limited_total` 可控；无大面积熔断
7. **监控**：面板 metrics 正常；告警测试触发/恢复OK
8. **回滚**：设置 `engine.mode=flatten-only` 能 1 分钟内清仓并冻结新单

# H. **三条“红线”与兜底**

* **红线 1**：任何订单出现无保护窗口 → 立即 `flatten-only`，并启用 Stop-MKT
* **红线 2**：PG 账本差额≠0（预留与 HELD 不等）→ 冻结下单，仅放成交释放
* **红线 3**：策略 exec p95>500ms（连续 5 分钟）→ 自动把该策略 cadence×2 并发告警

# J. 关键设计复核（确保无遗漏）

* ✅ **每策略独立资金池**：PG 账本按策略记账 + advisory lock（策略×symbol）

* ✅ **可恢复**：IB adopt_existing；OCO 组重建；对账日志
* ✅ **可观测**：Prom 指标全集 + SLO/告警
* ✅ **策略易用**：StrategyAlgorithm API、模板库（ORB/Trend/VWAP/Range/Pair）
* ✅ **影子→小额→放量**：上线路径明晰；回滚开关 `flatten-only`
