有，而且都直接影响“出不出手、怎么出手、出手多大”这三件事。下面只聚焦**交易决策本身**的关键缺口与方案（不谈基础设施），按优先级给出：**要补什么 → 为什么 → 怎么落地 → 验收指标**。做完这些，你的决策质量和一致性会跃迁一个层级。

# P0（立刻补齐，直接影响盈亏与一致性）

### 1) 决策新鲜度与截止时间（Decision Freshness & Deadline）

* **缺口**：没有硬性的“决策必须在 bar 结束后 X ms 内产生/失效”的约束；老信号可能被延迟执行。
* **方案**：为每次决策设置 **DLB（Decision Latency Budget）** 与 **TTL**：

  * 5s 策略：`bar_end + 800ms` 内必须生成 intent；intent **有效期 2s**（超时撤并重估）。
  * 在 intent 中携带 `bar_id / ts_bar_end / ttl_ms`，执行器超时即拒。
* **验收**：仪表盘显示**bar_end→intent_publish p99 ≤ 800ms**，`expired_intent_rate < 1%`。

### 2) 决策前置必备条件校验（Pre-Decision Validator）

* **缺口**：策略直接读取特征并下判，没有统一的“可判定性”校验。
* **方案**：对每次判定执行 4 项硬校验：

  1. **窗口充分**（特征所需最短历史 N 个 5s bar 已齐）；
  2. **数据质量 OK**（无 NaN/Inf/跳变，ATR/成交量非零）；
  3. **市场状态可用**（有 NBBO 或有效中价；LULD/SSR/Halt 状态已确定或降级处理）；
  4. **成本覆盖**（预估滑点+费用后，edge 仍 > 最小阈值）。不满足则**跳过本轮**。
* **验收**：`skipped_due_to_insufficient_context / total_decisions` 明确可见且 < 5%；无“半成品信号”。

### 3) 决策 → 执行意图翻译层（Intent Translation Policy）

* **缺口**：策略常直接决定“下什么单型”；容易与微观结构错位。
* **方案**：策略只输出**方向/目标头寸/容忍度**，由翻译层根据流动性/点差/波动自适应选择：

  * 点差小、成交量足：`LMT`（贴内盘±k tick，带价格围栏）；
  * 波动放大：`STP_LMT`（触发保护 + 限价）；
  * 短期机会且风险可控：`IOC` 子单；
  * 大单：自动切换到 TWAP/POV 子单计划，并**同步挂 OCO 保护**（已在你系统中，但要前置到“首次子单成交即挂”）。
* **验收**：按 **spread quantile** 分桶的**成交成本分布**显著收敛；过宽/过远价格意图被翻译层纠正（见拒单/改单原因统计）。

### 4) 头寸目标化与一次只做一件事（Target Positioning & Single-Action）

* **缺口**：增仓/减仓/反手的规则在不同策略里不一致，容易互相打架。
* **方案**：统一用 **目标头寸**（`target_qty`）表达任何决策；引擎根据当前 `pos_qty` 计算**净变动**并生成**唯一操作**：

  * 若已有同 symbol 的**进行中决策**且 TTL 未过 → 合并/覆盖为最新 `target_qty`；
  * 每策略/每标的 **同一时刻仅允许一个活动目标**。
* **验收**：`concurrent_intents_same_symbol` = 0；反手时不会短暂裸露无保护头寸。

### 5) 多策略冲突仲裁（Cross-Strategy Arbitration）

* **缺口**：不同策略可能同时对同一标的做相反决策，或总敞口超限。
* **方案**：增加**仲裁器**：

  * 先按**策略优先级**（IR/长期夏普/资本池规模）打分；
  * 若方向冲突，比较**净边际收益 = 期望收益 – 成本 – 约束惩罚**，胜者获得名额；
  * 约束惩罚：行业集中度、净/总杠杆、回撤压力、计划数量限制。
  * 未获名额的决策进入 `DEFERRED` 或 `SKIPPED`，并记录原因。
* **验收**：同一 symbol 同时相反方向的**生效决策数=0**；被仲裁淘汰的决策**累计边际效益**为负或低于阈值。

### 6) 头寸大小与资金池（Sizing with Volatility Targeting + Pool Caps）

* **缺口**：虽有策略资金池，但“如何从信号强度→下单规模”的映射不统一。
* **方案**：

  * **波动目标化**：`size = k * pool_nav * target_vol / realized_vol(symbol)`（k 由 IR 标定）；
  * **Kelly-lite**：用**半凯利**上限约束边界；
  * **单笔/单标的/单策略**多级上限（名义、delta、保证金占用、参量化 participation rate）；
  * **亏损减仓曲线**：日内/滚动回撤越大，k 线性衰减。
* **验收**：`per-strategy realized_vol ≈ target_vol`（偏差 < 15%）；`margin_utilization` 不越界；回撤阶段自动降档。

### 7) 退出与保护策略标准化（Exits & Protections）

* **缺口**：止损/止盈/时间止损在不同策略上不一致，且可能滞后。
* **方案**：三层保护**统一模板**：

  1. **灾难止损**（catastrophic）：进场即设，绝不取消；
  2. **跟踪止损**（ATR/波动自适应，带**滞回**与**宽松窗口**避免假突破）；
  3. **时间止损**（horizon 内未达期望，就按滑点预算退出）。

  * 所有保护**与已成交头寸比例同步**（部分成交即按比例调整 OCO）。
* **验收**：尾部亏损（95% 分位）压缩；**止损触发后成交滑点 p50/p90**下降（市价→止损限价）。

### 8) 决策去抖与冷却（Hysteresis & Cooldown）

* **缺口**：高波动时来回翻转；止损后马上重进。
* **方案**：

  * **信号阈值双边界**（enter > a，exit < b，a>b）+ **最短持有时间**；
  * **止损冷却**：同方向 `cooldown_bars` 内不再开同向仓位；
  * **资金/风控 hit 后冷却**：策略被风控拒超 N 次→降频或短暂停止。
* **验收**：翻转率/交易次数在高波动时**下降**且净收益率**上升**；重复被拒单的策略被自动降频。

# P1（强烈建议，提升边际胜率与一致性）

### 9) Regime/环境感知（Regime Awareness）

* **方案**：在决策信封写入 `regime_tag`（趋势/均值回归/高波/低波/开盘前 30min/午后等），允许每策略设**允许/禁用**的 regime 集合，并在翻译层调整单型与价格围栏。
* **验收**：禁用 regime 的期间，策略**不产生意图**；启用 regime 的期间，单型选择分布更合理（成本更低）。

### 10) 成本/冲击前估（Cost-of-Trade Gate）

* **方案**：下判前估算**可得流动性**、**参与率**、**预期冲击**；若 `expected_edge <= expected_cost + risk_buffer` → **直接否决**（intent 不发）。
* **验收**：负边际的交易显著减少；“到手边际 < 0”的占比下降。

### 11) 决策一致性与可复现（Snapshot & Hash）

* **方案**：每次决策随身记录并落库：`features_hash`, `param_hash`, `bar_ids`, `market_state_version`, `sizing_inputs`。
* **验收**：复盘任意 `decision_id` 能**复现同一判定**（重跑产生同样 output）。

### 12) 影子/AB 与在线校准（Online Calibration）

* **方案**：同策略两套参数/阈值并行（影子），按 symbol/时间分桶对比 **命中率、滑点、拒单率**，在线调参至稳定区域。
* **验收**：参数变更后 **影子优于主**才放量；失败自动回滚。

## “决策信封（Decision Envelope）”建议字段（统一给所有策略）

```text
decision_id
strategy_id / strategy_version / param_hash
symbol
bar_id, ts_bar_start, ts_bar_end
regime_tag
signal_score (强度归一化到 [0,1])
target_qty, max_notional, max_participation
price_intent { ref='mid/last', offset_ticks, hard_ceiling_px, hard_floor_px }
risk_overrides { catastrophic_stop_px, trailing_atr_mult, time_stop_s }
cost_estimates { slippage_bp, fees, impact_bp, confidence }
freshness { dlb_ms, ttl_ms }
reason_codes [ rule/feature 触发摘要 ]
```

> 所有执行与风控都以 Envelope 为准；**缺字段即拒**（由 Pre-Decision Validator 报告）。

---

## 与“每策略资金池 + 独立节奏”的结合

* **独立资金池**：为每策略记录 `pool_nav / pool_cap / pool_margin_limit`，Sizing 以池为单位；
* **独立节奏**：Scheduler 读取每策略 `cadence_s` 与 `jitter_ms`；封顶每策略**每窗口最大决策数**；
* **缺数据智能跳过**：如果 `min_history_ok=false` 或 `market_state_stale=true`，该轮**跳过**并记 `skip_reason`。

---

## 监控与 SLO（只列与决策直接相关的）

* **Freshness**：`bar_end→intent_publish p95/p99`、`expired_intent_rate`
* **Quality**：`edge_minus_cost > 0 的占比`、`post-trade alpha 实现率`
* **Stability**：`flip_flop_rate`、`cooldown_violations`
* **Sizing**：`realized_vol / target_vol`、`per-strategy margin_utilization`
* **Arbitration**：`conflict_intents_blocked`、`deferred_win_rate`（被推迟后再交易的胜率）

## 一周内能完成的最小落地（不写代码，仅工程动作）

1. 把 **Decision Envelope 字段**定版，加入策略引擎 API（策略只填 Envelope）。
2. 在策略引擎里接入 **Pre-Decision Validator** 与 **DLB/TTL** 强约束（不达标直接 `SKIP`）。
3. 上线 **Intent Translation Policy**（一个 YAML 即可：spread/vol 桶 → 单型与围栏参数）。
4. 打一个极简 **Arbitration**：同 symbol 同时相反方向只允许优先级高者通过。
5. 统一 **Sizing 曲线**（波动目标化 + 半凯利上限），把 per-strategy `pool_cap` 真正生效。
6. 保护模板落地：灾难止损 + 跟踪止损 + 时间止损 统一配置，**部分成交比例同步**。
