# 一、模块接口与任务清单 v1

## 1) Risk Service（风控审批与资金预留）

**外部输入（Kafka）**

* `engine.order.request.v2`（已定义）

**外部输出（Kafka）**

* `risk.decision.v2`（已定义）

**数据库**

* PG：调用存储过程

  * `core_sp_risk_approve_and_reserve(strategy_id, symbol, notional_usd, buffer_bps, idemp_key)`
  * `core_sp_release_on_terminal(idemp_key, order_id, terminal, reason)`
* 读写：`core_strategy_ledger / core_order_reservation / core_risk_event`

**REST（运维/调试，可选）**

* `POST /risk/approve`、`POST /risk/release`（已给）

**任务分解**

1. 接 Kafka，消费 `engine.order.request.v2`，做**分布式串行化**（PG advisory lock），产出 `risk.decision.v2`。
2. 集成**板块暴露/黑名单/时窗**检查；拒单枚举原因。
3. 集成**策略资金池**（上限/预留回收）。
4. 指标：`risk.approval_latency_ms`、`ledger.reserved_usd`、`reservation_mismatch_usd=0`。

**验收要点**：并发同一 `strategy×symbol` 仅 1 条 APPROVED；账不黑；拒单带原因。

---

## 2) Execution Service（执行器 / OCO / 止损 / 巡检）

**外部输入（Kafka）**

* `risk.decision.v2`、（可透传）`engine.order.request.v2`

**外部输出（Kafka）**

* `exec.order.status.v2`、`exec.fill.v2`

**数据库**

* PG：`core_order`（幂等写入）、`core_fill`（去重）、`core_order_reservation`（终态释放）
* 过程：`core_sp_release_on_terminal(...)`

**关键行为**

* **首填即挂 OCO**（止损/止盈），失败重试→升级 `Stop-MKT` 兜底。
* **三层止损**：硬停（%）、追踪 `Stop-LMT`（ATR_k + 去抖 + 改价限速）、Time-Stop。
* **巡检协程**（3–5s）：补齐缺失 OCO、清理“该撤未撤”。
* **反转持仓**：先平后建，避免遗留保护单。

**任务分解**

1. 幂等键贯穿：下单、OCO 附挂、撤改、释放。
2. 保护参数守门（上下界/步长）。
3. 指标：`order.oco_attach_success_rate=1.0`、`order.unprotected_window_seconds=0`、`stop_to_market_upgrade_total`。

**验收要点**：任何成交后 ≤1s 必有 OCO；无保护窗口=0；重复提交仅一单生效。

## 3) Reconciliation 2.0（冷启动对账）

**输入**

* IB 实挂单（permId/orderRef/价/量/方向）
* PG：`core_order/core_fill/core_position`

**输出**

* `core_reconcile_log` 审计
* 必要时补挂 OCO（走执行器）

**关键逻辑**

* 匹配序：permId → orderRef → 模糊（合约+方向+价差≤bps+时间窗）。
* “孤儿”领养、“幽灵”清理、上下文重建；安全阈（价格 bps、窗口、最大动作数）。

**验收要点**：重启后 ≤5 分钟恢复到可交易态；无幽灵单；所有实挂单被领养并受 OCO 保护。

## 4) Data Plane（IB Bridge / Aggregator / Backfill / CH Writer）

**Bridge**

* `ib_insync` 订阅 tick（trade）+ quote（去抖），产出 `md.tick.v2`。
* 断线指数退避重连；本地缓冲（内存/可选落盘）。

**Aggregator**

* `md.tick.v2` → 5s 固定桶，**watermark=2s**，**emit_buffer=200–400ms**，Redis 存桶状态。
* 产出 `md.bar.5s.v2`。

**Backfill**

* 缺口探针（CH 查询）→ IB 历史拉取（1m/5s）→ 5s 聚合写入 `calc_mode='backfill'`。

**CH Writer**

* 批量落库（5k/500ms）；`ReplacingMergeTree(event_id)` 去重。

**验收要点**：`emit_latency_p95<400ms`；Redis 续聚合 kill-9 不丢桶；缺口回补成功率≥99%。

# 三、E2E 验收脚本草案

## M1（安全内核 + 数据最小竖切）

### A. 执行安全/资金预留

1. **下单→预留**

   * 发布 1 条 `engine.order.request.v2`（同一个 `idempotency_key` 重放 3 次）。
   * 期望：Risk 仅 `APPROVED` 一次；PG `core_order_reservation` 一条，`reserved_usd` 正确；`core_strategy_ledger.reserved_usd` 增长=预留额。
2. **终态释放**

   * Exec 发 `FILLED`；调用 `core_sp_release_on_terminal`。
   * 期望：`ledger.reserved_usd` 恢复；Reservation 标记 `RELEASED`。
3. **并发冲关**

   * 并发 10 条同 `strategy×symbol` 请求。
   * 期望：仅 1 条 APPROVED，其余 `RETRY_LATER/LOCKED`；账不黑。

### B. OCO/止损与巡检

1. **首填→OCO 挂载**

   * 模拟部分成交（`exec.fill.v2`），观察 `exec.order.status.v2` OCO 子单生成。
   * 期望：≤1s 出现止损/止盈两条；`order.oco_attach_success_rate=1.0`。
2. **破坏 OCO**

   * 手动取消止损；巡检应在 5s 内补回。
   * 期望：`unprotected_window_seconds=0`；有“补挂”日志/指标。
3. **追踪限速**

   * 高频价格抖动；观察 Stop-LMT 改价频率受 `min_modify_secs/max_updates_per_min` 限制。

### C. Data Plane（5s bar）

1. **tick→bar**

   * 向 `md.tick.v2` 发送 1 分钟合成 tick（含±1500ms 乱序）。
   * 期望：`md.bar.5s.v2` 输出 12 条；`emit_latency_p95<400ms`；CH `bar_5s_v2` 行数匹配。
2. **kill-9 聚合器**

   * 中途 kill，重启后 Redis 恢复窗口，无重复桶。

**通过标准**

* OCO 成功率=100%；无保护窗口=0；`emit_latency_p95<400ms`；账不黑。

## M2（引擎骨架 + CH DAL + 策略调度）

### A. 5s/20s 独立节奏

* 启两策略（同 symbol 不同 cadence）。
* 期望：`engine.strategy.actual_cadence_s{strategy}` 分别接近 5/20；互不影响。

### B. 智能跳过

* 暂停某 symbol 的 5s 流。
* 期望：`DATA_GAP_5S` 跳过计数增加；恢复后自动继续。

### C. 幂等与只发一次

* 同一次 `on_microbar` 内多次命中下单条件。
* 期望：只产生 1 条 `engine.order.request.v2`（引擎去重）。

### D. 延迟退避

* 降慢 CH（注入 `sleep`）；
* 期望：`engine.strategy.actual_cadence_s` 自适应上调，慢查询报警触发。

**通过标准**

* on_microbar p95 < 200ms；独立节奏/跳过/幂等/退避全部达标。

# 四、On-call 处理手册（最小）

| 告警                                      | 判断       | 处置                                                                           |
| --------------------------------------- | -------- | ---------------------------------------------------------------------------- |
| `order.oco_attach_success_rate < 0.995` | OCO 挂载失败 | 1) 检查 IB 连通；2) 执行器日志搜 “attach fail”；3) 触发巡检；4) 必要时 `halt` 并人工补挂；恢复后 `resume` |
| `order.unprotected_window_seconds > 0`  | 出现无保护窗口  | 立即 `halt (flatten-only)`；排查执行链路；回归测试通过后恢复                                    |
| `emit_latency_p95 > 600ms`              | 聚合延迟     | 检 CH/Kafka/Redis；临时提高 `emit_buffer`；回补补齐                                     |
| `risk.reservation_mismatch_usd != 0`    | 账不平      | 运行 `core_sp_sweep_stale_reservations`；检查异常订单终态                               |
| `reconcile.restore_time > 300s`         | 对账超时     | 减小 `max_actions_on_start` 分批，扩大 price_tolerance_bps；必要时人工介入                  |
