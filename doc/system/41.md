有，还真有几件“比功能更要命”的事我们还没彻底落地。它们不写一行策略代码，却直接决定系统能不能长期稳稳地跑、出事能不能迅速止血。我把它们按“P0++ 必做”→“P1 建议”排好，并给出**验收标准**与**本周就能执行的动作**。做完这些，你的整套链路才算具备可上线、可回滚、可审计的工程质量。

# P0++（比功能更重要，先做它们）

1. **高可用与灾备（HA/DR）**

   * **缺口**：Kafka/PG/ClickHouse 目前是“能跑”，但**RPO/RTO**没定义、主备切换/备份恢复流程没固化。
   * **要点**：

     * Kafka：`replication.factor≥3`、`min.insync.replicas=2`、主题分区键按我们已定的 `decision_id/symbol`。
     * Postgres：Patroni/Keepalived 双机，**小时级 base backup + WAL**；恢复演练。
     * ClickHouse：Replica 表 + 日快照（S3/对象存储），`system.backup` + 恢复脚本。
   * **验收**：拉闸三选一（Kafka/PG/CH），**<5 分钟**自动/手动切主成功，数据不回退超出既定 RPO。

2. **EOD 三方对账（Broker ↔ 账本 ↔ 持仓）**

   * **缺口**：我们有实时账本，但**日终对账**（含现金/仓位/PnL）还没固化。
   * **要点**：

     * 用 IB **Flex** 报表拉取上一交易日成交与期末持仓；
     * 逐笔对 `fills`、期末对 `positions`、现金对 `broker.account.v1`；
     * 若不平：生成差异表并把第二天开盘前置为 **PAUSE**（全局闸门），人工确认后解锁。
   * **验收**：连续 5 个交易日自动对账**0 容差**或在阈值内，差异单可追溯到具体成交/费用。

3. **密钥与权限（Secrets & RBAC）**

   * **缺口**：IB 凭据/Kafka/PG 密码仍是环境变量或明文文件。
   * **要点**：

     * 统一进 Vault/Secrets Manager；按服务账号发放**最小权限**；
     * 所有容器只读挂载；密钥轮换剧本（季度）。
   * **验收**：禁用一把密钥→受影响的进程能在**<10 分钟**内换新恢复。

4. **统一时钟与事件顺序保证**

   * **缺口**：NTP 校时与“单计划内全链路同序”还没硬性约束。
   * **要点**：

     * NTP/Chrony 健康探针：**时钟漂移 >200ms 直接摘节点**；
     * Kafka 分区键固定：交易链路按 `decision_id`，保证**同一计划事件不乱序**；
     * 策略/风控/执行统一使用**事件时间戳**判重与去抖，处理**乱序/重复**。
   * **验收**：注入乱序/重复消息→系统不重复下单、不丢保护、账本无双计。

5. **灰度与自动回滚（Canary）**

   * **缺口**：我们有 Kill-Switch，但缺**按策略/版本的灰度发布与自动回滚**。
   * **要点**：

     * 每个策略带 `strategy_version` 与 `param_hash`；
     * 灰度列表（白名单）+ **影子模式**并行跑，达标才放量；
     * SLO/错误预算：风控 p95 < 400ms、撤改成功率 > 99%、超额预留率 < 1%，**任一破阈自动回滚**。
   * **验收**：一键把新版本推到 10% 策略→指标异常→系统**自动回滚**到上一版本。

6. **合规与审计（Trade Blotter / Best-Ex / Who-What-When）**

   * **缺口**：目前日志可查，但**合规口径**（谁、何时、为什么、怎么下的单）未标准化。
   * **要点**：

     * 建“交易流水（blotter）”表：`decision_id, order_ref, actor=strategy_id, reason, params, approvals, timestamps`；
     * 保存 OCO 保护轨迹、风控拒绝原因、CRS 纠偏记录；
     * 保留期 ≥ 7 年（可冷存），支持导出审计包。
   * **验收**：给任意 `decision_id`，5 分钟内输出**自洽的审计链**与证据包。

# P1（强烈建议，稳定性跃迁）

7. **双活 IB 网关 + 自动切主**

   * 两套 TWS/IBGW；连接探活失败自动切换，orderId 区间隔离、`clientId` 管理；冷启动领养覆盖两端。

8. **波动驱动的自适应节流**

   * 以 ATR/成交量/订单拒绝率动态调节：**下单频率、订单尺寸、止损宽度**；避免剧烈行情时“硬冲”。

9. **变更管控**

   * 策略/风控参数改动必须：PR 审核 + `param_hash` 记录 + 影子一日；紧急变更需事后审计。

10. **自动化 Chaos/GameDay 周期执行**

* 把我们列的演练脚本做成每周定时任务（非交易时段），自动注入故障、收集指标、生成报告。
