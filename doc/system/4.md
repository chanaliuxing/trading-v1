# 一句话答案（最应该先做哪一块）

**先做“安全内核（Safety Core）”**：
**执行安全 + 风控账本/订单预留 + 冷启动对账 + Kill-Switch + 启动前健康检查**。
理由：这几件事是“把钱管住”的最短路径，任何数据/策略加速在它们缺位时都可能放大风险（无 OCO 保护、重复下单、资金超限、宕机后失控等）。

---

## 为什么是它（结合我们既往讨论的痛点）

* **OCO/止损窗口**：之前分析里指出 OCO 挂载失败、撤改竞态、网络抖动会造成“无保护窗口”。先把这块打穿，5s 或 250ms 数据再快也不敢用。
* **并发冲关**：多策略同时过风控的“读-改-写”不是原子操作会超限。**PG Advisory Lock + 订单级资金预留**是硬护栏。
* **重启恢复**：Reconciliation 2.0 领养“孤儿单”、清理“幽灵单”、重建 `order_map`，否则重启就是赌博。
* **Kill-Switch/Pre-flight**：心跳丢失、依赖异常时全局只许平仓；启动前的阻塞式健康检查避免“带病跑”。

# 你现在就可以开工的“安全内核”清单（必须项）

### A. 执行服务硬化（Phase 4 的重写基线）

* **OCO 即时保护**：子单**首笔成交**→立刻挂 OCO（止损/止盈），数量随净仓动态调整；**修改失败→取消重下**；
* **止损三层**：

  1. **灾难硬停**（Stop-MKT，独立 OCA 组、始终在场）；
  2. **追踪 Stop-LMT**（microATR + 去抖 + 最小步进 tick + 最小改价间隔 + 每分钟限次）；
  3. **BE/Time-Stop**（达 R1 抬 BE，R2 收紧；到时平）；
     未成交 N 个 5s 窗口 → **升级为市价**兜底；
* **订单巡检协程**：每 3–5s 扫描“该取消未取消/该修改未修改”的订单，强制清理，确保**无保护窗口=0**；
* **幂等键**：对每个订单/动作生成 `idempotency_key`，数据库唯一约束，保证**重复请求只生效一次**；
* **反转持仓**：有符号仓位（BUY=+，SELL=−），反转 = **先平再建**，并重挂 OCO。

**验收**

* 断网/重连/超时/拍单突发场景下，**无保护窗口 >1s = 0**；
* 同一 `idempotency_key` 的重复提交，交易所与 DB 实际只有**一笔**；
* 反转流程不留下遗留止损/止盈挂单。

---

### B. 风控账本 + 订单级资金预留（策略资金池）

* **每策略资金池**：`capital_limit_usd / reserved / realized / unrealized`；
* **订单级预留**：风控审批通过即在内存+DB**原子预留**（`notional × (1+slippage_bps+fee_bps)`）；订单终态（Filled/Cancelled/Rejected）→**释放**；
* **审批原子化**：审批路径用 **PG Advisory Lock**（建议“策略×标的”粒度），保证“查-改-写”一致；
* **集中度/板块暴露**：接入 `risk_sector_tracker` 阈值（%NAV 或名义金额）；
* **互斥与限速**：`symbol_exclusive`、撤改速率上限、最大并发订单数。

**验收**

* **reserved** 与订单**终态释放**始终平衡（账不黑）；
* 并发下**同一标的**只会有**一个策略**拿到审批通过；
* 超限时风控拒单并带**明确原因**（资金不足/集中度/黑名单/时间窗）。

---

### C. 冷启动对账（Reconciliation 2.0）

* **孤儿领养**：从 IB 拉实挂单，按 `permId > orderRef > 模糊(合约/方向/价差)`序匹配，纳入监控；
* **幽灵清理**：DB 有、IB 无 → 标记 `STALE_CLOSED`；
* **上下文重建**：`order_map`、净仓/均价、OCO 关系；
* **安全阈**：价格容忍度（bps）、时间窗口、**最大动作数**，中途失败可回滚；
* **审计**：详细记录每次领养/清理/重建动作。

**验收**

* 重启后 ≤ **5 分钟**恢复到“可交易状态”；
* 不遗留**幽灵单**；所有实挂单都被**领养**并带上 OCO 状态。

---

### D. Kill-Switch + Pre-flight

* **Pre-flight**（阻塞）：PG/ClickHouse/Kafka/IB 连接、时间同步、配置校验，**任何一项失败即拒绝启动**；
* **Kill-Switch**：心跳缺失、CH/Kafka 重大异常、IB 掉线超过阈值 → **全局只许平仓**，并允许在控制面手动解除（带审计与观察期）。

**验收**

* 通过模拟停 IB/停 Kafka/延迟飙升，系统进入 only-flatten，复原后**人工解锁**方可继续。

# 与“安全内核”同步推进的最小数据侧（不拖后腿）

> 你已经决定用 **ClickHouse**，并且要 250ms tick + 5s 决策。为保证“安全内核”测试可跑，数据侧并行做**最小竖切**：

* **Kafka→CH**：`md.bar.5s.v2`（必做）、`md.tick.v2`（可稍后），物化视图入 `bar_5s_v2`；
* **抗抖动**：Data Service 侧 5s 窗口**本地缓冲 200–400ms** 后发送，CH 侧 **watermark 2s**；
* **缺口探针+回补**：today-so-far 拉历史，`calc_mode='backfill'`；
* **引擎消费**：引擎直接订阅 `md.bar.5s.v2`，保证 5s 策略能跑；
* **监控**：Kafka Lag、CH 入库 p95、缺口计数与回补成功率。

> 离线预计算（`feat_daily_snapshot_v2`）可以在安全内核成型后补上，但**接口预留**现在就定好。

# 后续的实施顺序（安全内核完成后）

1. **Per-Strategy 调度器**（最小 5s，可 10/20/1m，独立配置 + 智能跳过 + 可选自适应）
2. **离线预计算**（收市后快照 + 开盘加载，带 `params_hash`）
3. **Meta-Order（TWAP/VWAP/POV）** 基线（子单成交即挂 OCO、撤改节流、异常降级）
4. **回测一致性**（限价撮合 + 微周期滑点 + 拆单曲线 + 状态序列对齐）
5. **可观测性完善**（指标、告警、Runbook、重放工具）
6. **策略层级/Tier 与资金池**（同策略不同 Tier 独立资金上限与节奏）

---

# 立刻可用的验收用例（建议先在仿真或只平仓模式演练）

* **OCO 安全**：成交 → OCO 立挂；网络抖动下仍能在 <1s 完成；
* **幂等**：重复提交同 `idempotency_key`，IB 与 DB 都只见一单；
* **并发防冲关**：两个策略同时对同一 symbol 下单，只有一个得批；
* **崩溃恢复**：带实盘挂单的情况下重启，5 分钟内完全领养/清理完毕；
* **Kill-Switch**：停掉 IB 连接，系统进入 only-flatten；恢复后按流程解锁；
* **资金平衡**：预留→终态释放一致，`reserved` 不漂移。

---

## 小结

* **第一优先**：把“安全内核”打透（执行安全 + 资金/预留原子 + 对账 + Kill-Switch + Pre-flight）。
* **并行最小数据链路**：Kafka→ClickHouse 的 5s bar + 抗抖动 + 回补，确保 5s 策略能跑。
* 做到这一步，你就能**安全地**开启 5s 级的独立策略决策；后续再把离线预计算、Meta-Order、回测一致性和可观测性铺满。
