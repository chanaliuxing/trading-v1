好，**第 3 步：资金“预留-释放”看门狗（Reservation Watchdog）**。
目标：杜绝并发下单导致**资金超额**、订单异常/崩溃后出现**资金占用泄漏**，并在**冷启动**时**自愈**到一致状态；任何异常挂单能被**强撤**并释放预留。

我按“配置 → 资金账本与 API → 看门狗（TTL 扫描/强撤）→ 冷启动自愈 → 执行与风控接线 → 指标与自测”贴**可直接粘贴**的代码骨架（不生成文件）。

## B) 资金预留账本（线程安全 + 幂等）

> 设计要点
>
> * **按策略资金池**扣减：`pool_nav` / `pool_cap` / `margin_limit`（此处演示名义法，若有保证金实时数据可换用）。
> * **幂等**：同一个 `reservation_key`（建议用 `decision_id` 或 `plan_id`）多次调用只会**覆写**而非重复占用。
> * **动态调整**：收到**部分成交**→按**剩余可成交名义**自动**收缩预留**。
> * **终态释放**：订单 `FILLED/CANCELLED/REJECTED` → 立即释放。
> * **TTL**：超时自动释放（交给看门狗触发）。

```python
# -*- coding: utf-8 -*-
import time, asyncio
from dataclasses import dataclass, asdict
from typing import Optional, Dict, Any

def now_ms() -> int: return int(time.time()*1000)

@dataclass
class Reservation:
    reservation_id: str          # 全局唯一（建议：decision_id 或 plan_id）
    strategy_id: str
    symbol: str
    created_ms: int
    updated_ms: int
    amount_notional: float       # 预留的名义金额（USD）
    amount_remaining: float      # 动态收缩（随部分成交而变小）
    reason: str                  # 'entry','add','oco','child', etc.
    ttl_ms: int
    order_refs: Dict[str, str]   # {kind:'entry/oco/childN' -> order_ref}
    meta: Dict[str, Any]

class ReserveLedger:
    """
    - 仅内存模型（生产建议：落 PG 一张 reservation 表，并以 reservation_id 唯一）
    - 并发安全（asyncio.Lock）
    """
    def __init__(self, per_strategy_caps: Dict[str, float]):
        self._lock = asyncio.Lock()
        self._by_id: Dict[str, Reservation] = {}
        self._by_strategy_used: Dict[str, float] = {}
        self._caps = per_strategy_caps    # {strategy_id -> cap_usd}

    async def snapshot(self) -> Dict[str, Any]:
        async with self._lock:
            return {
                "used": dict(self._by_strategy_used),
                "items": {k: asdict(v) for k,v in self._by_id.items()}
            }

    async def can_reserve(self, strategy_id: str, need_usd: float) -> bool:
        async with self._lock:
            cap = self._caps.get(strategy_id, 0.0)
            used = self._by_strategy_used.get(strategy_id, 0.0)
            return (used + max(0.0, need_usd)) <= cap + 1e-6

    async def reserve(self, reservation_id: str, strategy_id: str, symbol: str,
                      amount_notional: float, ttl_ms: int, reason: str,
                      order_ref: Optional[str]=None, meta: Optional[Dict[str,Any]]=None) -> Reservation:
        """
        幂等：同 reservation_id 再次调用会“覆盖”额度并刷新 TTL（用于重算/合并）
        """
        async with self._lock:
            prev = self._by_id.get(reservation_id)
            now = now_ms()
            if prev:
                # 调整 strategy used：先减去旧的剩余，再加上新的
                delta = (amount_notional - prev.amount_remaining)
                used = self._by_strategy_used.get(strategy_id, 0.0) + delta
                cap  = self._caps.get(strategy_id, 0.0)
                if used > cap + 1e-6:
                    raise RuntimeError(f"cap_exceeded: need_delta={delta:.2f} used={used:.2f} cap={cap:.2f}")
                prev.amount_notional = amount_notional
                prev.amount_remaining = amount_notional
                prev.updated_ms = now
                prev.ttl_ms = ttl_ms
                prev.reason = reason or prev.reason
                if order_ref:
                    prev.order_refs[reason or "entry"] = order_ref
                prev.meta.update(meta or {})
                self._by_strategy_used[strategy_id] = used
                return prev

            # 新建预留
            used = self._by_strategy_used.get(strategy_id, 0.0)
            cap  = self._caps.get(strategy_id, 0.0)
            if used + amount_notional > cap + 1e-6:
                raise RuntimeError(f"cap_exceeded: need={amount_notional:.2f} used={used:.2f} cap={cap:.2f}")
            r = Reservation(
                reservation_id=reservation_id, strategy_id=strategy_id, symbol=symbol,
                created_ms=now, updated_ms=now,
                amount_notional=amount_notional, amount_remaining=amount_notional,
                reason=reason or "entry", ttl_ms=ttl_ms,
                order_refs={ (reason or "entry"): order_ref } if order_ref else {},
                meta=meta or {}
            )
            self._by_id[reservation_id] = r
            self._by_strategy_used[strategy_id] = used + amount_notional
            return r

    async def shrink_by_fill(self, reservation_id: str, fill_notional: float) -> Optional[Reservation]:
        """部分成交：按剩余名义收缩（不能 < 0）"""
        async with self._lock:
            r = self._by_id.get(reservation_id)
            if not r: return None
            if fill_notional <= 0: return r
            dec = min(fill_notional, r.amount_remaining)
            r.amount_remaining -= dec
            r.updated_ms = now_ms()
            # 归还策略池使用量（按 dec）
            self._by_strategy_used[r.strategy_id] = max(0.0, self._by_strategy_used.get(r.strategy_id, 0.0) - dec)
            return r

    async def attach_order_ref(self, reservation_id: str, kind: str, order_ref: str):
        async with self._lock:
            r = self._by_id.get(reservation_id)
            if not r: return
            r.order_refs[kind] = order_ref
            r.updated_ms = now_ms()

    async def release(self, reservation_id: str, cause: str="terminal") -> Optional[Reservation]:
        """释放剩余额度"""
        async with self._lock:
            r = self._by_id.pop(reservation_id, None)
            if not r: return None
            used = self._by_strategy_used.get(r.strategy_id, 0.0)
            self._by_strategy_used[r.strategy_id] = max(0.0, used - r.amount_remaining)
            r.amount_remaining = 0.0
            r.updated_ms = now_ms()
            r.meta["released_by"] = cause
            return r

    async def expire_candidates(self, now_ms_ts: Optional[int]=None):
        """返回超时的 reservation_id 列表（不释放，由看门狗外层决定是否强撤）"""
        now_ = now_ms_ts or now_ms()
        out = []
        async with self._lock:
            for rid, r in self._by_id.items():
                if (now_ - r.updated_ms) > r.ttl_ms:
                    out.append((rid, r))
        return out
```

## C) 看门狗（TTL 扫描 + 强撤 + 指标）

> 核心职责
>
> * 周期扫描**超时预留**：若还挂着活动订单 → 调用执行层 **cancel** 强撤；若无订单 → 直接释放。
> * 具有**节流**（防止撤单风暴）。
> * 所有动作都要有**指标与日志**可观测。

```python
from collections import defaultdict

class CancelPacer:
    def __init__(self, qps_symbol: float, qps_acct: float):
        self.sym = defaultdict(lambda: TokenBucket(qps_symbol))
        self.acct = TokenBucket(qps_acct)

    async def wait(self, symbol: str):
        while not (self.acct.allow() and self.sym[symbol].allow()):
            await asyncio.sleep(0.05)

class ReservationWatchdog:
    def __init__(self, cfg, ledger: ReserveLedger, exec_wrapper, logger, metrics):
        self.cfg = cfg; self.ledger = ledger; self.exec = exec_wrapper
        self.log = logger; self.m = metrics
        p = cfg["risk"]["reservation"]
        self.cancel_pacer = CancelPacer(p["cancel_qps_per_symbol"], p["cancel_qps_account"])
        self.interval = int(p["sweep_interval_ms"])
        self._stop = False
        self._task = None

    async def start(self):
        self._task = asyncio.create_task(self._loop())

    async def stop(self):
        self._stop = True
        if self._task: self._task.cancel()

    async def _loop(self):
        while not self._stop:
            try:
                await self._sweep_once()
            except Exception as e:
                self.log.error(f"[ResWD] sweep error: {e}")
            await asyncio.sleep(self.interval / 1000.0)

    async def _sweep_once(self):
        exps = await self.ledger.expire_candidates()
        for rid, r in exps:
            symbol = r.symbol
            # 有关联订单？逐个强撤
            if r.order_refs:
                for kind, order_ref in list(r.order_refs.items()):
                    await self.cancel_pacer.wait(symbol)
                    try:
                        self.m.reswd_cancel_attempts.labels(kind=kind).inc()
                        await self.exec.cancel(symbol, {"order_ref": order_ref})
                        self.log.warning(f"[ResWD] cancel sent rid={rid} kind={kind} ref={order_ref}")
                    except Exception as e:
                        self.m.reswd_cancel_fail.labels(kind=kind).inc()
                        self.log.error(f"[ResWD] cancel fail rid={rid} ref={order_ref}: {e}")
                        # 即便撤失败，也不立即释放资金；等下轮再试
                        continue
            else:
                # 无订单直接释放
                await self.ledger.release(rid, cause="ttl_no_order")
                self.m.reswd_release_no_order.inc()
                self.log.warning(f"[ResWD] release rid={rid} no-order")
```

## D) 冷启动自愈（Reconciliation 2.0 入口）

> 冷启动需要三步：
>
> 1. **同步券商活动订单**（真实 open orders）
> 2. **读取数据库订单表**（系统认为打开的订单）
> 3. 两边**匹配** → **领养孤儿** / **清理幽灵**；按“剩余可成交名义”**重建/收缩预留**

下面是骨架（你的 IB/DB 适配层替换 `list_broker_open_orders()`、`db_open_orders()` 即可）。

```python
@dataclass
class OpenOrderView:
    symbol: str
    order_ref: str
    side: str              # BUY/SELL/SELL_SHORT
    status: str            # Submitted/PreSubmitted/PartiallyFilled
    qty_total: float
    qty_filled: float
    limit_px: Optional[float]
    ts_ms: int

class ReservationReconciler:
    def __init__(self, cfg, ledger: ReserveLedger, logger, metrics, broker_adapter, db_adapter):
        self.cfg = cfg; self.ledger = ledger
        self.log = logger; self.m = metrics
        self.broker = broker_adapter
        self.db = db_adapter

    async def list_broker_open_orders(self) -> Dict[str, OpenOrderView]:
        """由 broker_adapter 实现；key=order_ref"""
        return await self.broker.open_orders()

    async def db_open_orders(self) -> Dict[str, OpenOrderView]:
        """由 db_adapter 实现；key=order_ref"""
        return await self.db.open_orders()

    async def run_once(self):
        bo = await self.list_broker_open_orders()
        db = await self.db_open_orders()

        # 1) 领养孤儿（券商有，DB无）
        for ref, oo in bo.items():
            if ref not in db:
                self.m.recon_adopt.inc()
                self.log.warning(f"[Recon] adopt orphan {ref} {oo.symbol}")
                # 写回 DB / 内存映射（具体由你的执行器/对账模块实现）
                await self.db.adopt(oo)

        # 2) 清理幽灵（DB有，券商无）
        for ref, oo in db.items():
            if ref not in bo and oo.status not in ("Filled","Cancelled","Rejected"):
                self.m.recon_ghost.inc()
                self.log.warning(f"[Recon] ghost {ref} {oo.symbol} => mark STALE_CLOSED")
                await self.db.mark_stale_closed(oo)

        # 3) 重建/收缩预留（以“剩余名义”为准）
        #   计算：remaining_notional = (qty_total - qty_filled) * (limit_px or mid_px)
        for ref, oo in (await self.db_open_orders()).items():
            rem_qty = max(0.0, oo.qty_total - oo.qty_filled)
            px = oo.limit_px or await self.db.ref_price(oo.symbol)
            remaining_notional = max(0.0, rem_qty * (px or 0.0))
            # reservation_id 建议用 plan_id/decision_id；此处演示用 order_ref
            rid = f"order:{ref}"
            if remaining_notional > 0:
                try:
                    await self.ledger.reserve(
                        reservation_id=rid, strategy_id=await self.db.strategy_of(ref),
                        symbol=oo.symbol, amount_notional=remaining_notional,
                        ttl_ms=self.cfg["risk"]["reservation"]["order_ttl_ms"],
                        reason="recon", order_ref=ref, meta={"recon": True}
                    )
                except Exception as e:
                    self.log.error(f"[Recon] reserve fail {rid}: {e}")
            else:
                await self.ledger.release(rid, cause="recon_zero")
```

## E) 风控与执行接线（把预留纳入批准链）

> 位置：`RiskService.approve()` 在通过 Reg-Lite、资金/集中度等规则后，**在真正提交给执行器前**做“预留”。
> 公式：
> `need = abs(target_qty) * ref_px * (1 + buffer_bp/1e4)`，`ref_px = mid/last`（保守取较大侧）。
> 预留成功 → 返回 OK，并把 `reservation_id` 透传给执行器；
> 执行器：下单/改单时调用 `ledger.attach_order_ref()`；收到 `FILLED/CANCELLED/REJECTED` 回报时 `ledger.release()`；收到 **部分成交**时 `ledger.shrink_by_fill()`。

**在 RiskService 中加入：**

```python
class RiskService:
    def __init__(self, cfg, market_state_provider, metrics, logger, ledger: ReserveLedger, ...):
        ...
        self.ledger = ledger
        self.res_cfg = cfg["risk"]["reservation"]

    async def approve(self, env, plan, ttl_ms: int):
        ...
        # -- 资金/集中度等你已有规则 --
        # 计算预留名义
        m = await self.ms.get(env.symbol)
        ref = max([x for x in (m.mid_px, m.last_px, m.ask_px if plan.side=="BUY" else m.bid_px) if x is not None] or [0.0])
        buffer_bp = float(self.res_cfg["buffer_bp"])
        need = (plan.qty or 0.0) * ref * (1.0 + buffer_bp/1e4)
        rid = env.decision_id  # 或 plan_id

        try:
            await self.ledger.reserve(
                reservation_id=rid, strategy_id=env.strategy_id, symbol=env.symbol,
                amount_notional=need, ttl_ms=min(ttl_ms, self.res_cfg["order_ttl_ms"]),
                reason="entry", order_ref=None, meta={"side": plan.side, "qty": plan.qty, "ref_px": ref}
            )
        except Exception as e:
            self.m.reservation_reject.inc()
            return False, {"kind":"reservation_cap", "reason": str(e)}

        # 批准通过，把 reservation_id 透传给执行层
        return True, {"reservation_id": rid, "need_usd": need}
```

**在执行器（place/modify/cancel 回调处）加入：**

```python
# 下单成功后（拿到 order_ref）
await ledger.attach_order_ref(reservation_id, kind="entry", order_ref=order_ref)

# Fill 回报（部分成交）
fill_notional = abs(fill_qty) * fill_price
await ledger.shrink_by_fill(reservation_id, fill_notional)

# 订单进入终态（Filled/Cancelled/Rejected）→ 释放
await ledger.release(reservation_id, cause=terminal_state.lower())
```

> **OCO/子单**：建议沿用同一个 `reservation_id`，但 `order_refs` 里按 `kind=tp/sl/childN` 加入引用；这样**任何子单终态**不影响预留，只有**主单终态或计划关闭**才释放；或选择“计划终态释放”。

## F) 启动序列与冷启动

在 `SystemManager` / `run_all.py` 启动顺序中插入（阻塞方式）：

1. **加载策略资金池上限** → 构造 `ReserveLedger(per_strategy_caps)`
2. **启动 ReservationWatchdog**：`await reswd.start()`
3. **执行 Reconciler.run_once()**（冷启动自愈）；等待 `reconcile_timeout_ms` 内完成
4. **启动 RiskService/Executor**（此时 ledger 已一致）

## G) 自测剧本（10 分钟）

1. **基本预留**：发 1 笔 BUY 100 @ 100，buffer 20bp → `need≈100*100*1.002=10020`，`ledger.used[strategy]` 增加。
2. **部分成交**：模拟 60 股 @ 100 成交 → `shrink_by_fill(6000)`，`used` 回落。
3. **终态释放**：订单 `CANCELLED` → `amount_remaining` 清零，`used` 回到初值。
4. **TTL 过期**：不成交不撤单，等 2 分钟，看门狗触发 cancel（fake 连接器返回 OK），随后释放。
5. **cap 越界**：策略池 cap=10,000，发两笔各 6000 → 第二笔 `reserve()` 抛 `cap_exceeded`，`RiskService.approve()` 返回 `reservation_cap`。
6. **冷启动自愈**：造一条 DB 打开但券商无的单 → `ghost` 计数 + `mark_stale_closed()`；造一条券商有但 DB 无的单 → `adopt` 计数 + `adopt()` 被调用；随后 `ledger.reserve()` 以剩余名义重建。

---

## H) 与前两步的协同

* **Reg-Lite**：在 `approve()` 里先过 Reg-Lite，再 `reserve()`，避免为必然违规的单占用额度。
* **Error Matrix**：看门狗触发的 `cancel()` 也走错误矩阵；若 pacing → 退避重试，直到撤成或 TTL 下一轮继续；**不会风暴**。

### 一句话总结

* 资金预留看门狗让系统在**并发/异常/崩溃**情形下仍能**不超额**、**可自愈**；
* 结合 **Reg-Lite + Error Matrix**，形成“**先校门，后占用；占用有 TTL；异常能撤；冷启能补**”的闭环；
* 落地后，你就具备**小流量生产**的关键安全网之一。
