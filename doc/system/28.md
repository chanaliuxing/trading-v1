# ① FiveSecondAggregator：Time&Sales 精确时间戳升级（补丁）

> 目标：在你现有 `FiveSecondAggregator` 基础上，最小改动即可开关 **T&S 模式**。默认仍走 Tick；设置 `use_time_sales=True` 后改为 Time&Sales（交易所时间戳，毫秒级），其余逻辑（Redis 水位、修复、缺口）不变。

把下面**三个片段**粘到你之前的聚合器里（同名方法直接替换/追加即可）。

## A. 配置新增字段（在 `AggConfig` 里追加）

```python
@dataclass
class AggConfig:
    ...
    use_time_sales: bool = False      # True 切为 Time&Sales（精确时间戳）
    ts_clock: str = "exchange"        # 'exchange' | 'local' ；优先用交易所时钟
    tbt_depth: int = 0                # TickByTick 拉取深度（0=无限，IB 会限流）
```

## B. 启动时订阅 Time&Sales（在 `start()` 内，订阅合约后追加）

```python
for sym in self.cfg.symbols:
    contract = Stock(sym, 'SMART', 'USD')
    await self.ib.qualifyContractsAsync(contract)

    if self.cfg.use_time_sales:
        # 订阅 AllLast（包含成交价、成交量、交易所与成交时间戳）
        self.ib.reqTickByTickData(contract, 'AllLast', self.cfg.tbt_depth, False)
    else:
        # 旧的 Tick 流
        self.ib.reqMktData(contract, '', False, False)

# 事件绑定：根据模式选择回调
if self.cfg.use_time_sales:
    self.ib.tickByTickAllLastEvent += self._on_tands   # 新增
else:
    self.ib.pendingTickersEvent += self._on_ticks
```

## C. 新增/改造回调与统一入口

### 1) 新增 Time&Sales 回调（把成交时间戳换算为 ms，并统一走 `_ingest_trade`）

```python
def _on_tands(self, tick):
    # ib_insync TickByTickAllLast: fields: time, price, size, exchange, specialConditions, ...
    # time 是 epoch秒（交易所时间），更精确
    ts_ms = int(tick.time * 1000)
    px = float(tick.price)
    size = float(tick.size)
    sym = tick.contract.symbol
    asyncio.create_task(self._ingest_trade(sym, px, size, ts_ms))
```

### 2) 复用原逻辑但改成“统一入口”（把原 `_ingest_ticks` 中每个 tick 的处理，抽成 `_ingest_trade`；原 `_ingest_ticks` 里只负责把 tick 转成本地时间戳后调用它）

```python
async def _ingest_trade(self, sym: str, px: float, size: float, ts_ms: int):
    if px is None or not size or size <= 0:
        return
    # 统计
    # _MET["agg_tick_ingested"].labels(symbol=sym).inc()  # 若你把“tick”理解为“成交”，这里也可以计

    win_start = floor_5s(ts_ms)
    win_end = win_start + 5000
    key = (sym, win_start)
    b = self.bucket.get(key)
    if not b:
        b = BarBucket(sym, win_start, win_end)
        b.bar_seq = self.last_bar_seq.get(sym, 0) + 1
        self.last_bar_seq[sym] = b.bar_seq
        self.bucket[key] = b
        self.emit_schedule[key] = win_end + self.cfg.emit_buffer_ms
        # _MET["agg_buckets_active"].inc()
    b.on_trade(px, size)

    # 是否落入“已过窗口 + 超过 buffer”的迟到区间？是→立刻发 REPAIR
    now_ms = int(time.time()*1000)
    if ts_ms > b.ts_end_ms + self.cfg.emit_buffer_ms:
        b.late_count += 1
        # _MET["agg_late_ticks"].labels(symbol=sym).inc()
        await self.emit_repair(b)

    try:
        await self._persist_bucket(b)
    except Exception:
        # _MET["agg_redis_fail"].inc()
        pass

# 旧 Tick 回调：仅做时间戳→统一入口
def _on_ticks(self, tickers):
    now_ms = int(time.time()*1000)
    for t in tickers:
        sym = t.contract.symbol
        px = float(t.last) if t.last else None
        size = float(t.lastSize) if t.lastSize else None
        if px is None or not size or size <= 0: 
            continue
        # 若使用本地时钟，保留 now_ms；否则也可以尝试 RTVolume 字段拆分交易时间
        asyncio.create_task(self._ingest_trade(sym, px, size, now_ms))
```

**到此为止**，`use_time_sales=True` 即可启用 T&S：5s 窗口切分基于交易所时间戳，修复率显著降低；你的 CH Writer 与策略引擎完全无感。

# ② 策略引擎：自动节奏降噪（过载自适应）

> 目标：**每策略**独立观察最近执行耗时分布；当 p95 超阈值（如 200ms）持续一段时间（如 5 分钟），自动把该策略 `cadence` *×2*（最多 ×4）。健康后缓慢下调（逐步恢复原始 cadence）。这能在策略多、特征多时，自动避免“卡一片”。

把下面**两段**加进你之前给的 `StrategyEngine`：

## A. 在 `__init__` 增加运行态 cadence 与窗口

```python
class StrategyEngine:
    def __init__(...):
        ...
        self._run_cadence: Dict[str, int] = {}     # 运行态 cadence_s（可动态调整）
        self._lat_hist: Dict[str, List[float]] = defaultdict(list)  # 近窗口 ms
        self._base_cadence: Dict[str, int] = {}    # 初始配置，向下恢复用
```

在 `start()` 完成实例化后，初始化并启动自适应任务：

```python
async def start(self):
    for sid, spec in self.specs.items():
        ...
        self._run_cadence[sid] = max(int(spec.cadence_s), 5)
        self._base_cadence[sid] = self._run_cadence[sid]
    ...
    asyncio.create_task(self._auto_backoff_loop())   # 新增
```

## B. 在回调处记录耗时并使用“运行态 cadence”

在 `_bar_dispatcher()` 与 `_worker_loop()` 两处，把 `cadence` 取自 `self._run_cadence[sid]`，并把执行时长记入 `_lat_hist`：

```python
cadence = max(self._run_cadence.get(sid, spec.cadence_s), 5)
...
self._metrics[sid]["lat_ms"] = (time.time()-t0)*1000
self._lat_hist[sid].append(self._metrics[sid]["lat_ms"])
if len(self._lat_hist[sid]) > 300:  # 滑动窗口，约 25 分钟（按5s节奏）
    self._lat_hist[sid] = self._lat_hist[sid][-300:]
```

## C. 新增自适应协程 `_auto_backoff_loop()`

```python
def _pctl(self, xs: List[float], q: float) -> float:
    if not xs: return 0.0
    ys = sorted(xs); k = max(0, min(len(ys)-1, int(len(ys)*q)))
    return ys[k]

async def _auto_backoff_loop(self):
    THRESH_P95_MS = int(os.getenv("ENGINE_P95_THRESH_MS","200"))     # 触发阈值
    UP_HOLD_ITERS = int(os.getenv("ENGINE_UP_HOLD_ITERS","5"))       # 连续触发次数（*30s）
    DN_HOLD_ITERS = int(os.getenv("ENGINE_DN_HOLD_ITERS","10"))      # 连续健康次数
    MAX_MULT = int(os.getenv("ENGINE_MAX_MULT","4"))                 # 最大倍率（×4）
    CHECK_EVERY_S = 30

    up_cnt = defaultdict(int); dn_cnt = defaultdict(int)

    while True:
        await asyncio.sleep(CHECK_EVERY_S)
        for sid in list(self._lat_hist.keys()):
            xs = self._lat_hist[sid][-180:]   # ~ 上 15 分钟样本
            p95 = self._pctl(xs, 0.95)
            base = self._base_cadence[sid]
            cur  = self._run_cadence[sid]
            # 过载：放大 cadence
            if p95 > THRESH_P95_MS and cur < base*MAX_MULT:
                up_cnt[sid] += 1; dn_cnt[sid] = 0
                if up_cnt[sid] >= UP_HOLD_ITERS:
                    self._run_cadence[sid] = min(cur*2, base*MAX_MULT)
                    up_cnt[sid] = 0
                    print(f"[AUTO] backoff {sid}: {cur}s -> {self._run_cadence[sid]}s (p95={p95:.0f}ms)")
            else:
                dn_cnt[sid] += 1; up_cnt[sid] = 0
                # 健康：缓慢恢复（每 DN_HOLD_ITERS 次把 cadence /2，直至回到 base）
                if dn_cnt[sid] >= DN_HOLD_ITERS and cur > base:
                    self._run_cadence[sid] = max(cur//2, base)
                    dn_cnt[sid] = 0
                    print(f"[AUTO] recover {sid}: {cur}s -> {self._run_cadence[sid]}s (p95={p95:.0f}ms)")
```

> 指标对齐：你已经导出了 `engine_strategy_exec_latency_ms` 和 `engine_strategy_actual_cadence_s`；这个 loop 会同步更新后者，Grafana 上能直接看到“策略被自动降噪”的轨迹。

# ③ 极简健康探针（选用；无额外依赖也可）

如果你允许加一个很轻的依赖，可以用 `aiohttp` 暴露 `/live` 和 `/ready`。把下面小段放进聚合器与引擎的 `start()` 里起一个任务：

```python
# 依赖: aiohttp>=3.9
from aiohttp import web
import asyncio

async def boot_health_probe(port:int, ready_fn):
    app = web.Application()
    async def live(_):  return web.Response(text="OK")
    async def ready(_): return web.Response(text="OK" if await ready_fn() else "NOT_READY", status=200 if await ready_fn() else 503)
    app.add_routes([web.get('/live', live), web.get('/ready', ready)])
    runner = web.AppRunner(app); await runner.setup()
    site = web.TCPSite(runner, "0.0.0.0", port); await site.start()
    return runner  # 需要时可 runner.cleanup()

# 使用示例（聚合器）：
# await boot_health_probe(8001, ready_fn=lambda: asyncio.to_thread(lambda: True))
# 使用示例（引擎）：
# await boot_health_probe(8003, ready_fn=lambda: asyncio.to_thread(lambda: True))
```

> 不想加依赖？那就略过。K8s/Compose 里也可以直接探 `Prometheus` 端口是否可达当作存活检查。
