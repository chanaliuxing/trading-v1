# 引擎侧 ClickHouse 数据访问层（DAL）规范 v1

## 1) 连接与通用设置

**连接**：优先使用 **native** 协议（性能更好），HTTP 作回退。
**推荐参数（按需调整）**：

* `max_threads=2`（单策略查询不抢线程；批量或离线再放大）
* `max_result_rows=50000`、`max_block_size=16384`
* `connect_timeout=1s`、`receive_timeout=2s`、`send_timeout=2s`
* `max_execution_time=800ms`（微周期查询硬上限）
* `compression=lz4`
* **强制 PREWHERE**（见 SQL）
* 错误处理：> 800ms 视为**慢查询**并触发**策略级退避**（把 cadence 临时拉长 5s）

> 注意：我们表 `bar_5s_v2 / bar_1m_v2` 的 ORDER BY 为 `(symbol, ts_start)`，要让 `symbol` 落在 **PREWHERE**，以走**索引跳转**。

## 2) 读接口（Python 伪代码 + SQL 模板）

### 2.1 最近 N 根 5s Bar（含连续性检测）

```python
def read_recent_bars_5s(ch, symbol: str, n: int) -> list[Bar5s]:
    sql = """
    SELECT symbol, ts_start, ts_end, open, high, low, close, vol, vwap, rth, source, calc_mode
    FROM qsys.bar_5s_v2
    PREWHERE symbol = {sym:String}
      AND ts_start >= now() - INTERVAL {win:Int32} second
    WHERE rth = 1
    ORDER BY ts_start DESC
    LIMIT {lim:Int32}
    """
    # win 取 n*5*2（给乱序冗余），lim=n*2（多取一点防缺口）
    rows = ch.query(sql, {"sym": symbol, "win": n*10, "lim": n*2})
    bars = list(reversed(rows[:n]))  # 最新在后，回调需要正序
    # 连续性（可选）：检查相邻 ts_start 差值是否为 5s；缺口交给引擎 ReadyCheck“智能跳过”
    return bars
```

### 2.2 最近 N 根 1m Bar

```sql
SELECT symbol, ts_start, ts_end, open, high, low, close, vol, vwap, rth, source, calc_mode
FROM qsys.bar_1m_v2
PREWHERE symbol = {sym:String}
  AND ts_start >= now() - INTERVAL {N:Int32} minute
WHERE rth = 1
ORDER BY ts_start DESC
LIMIT {N:Int32};
```

### 2.3 Intraday 特征（最新 + 新鲜度）

```sql
-- 拉多指标：返回最新一条并检查陈旧度
SELECT anyLast(symbol) AS symbol, anyLast(ts) AS ts,
       maxIf(value, name='atr_1m') AS atr_1m,
       maxIf(value, name='trend_slope_20') AS trend_slope_20
FROM (
  SELECT symbol, ts, name, value
  FROM qsys.feat_intraday_v2
  PREWHERE symbol = {sym:String}
    AND ts >= now() - INTERVAL 5 minute
  WHERE name IN {names:Array(String)}
  ORDER BY ts DESC
  LIMIT 200
)
GROUP BY symbol
HAVING now() - ts <= INTERVAL {stale:Int32} second;
```

> 说明：如果 `HAVING` 不通过（过旧），DAL 返回空，调度器会**跳过**本次。

### 2.4 Daily Snapshot（收市后快照）

```sql
SELECT asof_date, symbol, params_hash, precomputed, version
FROM qsys.feat_daily_snapshot_v2
PREWHERE symbol = {sym:String}
WHERE asof_date = today()
LIMIT 1;
```

### 2.5 微型应急：缺特征时的 on-the-fly microATR（代替品）

```sql
SELECT
  symbol,
  avg(high - low) / 12.0 AS micro_atr_5s   -- 简化微ATR
FROM qsys.bar_5s_v2
PREWHERE symbol = {sym:String}
  AND ts_start >= now() - INTERVAL 1 minute
WHERE rth = 1
GROUP BY symbol;
```

> 仅作**兜底**；策略不依赖它，优先走 `feat_intraday_v2`。

## 3) DAL 封装（引擎可直接调用）

```python
class ClickHouseDAL:
    def __init__(self, dsn, timeouts, logger, metrics):
        self.ch = connect_native(dsn, timeouts)
        self.log = logger; self.m = metrics

    def bars_5s(self, symbol, n):
        t0 = monotonic()
        try:
            bars = read_recent_bars_5s(self.ch, symbol, n)
            self.m.observe("ch.bars5s.latency_ms", (monotonic()-t0)*1000, tags={"sym":symbol})
            self.m.count("ch.bars5s.rows", len(bars), tags={"sym":symbol})
            return bars
        except Exception as e:
            self.m.inc("ch.error", tags={"op":"bars5s","sym":symbol,"err": type(e).__name__})
            self.log.exception("bars_5s", extra={"sym":symbol})
            raise

    def bars_1m(self, symbol, n): ...
    def features_intraday(self, symbol, names, stale=15): ...
    def snapshot_daily(self, symbol): ...
```

## 4) 预取与缓存（减少热点/尾延）

**目标**：把“策略读 CH 的随机查询”变成**可控的批量/低频**访问。

* **启动预热**：每策略每个 symbol 先拉近 **3–5 分钟**的 5s bar 和 30–60 分钟的 1m bar；
* **本地 RingCache**：`{symbol -> deque(max= N_minutes*60/5)}`，每消费一条 `md.bar.5s.v2` 就追加；
* **按需回灌**：当缓存长度 < 需求时才触发 CH 查询；
* **特征缓存**：`intraday` 读出来带 `ts`，一个 symbol **15s 内不重复查**；
* **快照缓存**：按 `symbol` 缓存当日；若缺失，DAL 会重查 CH（失败不阻断，策略跳过本次）；
* **批量查询**：多 symbol 时，DAL 每 5s 合并一次**批量 SQL**（`IN {syms}`），减少往返；
* **热点规避**：策略基本只读**最近窗口**，避免扫描全日分区；各 SQL 都用 `PREWHERE symbol` 限定，时间窗极短。

---

## 5) 降级与回退

* **CH 慢/不可达**：

  * 继续**消费 Kafka `md.bar.5s.v2`** 以保证微周期能跑（只要策略依赖的特征不强制）；
  * DAL 对 `features_intraday/snapshot` 返回空，引擎触发**智能跳过**；
  * 若超过 X 分钟仍不可达 → 控制面标红 & 可选**只许平仓**。
* **数据缺口**：

  * 引擎发现 `DATA_GAP_5S` 增多，触发 Data Service **回补任务**（我们已在数据层规范里定过 `calc_mode='backfill'`）。
* **负载过高**：

  * 观察 `ch.bars5s.latency_ms p95` 或引擎 CPU 高 → **自适应拉长 cadence**（策略级），并把批量查询间隔加大到 10s。

---

## 6) 表/存储优化建议（与现有 DDL 对齐）

* **分区**：`PARTITION BY trade_date`（已用）。
* **ORDER BY**：`(symbol, ts_start)`（已用），保证 `PREWHERE symbol & time` 高效。
* **物化视图**：5s→10s/1m（已给），**聚合字段**用 `argMin/argMax/sum` 确保 OHLC 正确。
* **TTL**：`bar_5s_v2` 设定 10–30 天 TTL（视容量）；更老数据压缩到 1m。
* **Projections（可选）**：对 `bar_5s_v2` 常用列建立投影（只在热路径收益显著时加）。
* **副本/分片**：早期单机足够；高并发后再做 2 副本、按 symbol hash 分片。

---

## 7) 监控埋点（Prometheus 名称）

* `ch.bars5s.latency_ms{sym}`（p50/p95）
* `ch.bars1m.latency_ms{sym}`
* `ch.features.latency_ms{name}`、`ch.features.stale_hits_total`
* `ch.snapshot.hit_total` / `miss_total`
* `engine.cache.bars5s.fill_ratio{sym}`（缓存命中率）
* 告警：`ch.bars5s.latency_ms_p95 > 400` 持续 5 分钟；`stale_hits_total` 突增

# 最小策略模板 + 单元测试样例（Mock）

## A) 策略模板（与我们前面的 StrategyAlgorithm 一致）

```python
class ORBPullback(StrategyAlgorithm):
    def initialize(self, ctx):
        self.syms = ["AAPL"]
        for s in self.syms:
            ctx.subscribe(s, resolutions=["5s","1m"])
        ctx.set_cadence(default_s=5)
        self.snap = {s: ctx.features_snapshot(s) for s in self.syms}

    def on_microbar(self, ctx, bars_5s):
        for bar in bars_5s:
            if bar.symbol not in self.syms: continue
            pos = ctx.position(bar.symbol)
            if pos.pos_qty != 0: continue

            hist = ctx.history(bar.symbol, resolution="5s", limit=12)
            feats = ctx.features_intraday(bar.symbol, ["atr_1m","trend_slope_20"])
            if not feats: return     # 智能跳过

            microATR = feats["atr_1m"] / 12.0
            pullback = bar.close <= min(b.low for b in hist[-6:]) + 0.5*microATR
            uptrend = feats["trend_slope_20"] > 0

            if uptrend and pullback:
                notional = bar.close * 100
                ctx.limit_order(bar.symbol, +100, bar.close, notional_hint_usd=notional, tags=["orb","5s"])
```

## B) 单元测试样例（Mock CH/Kafka/时间）

```python
def test_orb_pullback_places_one_order_once():
    # 1) Mocks
    fake_ch = FakeCH(
        bars5s={"AAPL": make_bars5s(minutes=1, uptrend=True, last_close=221.34)},
        bars1m={"AAPL": make_bars1m(minutes=30)},
        intraday={"AAPL": {"atr_1m": 1.20, "trend_slope_20": 0.005}},
        snapshot={"AAPL": {"params_hash": "abc"}}
    )
    fake_kafka = FakeKafka()
    strategy = ORBPullback()
    engine = EngineTestHarness(ch=fake_ch, kafka=fake_kafka, strategy=strategy, symbols=["AAPL"], cadence_s=5)

    # 2) 初始化 + 一次 on_microbar 触发
    engine.initialize()
    engine.tick_microbar()   # 调用一次 ReadyCheck → on_microbar

    # 3) 断言只发出一次 engine.order.request.v2
    msgs = fake_kafka.find(topic="engine.order.request.v2", key_prefix="ORB")
    assert len(msgs) == 1
    m = msgs[0]
    assert m["data"]["symbol"] == "AAPL"
    assert m["data"]["order_type"] == "LMT"
    assert m["data"]["qty"] == 100
    assert "idempotency_key" in m["metadata"]

    # 4) 再次触发（相同条件）→ 引擎幂等去重，仍然只 1 条
    engine.tick_microbar()
    msgs2 = fake_kafka.find(topic="engine.order.request.v2", key_prefix="ORB")
    assert len(msgs2) == 1
```

> 说明：`EngineTestHarness` 把 ReadyCheck 固定为 true，时间固定步进 5s；`FakeCH` 返回固定窗口；`FakeKafka` 只把 publish 入内存队列，便于断言。
