# 执行安全内核 v1：OCO + 追踪止损 + 改价节流状态机

## 0. 目标与 SLO

* **零无保护窗口**：首笔成交后 ≤1s 必挂 OCO（止损/止盈），失败即升级兜底。
* **稳定追踪**：追踪止损改价节流（频率/步长/最小增量）生效，**不抖动、不刷屏**。
* **幂等确定性**：重复事件不重复下单；取消/改价有且仅有一次生效。
* **可恢复**：重启或对账后，能复原 OCO 关系并继续追踪。

---

## 1. 事件与入参（与既有合约一致）

**输入 topic**

* `risk.decision.v2`（APPROVED 才执行）
* `exec.fill.v2`（部分/最终成交）
* `engine.control.v1`（kill-switch、flatten-only）
* `portfolio.snapshot.v2`（仓位/PnL 快照，可作为参考）

**输出 topic**

* `exec.order.status.v2`（NEW/SUBMITTED/WORKING/PARTIAL/FILLED/CANCELLED/REPLACED/REJECTED）
* `exec.fill.v2`（成交回报）
* `exec.oco.attach.v1`（内部可选：记录 OCO 附挂成功/失败）

**策略侧关键参数（来自 `engine.order.request.v2.data` 或策略配置）**

* `stop_mode`: `HARD_% | ATR_K | CHANNEL | MIXED`
* `stop_limit_offset_bps`: 止损限价相对 stop 的回撤，默认 5–20 bps
* `trail_hysteresis_bps`: 追踪更新的最小改善阈值，默认 ≥ 3–10 bps
* `trail_min_step_bps`: 每次改价的最小步长（避免微抖），默认 ≥ 3 bps
* `max_updates_per_min`: 每订单每分钟最大改价次数，默认 6
* `min_modify_secs`: 连续两次改价的最小间隔，默认 5s
* `profit_tgt_mode/px`: 是否挂止盈，及宽度（可为 ATR_K 或固定 bps/%）

## 2. 参数守门（下单与改价前的硬性校验）

**价格类**

* `limit_px/stop_px` 必遵守交易所最小价位（tick size），四舍五入到合法档位。
* `stop_px` 与最新基准（`ref = mid 或 last trade`）距离 ≥ `min_stop_bps`（如 10–20 bps）。
* `stop_limit_offset_bps` ∈ [3, 50]；若小于 3 bps 直接提升到 3，以避免“马上触发但不成”。
* 当行情剧烈（近 5s bar `high-low` > X bps）时，禁止把 stop 提得过近（长仓：`stop >= low + guard_bps`）。

**数量类**

* 子单数量 = **已成仓位数量**（partial fill 后**按比例**更新）；剩余入场挂单不计入保护数量。

**风控联动**

* 任意保护单价格/数量变更均触发**一次**风控快速判定（仅静态规则：黑名单/最大单笔限额），通过后改价；失败→保持旧价并报警。

**失败兜底**

* 守门失败或改价被拒绝：立即降级为 **Stop-MKT**（市价止损），并标记 `stop_to_market_upgrade_total+1`。

## 3. OCO 生成与维护

**首填即挂（T+≤1s）**

* 发生**首笔成交**（不论部分/全部）→ 立刻生成 OCO bracket：

  * **止损**（必备）：`STP_LMT`（或 `STP_MKT` 作为兜底）
  * **止盈**（可选）：`LMT`，价格由策略给定或 ATR_K
* OCO 子单 **qty = 当前净仓位数量**；随后每次部分成交 → **按净仓增量**同步放大/缩小 OCO qty。

**互斥规则**

* 任意一侧成交进入终态（FILLED）→ 取消另一侧及所有剩余入场挂单（同 `idempotency_key` 或同 `oco_group_id`）。
* 若止盈/止损取消失败 → **巡检协程**（3–5s）强制撤单，重试指数退避；超过重试阈值触发 **flatten-only** 升级。

**重启/对账**

* 通过 `orderRef / permId / tag(idem_key, oco_group_id)` 重建父子关系：

  * 缺失保护单 → 立即补挂（以最近水位和当前模式推导价格）
  * 发现**重复保护**（两套 OCO）→ 保留“最新”一套，撤旧；写 `reconcile_log('REPAIR_OCO')`

## 4. 追踪止损算法（统一多空，加防抖）

记号（长仓；空仓对称，取 max→min / >=→<=）

* `H_t`：开仓以来或本轮以来的**最高价**（更新于新高）
* `ATR_1m`：最新 1 分钟 ATR（取自 `feat_intraday`，无则用 microATR 兜底）
* `ref_px`：当前参照（默认 last；出现跳空可切 mid）
* `k_atr`：ATR 倍数参数（如 2.0–3.5）
* `trail_hysteresis_bps`、`trail_min_step_bps`：上面守门参数

**模式**

* `HARD_%`：`new_stop = max(old_stop, H_t * (1 - hard_pct))`
* `ATR_K`：`new_stop = max(old_stop, H_t - k_atr * ATR_1m)`
* `CHANNEL`：`new_stop = max(old_stop, LowestLow(N) + band_bps)`（N=近 N 根 5s 或 1m）
* `MIXED`（推荐）：`cand = max(HARD_%, ATR_K, CHANNEL)` 取最保守者（离市场最近的一侧）

**更新触发**

* `ref_px` 创新高（长仓）**且** `cand - old_stop ≥ max(trail_min_step, trail_hysteresis)` → 触发一次改价
* 改价频率受 `min_modify_secs` 与 `max_updates_per_min` 限制
* **止损限价**：`stop_limit = new_stop - stop_limit_offset_bps`（长仓），并按 tick size 对齐

**防追坏**

* 当 `ATR_1m` 变大（波动急升）导致 `cand` 过近，使用**两段式**：

  * 近端：`max(H_t - k1*ATR, hard%)`（k1 小）
  * 远端：若 30s 内触发 2 次未成交 → 提升到 `k2>k1`，减少频繁改价

**升级兜底**

* 连续 3 次改价被拒 / 超过 `max_updates_per_min` → 暂停追踪 30–60s 并立刻下 **Stop-MKT** 保护单（留存原 STP_LMT 作为副保护可选）
* 成交触发后，所有改价 timers 清零

## 5. 改价节流与全局配额

**单订单**

* `min_modify_secs`（默认 5s）：两次改价间隔
* `max_updates_per_min`（默认 6）：一分钟最多 6 次
* `max_total_updates`（默认 30）：订单生命周期改价总上限

**每符号/每账户**

* `per_symbol_modify_qps`（默认 2/s）
* `account_modify_burst`（默认 5 次/秒，配合 IB pacing）
* 触发配额 → 本订单进入 **RETREAT**（退避）状态，延时 `backoff=2^n * base` 后再试

## 6. 状态机（文字版）

```
INIT
  └─(risk APPROVED & parent SUBMITTED)→ LIVE_PARENT
LIVE_PARENT
  ├─(first FILL)→ OCO_ATTACHING
  └─(cancel/reject)→ TERMINAL
OCO_ATTACHING
  ├─(attach OK)→ PROTECTED
  ├─(attach FAIL & retry<N)→ OCO_ATTACHING
  └─(attach FAIL & retry≥N)→ FALLBACK_STOP_MKT → PROTECTED
PROTECTED
  ├─(partial FILL)→ PROTECTED  [resize OCO qty]
  ├─(trail trigger & pacing OK)→ TRACKING
  ├─(profit leg FILLED)→ EXITING
  ├─(stop leg FILLED)→ TERMINAL
  └─(time-stop hit)→ EXITING
TRACKING
  ├─(modify OK)→ PROTECTED
  ├─(modify REJECT & can_fix)→ PROTECTED [adjust ticks]
  └─(modify REJECT & cannot_fix)→ FALLBACK_STOP_MKT → PROTECTED
EXITING
  ├─(cancel other leg OK)→ TERMINAL
  └─(cancel fail)→ SWEEP_PENDING → TERMINAL
FALLBACK_STOP_MKT（子状态，随时可能进入）
  └─(market stop placed)→ PROTECTED
TERMINAL
  └─(release reservation; clean bookkeeping)
```

## 7. 幂等与持久化键

* **父单**：`idempotency_key`（来自引擎） → `core_order.idempotency_key` 唯一
* **OCO 组**：`oco_group_id = sha256(parent_order_id || 'oco' || ts)`

  * 子单携带 `oco_group_id` 与 `parent_order_id`
* **改价**：`replace_key = sha256(order_id || last_replace_seq)`，避免并发替换交叉
* **巡检**：表驱动（`core_order` 状态 + `core_fill`），按 `oco_group_id` 恢复一致性

---

## 8. 关键边界场景与动作

1. **部分成交后突发跳水**

* 在 `OCO_ATTACHING` 前再次收到 fill：仍走**先附挂再追踪**，若 attach 来不及 → **FALLBACK_STOP_MKT** 兜底

2. **止损 LMT 被穿不成交**

* 连续 2 根 5s bar 收盘低于 `stop_px` 且未成交 → 将该止损**提升为 Stop-MKT**，同时记录一次升级计数

3. **反向信号触发**

* 统一走 `EXITING`：先撤止盈，保留止损作为兜底；平仓后进入 `TERMINAL`

4. **IB pacing 拒绝**

* 标记 REJECT class = QUOTA → 延时退避并降频，超过阈值启用 **Stop-MKT** + `flatten-only` 提示

## 9. 指标与告警（Prom）

* `order.oco_attach_success_total / order.oco_attach_fail_total`
* `order.unprotected_window_seconds{strategy,symbol}`（必须为 0）
* `order.stop_updates_total{reason="trail|resize|repair"}`
* `order.stop_update_reject_total{class="quota|price|unknown"}`
* `order.stop_to_market_upgrade_total`（>0 告警）
* `exec.modify_rate_limited_total`（节流命中次数）
* `exec.sweep_actions_total`（巡检补救动作数）
* 告警：

  * `oco_attach_success_rate < 0.995` 连续 5 分钟
  * `unprotected_window_seconds > 0` 立即红警 + 自动 `flatten-only`
  * `stop_to_market_upgrade_total` 突增

## 10. 最小伪代码（核心路径）

**首填→OCO**

```python
async def on_fill(parent):
    st = get_state(parent)
    if st.phase in {"INIT","LIVE_PARENT"}:
        ok = await attach_oco(parent, qty=filled_qty(parent), stop=calc_initial_stop(), take=calc_take())
        if not ok:
            ok2 = await place_stop_market(parent, qty=filled_qty(parent))
            if not ok2: raise Critical("NO_PROTECTION")
    resize_oco_qty(parent, qty=current_net_pos())
```

**追踪改价（节流）**

```python
async def maybe_trail(parent):
    if not pacing_ok(parent): return
    new_stop = trail_formula(parent)  # MIXED/HARD/ATR/CHANNEL
    if not improve_enough(new_stop, old_stop, hysteresis, min_step): return
    new_stop, new_lmt = guard_and_round(new_stop, offset_bps, tick)
    ok = await replace_stop_lmt(parent, new_stop, new_lmt)
    record_update(ok)
    if not ok and reject_class in {"quota","price"}:
        backoff(parent)
        if too_many_rejects(parent):
            await upgrade_to_market(parent)
```

**巡检**

```python
async def sweep():
    for g in all_open_oco_groups():
        if missing_leg(g):  # 缺止损/止盈其一
            repair_oco(g)
        if stale_cancel(g):
            force_cancel(g)
```

## 12. 与 PG 账本/风控的衔接

* **任何 attach/replace/cancel** 成功 → 回写 `core_order` `state=REPLACED/WORKING`、`updated_at=now()`
* **终态**（FILLED/CANCELLED/REJECTED）→ 调用 `core_sp_release_on_terminal(idem_key, order_id, terminal, reason)`
* **幂等**：重复事件（同 `idempotency_key` / `replace_key`）直接认可，不二次落库
