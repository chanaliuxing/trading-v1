太好了，我们直接进入 **P7：Portfolio Service（持仓 / 资金 / PnL 权威账本）**。
这是**一次成型的实现规范**，与 P4（账户/断路器）、P5（行情/特征）、P6（执行引擎）无缝衔接；落地后你将拥有**单一真源**的仓位与资金账本，供策略查询、风控与报表。

---

# 0) 目标与退出标准

**目标**

* 用**成交流水（fills）+ 市价/中价（mark）**，递推出**权威持仓、资金、PnL、NAV**（账户级/策略级/标的级）。
* 支持**多策略独立资金池**、多币种、卖空（负仓位）、费用/分红/借券利息等现金事件。
* **Exactly-once**：fill 幂等去重，递推结果可回放/重算；重启能从快照接续。
* 提供**低延迟查询 API**给策略（`self.Portfolio`），以及 5s 粒度的 NAV/仓位时序给报表。

**P7 退出标准**

1. 实盘 1 天内，**持仓与券商快照对账误差=0 手**；
2. 策略/账户 NAV 曲线与券商对账单差额 ≤ **2‰**；
3. 回放最近 N 小时 fills 可**完全重建**同样的仓位/PNL；
4. 策略端 `self.Portfolio.Position(symbol)`、`Portfolio.Summary(strategy_id)` **p95 < 5ms**；
5. 支持**分红/费用/借券息**三种现金事件并入账。

## 1.1 PostgreSQL（权威）

```sql
-- 现金事件（佣金、费率、分红、借券息、调整）
CREATE TABLE cash_events (
  id BIGSERIAL PRIMARY KEY,
  ts TIMESTAMPTZ NOT NULL,
  account_code TEXT NOT NULL,
  strategy_id TEXT,                 -- 可空：账户级事件
  symbol TEXT,                      -- 可空：非标的相关事件
  ccy TEXT NOT NULL DEFAULT 'USD',
  kind TEXT NOT NULL,               -- COMMISSION|FEE|DIVIDEND|BORROW|ADJUST
  amount NUMERIC(20,6) NOT NULL,    -- +入金/-出金（按 ccy）
  ref TEXT,                         -- 参考单号/说明
  UNIQUE (ts, account_code, strategy_id, symbol, kind, amount)
);

-- 仓位快照（权威）——用于断点恢复（每策略、每标的）
CREATE TABLE positions_snapshot (
  id BIGSERIAL PRIMARY KEY,
  ts TIMESTAMPTZ NOT NULL,
  account_code TEXT NOT NULL,
  strategy_id TEXT NOT NULL,
  symbol TEXT NOT NULL,
  pos_qty NUMERIC(20,6) NOT NULL,
  avg_px NUMERIC(20,6),             -- WAC（加权平均成本）
  realized_pnl NUMERIC(20,6) NOT NULL,   -- 该策略该标的累计已实现
  base_ccy TEXT NOT NULL DEFAULT 'USD'
);
CREATE UNIQUE INDEX ON positions_snapshot (account_code, strategy_id, symbol);

-- 策略资金池（上限与当前使用）
CREATE TABLE strategy_pools (
  strategy_id TEXT PRIMARY KEY,
  base_cap NUMERIC(20,2) NOT NULL,          -- 初始/目标资金池
  used_cap NUMERIC(20,2) NOT NULL DEFAULT 0, -- 当前占用（由预留/仓位派生）
  updated_ts TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> 继续使用已建的 `orders / fills`（带唯一索引 `(order_id, ts, qty, price)`）以保证 **Exactly-once**。

# 2) 估值与递推公式（WAC 成本法，支持空头）

**符号约定**

* `pos_qty`：正=多，负=空；
* `avg_px`：**加权平均成本**（WAC），对空头同样适用；
* `mark`：标的当前估值价（优先 NBBO mid，其次 1s close）。

**成交入账（Fill）**

* **开/加仓（同向）**

  ```
  new_qty = pos_qty + sgn * fill_qty    # sgn=+1 买 / -1 卖
  new_avg = (pos_qty*avg_px + sgn*fill_qty*fill_px) / new_qty
  RPL += 0
  ```
* **减仓（反向且 |fill_qty| ≤ |pos_qty|）**

  ```
  close_qty = fill_qty
  pnl = (fill_px - avg_px) * sgn_prev * close_qty
  new_qty = pos_qty - sgn_prev * close_qty
  avg_px 不变
  RPL += pnl
  ```
* **反转（穿越 0）**：分两段

  1. 先把 `|pos_qty|` 作为减仓计入 RPL；
  2. 剩余作为新方向的开仓，重置 `avg_px = fill_px`。

**未实现**

```
UPL = (mark - avg_px) * pos_qty
```

**策略 NAV**

```
NAV = cash + Σ_s (pos_qty_s * mark_s)
```

**现金（cash）**

* 成交现金流：`- buy_qty*price + sell_qty*price`
* 手续费/费用：`cash += -commission - fees`（来自 fill 或 cash_events）
* 分红（多仓 +，空仓 -，依据券商结算口径）：`cash += dividend`
* 借券息/融资利息：`cash += -borrow`（每日结算，T+1 记入）

> 多币种：统一换算到 `base_ccy`（P4 的 FX 价源复用）。

# 3) 数据来源与更新顺序

**实时路径**

1. `FillEvent`（P6 输出）→ **去重**（PG 唯一索引）
2. **递推器**（Ledger）按 **(account, strategy, symbol)** 粒度更新：

   * `pos_qty / avg_px / RPL`
   * `cash`（含佣金/费用）
3. **行情 Mark**（来自 P5 `bars_1s` 或 NBBO mid）→ 计算 `UPL/NAV`
4. 每 5s 刷新一次 CH：`nav_strategy_5s`、`pos_strategy_symbol_5s`

**T+1 路径**

* 券商对账单 → 导入 `cash_events`（分红/借券/杂费）→ **回放日内**填补差额；
* 对账差异写 `ADJUST` 事件（可正可负），确保 NAV 最终对齐。

---

# 4) 策略资金池与占用

* `strategy_pools.base_cap`：初始池（可动态调度，来自 P4 动态 cap）；
* **占用口径**（实时）：

  ```
  used_cap = Σ |pos_qty_s * mark_s|  + reservations_live(strategy)
  usage_ratio = used_cap / base_cap
  ```
* 风控前门（P6）读取 `usage_ratio` 与 `available_cap` 联合做拒单。

# 6) Exactly-once、回放与快照

* **去重**：`fills` 唯一索引 `(order_id, ts, qty, price)`；重复来包直接忽略。
* **快照**：每策略×标的的最新 `positions_snapshot` 持久化；Ledger 重启先 load 快照，再从 `fills` 的**断点 offset**回放。
* **区间重算**：提供作业 `recompute(start_ts,end_ts,strategy?)`：

  * 从零基状态（或快照）+ 该区间 `fills + cash_events` 回放 → 产出 CH 全量修正（更大 `ver` 覆盖）。
* **手工调整**：写 `cash_events(kind='ADJUST')`，并记录 `ref/说明`。

---

# 7) 对账与差异处理

* **日内对账**：每小时抓一次 IBKR `positions` 与 `cash` 快照；比较**仓位数量**与**现金余额**；偏差≠0 → 记 `ADJUST` 草案，人工确认后入账。
* **日终对账**：用券商对账单（官方口径）对齐 NAV；差额入 `ADJUST` 并挂明细。
* **越权交易**（券商端手工单）：识别 `orderRef` 为空的成交，归属到 `strategy_id='manual'`，并触发告警。

---

# 8) 监控与告警

* 滞后：`portfolio_ledger_lag_s`（目标 < 1s）
* 一致性：`pos_mismatch_total`（与券商快照）→ 阈值 0；
* 资金池：`strategy_usage_ratio` > 1.0 告警；
* 回放：`recompute_jobs_running`、`recompute_fail_total`；
* 现金事件：`unreconciled_cash_events_total`（超过 T+1 未入账告警）。

# 9) 关键伪码（递推器）

```python
async def on_fill(fill):
    # 幂等：若已存在则 return
    if await fills_repo.exists(fill): return
    await fills_repo.insert(fill)

    pos = await state.load(fill.strategy_id, fill.symbol)  # {qty, avg, rpl, cash}
    sgn = +1 if fill.side=='BUY' else -1
    # 佣金/费用
    commission = fill.commission or estimate_commission(fill)
    cash_delta = -sgn * fill.qty * fill.price - commission

    if pos.qty == 0 or (pos.qty * sgn >= 0):  # 同向开/加仓
        new_qty = pos.qty + sgn*fill.qty
        new_avg = ((pos.qty*pos.avg) + (sgn*fill.qty*fill.price)) / new_qty
        pos.qty, pos.avg = new_qty, new_avg
    else:
        # 减仓/反转
        close_qty = min(abs(fill.qty), abs(pos.qty))
        pnl_close = (fill.price - pos.avg) * (1 if pos.qty>0 else -1) * close_qty
        pos.rpl += pnl_close
        pos.qty += sgn*close_qty
        if sgn*fill.qty != sgn*close_qty:   # 反转剩余部分
            open_qty = abs(fill.qty) - close_qty
            pos.avg = fill.price
            pos.qty += sgn*open_qty

    pos.cash += cash_delta
    await state.save(fill.strategy_id, fill.symbol, pos)
```

> **标记/估值**：独立小协程每 1s 拉 `mark_px`，更新 `UPL/NAV` 并批量写 CH（5s）。

# 10) 演练 / 验收（60 分钟）

1. **穿越 0 反转**：多→空，检验 RPL 先结转、avg_px 重置。
2. **部分成交序列**：多次 partial → WAC 正确、UPL 单调合理。
3. **佣金/费用**：开启真实佣金 → cash 持续下降且 NAV=现金+市值 恒等。
4. **分红/借券息**：导入 cash_events 两条 → NAV 与现金同步变化，策略/账户两级都正确。
5. **对账**：与 IBKR positions/cash 对比=0；与对账单 NAV 差额 ≤ 2‰。
6. **重启恢复**：杀 Ledger → 恢复后仓位/PNL 连续无跳变。
7. **回放重算**：选 2 小时窗口重算 → 与在线曲线一致（ver 覆盖）。

# 11) 与其他阶段的接口

* **P6 执行**：`FillEvent` → Ledger；`Reservation.release` 由执行侧在终态调用，资金占用由本服务汇总到 `strategy_pools.used_cap`。
* **P4 断路器**：基于 `NAV_dd_day` 与 `reject_rate` 驱动；本服务提供 NAV 与 UPL/RPL 基础指标。
* **P5 行情**：`mark_px` 来自 `bars_1s.mid/close`（优先 mid）。
* **DSL 策略**：`self.Portfolio` 只读、低延迟；禁止策略直接改账本。
