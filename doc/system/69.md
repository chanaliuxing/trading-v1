# 一、目标与边界

**目标**

* 把 **IBKR 账户快照**（净值、可用资金、保证金、购买力）接入为**权威资金来源**；
* 将 **available_cap** 融入 **Pre-Trade Gate + Reservation**，保证**任何时刻不超杠杆**；
* 引入 **Global Breaker 全局断路器**（多级），在异常市况/系统状态不稳时**一键拉闸**，并带冷却期与审计；
* 与已上线的 **策略资金池 / 动态 cap / 账本 / OCO 看门狗**无缝联动。

**不变约束**

* 账户层**硬护栏优先级最高**（高于策略层 cap）；
* 资金预留 **下单即预留、终态即释放**；
* Breaker **禁止强平**（默认“只减不增”），除非达到最高级别红牌且人工确认。

# 二、数据字典（IBKR → 标准化字段）

> 每 5 秒取一份；若多币种账户，全部**转换为基准货币（BaseCCY，默认 USD）**。

| 字段                   | 含义       | 来源（示例）            | 备注                      |
| -------------------- | -------- | ----------------- | ----------------------- |
| `account_code`       | 账户号      | IBKR API          | 必填                      |
| `ts_broker`          | 券商侧时间    | IBKR API          | 毫秒/微秒对齐                 |
| `ts_recv`            | 我方接收时间   | 采集器               | `now()`                 |
| `base_ccy`           | 基准货币     | 配置                | USD                     |
| `net_liquidation`    | 资产净值     | `NetLiquidation`  | BaseCCY                 |
| `available_funds`    | 可用资金     | `AvailableFunds`  | BaseCCY                 |
| `excess_liquidity`   | 超额流动性    | `ExcessLiquidity` | BaseCCY                 |
| `init_margin`        | 初始保证金占用  | `InitMarginReq`   | BaseCCY                 |
| `maint_margin`       | 维持保证金占用  | `MaintMarginReq`  | BaseCCY                 |
| `buying_power`       | 购买力      | `BuyingPower`     | 股票典型≈4×RegT             |
| `currency_breakdown` | 各币种明细    | IBKR              | JSON：{ccy: {nl, af, …}} |
| `risk_flags`         | 券商风险标志   | IBKR              | 如 PDT/日内/SSRs           |
| `fx_rates`           | FX 速率    | 自家/IBKR           | {EURUSD:1.08,…}         |
| `pull_ok`            | 本次拉取是否成功 | 采集器               | bool                    |
| `errors`             | 错误码      | 采集器               | 重试/退避依据                 |

**标准化可用资金（账户级）**

```
available_cap_raw = min(
    buying_power * broker_safety_mult,
    net_liquidation - init_margin
)
available_cap = max(0, available_cap_raw) - reservations_live - buffer_cost
```

* `broker_safety_mult` 建议 0.9–0.95（抗口径偏差）
* `buffer_cost` = `预估佣金+滑点缓冲`（如 10–20bp × 拟下单名义）

```sql
CREATE TABLE account_snapshots (

  buying_power     NUMERIC(20,4) NOT NULL,

  fx_rates          JSONB,
  pull_ok      BOOLEAN NOT NULL,
  errors       TEXT

```

**breaker_log（断路器变更审计）**

```sql
CREATE TABLE breaker_log (
  id BIGSERIAL PRIMARY KEY,
  ts        TIMESTAMPTZ NOT NULL DEFAULT now(),
  scope     TEXT NOT NULL,                    -- ACCOUNT / STRATEGY / SYMBOL
  account_code TEXT,
  strategy_id  TEXT,
  symbol       TEXT,
  level     INT NOT NULL,                     -- 0=OFF,1=黄,2=橙,3=红
```


# 四、AccountStateMonitor（采集器伪码）

```python
# -*- coding: utf-8 -*-
import asyncio, time, random

SAFETY = 0.92   # broker_safety_mult
JITTER = (0.4, 1.2)  # 5s 基础 + 抖动

class AccountStateMonitor:
    def __init__(self, ib, pg, ch, statebus, ledger, logger, metrics, base_ccy="USD"):
        self.ib = ib
        self.pg = pg
        self.ch = ch
        self.sb = statebus
        self.ledger = ledger   # Reservation 汇总
        self.log = logger
        self.m = metrics
        self.base = base_ccy
        self.fail_streak = 0

    async def loop(self):
        while True:
            t0 = time.time()
            try:
                snap = await self.pull_snapshot()
                await self.persist(snap)
                await self.broadcast(snap)
                self.fail_streak = 0
                self.m.account_pull_ok.inc()
            except Exception as e:
                self.fail_streak += 1
                self.log.exception(f"[acct] pull error: {e}")
                self.m.account_pull_err.inc()
                if self.fail_streak >= 3:
                    # 进入“只减不增”
                    await self.sb.publish("GLOBAL_RULES", {
                        "kind": "PAUSE_NEW_ORDERS",
                        "level": 1,
                        "reason": "account_pull_fail",
                        "until_s": int(time.time() + 5*60)
                    })
            # 5s + 抖动
            await asyncio.sleep(max(0, 5 - (time.time()-t0)) + random.uniform(*JITTER))

    async def pull_snapshot(self):
        raw = await self.ib.get_account_values()    # 多币种字段
        fx = await self.ib.get_fx_rates(self.base)  # e.g. {'EURUSD':1.08, 'USDJPY':147.1}
        ts_broker = raw["timestamp"]
        conv = lambda ccy, v: float(v) if ccy==self.base else float(v) * fx[f"{ccy}{self.base}"]

        # 汇总为 base_ccy
        nl = conv(raw["currency"], raw["NetLiquidation"])
        af = conv(raw["currency"], raw["AvailableFunds"])
        el = conv(raw["currency"], raw["ExcessLiquidity"])
        im = conv(raw["currency"], raw["InitMarginReq"])
        mm = conv(raw["currency"], raw["MaintMarginReq"])
        bp = conv(raw["currency"], raw["BuyingPower"])

        reservations_live = await self.ledger.total_reserved()  # USD
        available_cap_raw = min(bp * SAFETY, nl - im)
        available_cap = max(0.0, available_cap_raw) - reservations_live

        snap = {
            "ts_broker": ts_broker,
            "ts_recv": time.time(),
            "account_code": raw["AccountCode"],
            "base_ccy": self.base,
            "net_liquidation": nl,
            "available_funds": af,
            "excess_liquidity": el,
            "init_margin": im,
            "maint_margin": mm,
            "buying_power": bp,
            "reservations_live": reservations_live,
            "available_cap": available_cap,
            "pull_ok": True,
            "fx_rates": fx
        }
        return snap

    async def persist(self, s):
        # PG 权威 + CH 报表
        await self.pg.insert("account_snapshots", s)
        s_ch = {**s, "ver": int(time.time()*1000)}
        await self.ch.insert("account_snapshots_ch", s_ch)

    async def broadcast(self, s):
        await self.sb.publish("ACCOUNT_SNAPSHOT", {
            "account_code": s["account_code"],
            "ts": int(s["ts_recv"]*1000),
            "available_cap": s["available_cap"],
            "net_liquidation": s["net_liquidation"],
            "init_margin": s["init_margin"],
            "buying_power": s["buying_power"]
        })
```

# 五、StateBus 协议（频道与载荷）

**频道**

* `ACCOUNT_SNAPSHOT`（5s 广播）：最新账户可用资金关键字段；
* `GLOBAL_RULES`：断路器/系统级规则调整（带 TTL）；
* `BREAKER_EVENTS`：断路器变更审计事件（和 PG `breaker_log` 对齐）。

**示例载荷**

```json
// ACCOUNT_SNAPSHOT
{
  "account_code": "U12345",
  "ts": 1735862400123,
  "available_cap": 125000.0,
  "net_liquidation": 320000.0,
  "init_margin": 180000.0,
  "buying_power": 500000.0
}
// GLOBAL_RULES
{
  "kind": "BREAKER_SET",
  "scope": "ACCOUNT:U12345",
  "level": 2,                            // 0/1/2/3
  "reason": "dd_day>1%",
  "details": {"dd_day": 0.0123, "threshold": 0.01},
  "until_s": 1735866000,                 // 可选（冷却到期）
  "actor": "auto"
}
```

**组件遵守**

* 策略端：收到 `level>=1` → **不发新开仓意图**（`open_intents=0`），允许减仓与保护；
* 执行端：拒绝非减仓与非保护类订单（返回 `REJECT{breaker}`）；
* 风控端：`approve_and_reserve` 前判断 breaker & account cap。

# 六、Pre-Trade Gate 接线（风控前门）

> 将账户可用资金与 breaker 融入现有 `approve_and_reserve(order_req)`。

```python
async def approve_and_reserve(order_req):
    # 1) Breaker
    br = await breaker.current()   # 读 breaker_state（PG/StateBus 缓存）
    if br.level >= 1 and order_req.kind in ("OPEN","INCREASE"):
        return REJECT("breaker_level", br.level, br.reason)

    # 2) 账户可用资金
    acct = await account_cache.latest()    # 由 AccountStateMonitor 更新
    needed = abs(order_req.qty * order_req.limit_px) * (1 + buffer_bp(order_req.symbol))
    if needed > acct.available_cap:
        return REJECT("insufficient_account_cap", needed, acct.available_cap)

    # 3) 策略/标的 cap（已做动态 cap）
    if not risk_caps.within_caps(order_req):
        return REJECT("strategy_or_symbol_cap")

    # 4) 预留（成功才允许提交下游）
    ok = await ledger.reserve(order_req.strategy_id, order_req.symbol, needed, order_req.decision_id)
    if not ok:
        return REJECT("reserve_failed")

    return APPROVED(reservation=needed)
```

# 七、Global Breaker（分级规则与动作矩阵）

**等级与动作**

* `L1 黄`：**禁止新开**，允许减仓/保护/撤单；
* `L2 橙`：对选定策略集合发 **KillSwitch**（撤在挂/平仓/释放/暂停），账户层仍允许其他策略只减不增；
* `L3 红`：账户级 **KillSwitch**，全部暂停，进入冷却 60–120 分钟，需人工确认恢复。

**触发规则（PromQL 建议）**

```promql
# 回撤
max_over_time(rolling_nav_dd_day[3m]) > 0.01
# 拒单率
sum(rate(exec_order_rejected_total[5m])) / sum(rate(exec_order_submitted_total[5m])) > 0.02
# 数据滞后
max(bar_publisher_lag_ms) > 3000 or max(features_publish_lag_ms) > 3000
# 账户可用资金逼近预留
(account_available_cap < reservations_live * 1.2)
# 券商断连
increase(ibgw_disconnects_total[3m]) >= 1
```

**断路器控制器（轮询或告警订阅）**

* 规则命中 → 写 `breaker_state` 与 `breaker_log`，同时在 `GLOBAL_RULES` 推送；
* 冷却期计时：`until_ts` 未到禁止上调等级（仅可降级/解除）；
* 手工干预：`scope=ACCOUNT/STRATEGY/SYMBOL` 支持 CLI/API 一键设置/解除。

* `breaker_level=3` → **短信/电话**（高优先）

# 九、事故演练（30–45 分钟）

1. **IBGW 断连**：停 IBGW 2 分钟 → 采集器失败≥3 → `PAUSE_NEW_ORDERS`；新单被拒；恢复后 5 分钟才解封。
2. **保证金飙升**：Mock `init_margin` +50% → `available_cap` < `reservations_live*1.2` → 断路器 L3 红；执行 KillSwitch。
3. **回撤过线**：写入测试 NAV 导致 `DD_day=1.2%` → 断路器 L2 橙 + 动态 cap 自动降档；冷却期内不升档。
4. **拒单率过线**：执行器拒单率>2%（人为制造几次错误订单）→ 断路器 L1 黄，禁止新开。

**验收口径**

* 新开单拒绝路径**总在风控前门**；
* 断路器变更均有 **breaker_log** 审计行；
* KillSwitch 后：**在挂=0，净仓=0，预留=0**（资金看门狗通过）。

# 十、边角与风险提示

* **多币种/FX**：必须**统一到 BaseCCY**，FX 价来自可靠源；FX 波动剧烈时（如 USDJPY 闪崩）会影响 available_cap → 可加 `fx_safety_mult`。
* **券商口径差**：不同账户可能 `BuyingPower` 定义不同（RegT vs Portfolio Margin），优先取 **`min(BP×mult, NL-IM)`** 的保守口径。
* **短融/借券**：若做空需 locate，账户侧限制不允许裸空（此逻辑应在 Pre-Trade Gate 的合规模块已实现）。
* **时间漂移**：采集器、策略机、执行机 **NTP 健康**必须在 50ms 内（超限进 L1）。
* **幂等与回放**：PG/CH 写入使用 `ver` 与时间序列；断路器状态以 `breaker_state` 为真源。

# 十一、发布与回滚

**金丝雀**

* 单账户/单策略开启 P4，`broker_safety_mult=0.9`，断路器规则阈值**略宽**；

**回滚**

* Breaker 置 `level=0`；
* 关掉 Pre-Trade Gate 中的账户可用资金检查（保留策略 cap 与 Reservation）——仅限紧急退回，事后务必恢复。
