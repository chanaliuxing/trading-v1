好，**第 5 步：多策略仲裁（Arbitration）+ 每策略/每标的资金硬约束**。
目标：**同一标的同一时刻只做一个方向**（避免互踩）；**同向可共存但不超总上限**；每策略**独立资金池上限**硬执行；并给出**可观测**的结果。下面是可直接粘贴的配置与代码骨架（不生成文件）。

---

## A) 配置增量（`config.yml`）

```yaml
arbiter:
  enabled: true
  policy: "priority_then_marginal"   # 先按策略优先级，再看净边际收益
  preempt: "never"                   # 新信号是否“抢占”正在执行的计划：never | price_better | always
  coexist_same_side: true            # 同方向是否允许多策略共存
  ttl_ms: 1500                       # 仲裁授予的临时名额超时（未进入风控/下单将回收）
  symbol_cap:                        # 每标的“全局”硬约束（防过度集中/冲击）
    max_notional_usd: 500000         # 同一标的总名义上限
    max_participation: 0.20          # 最多吃 20%（需要有 ADV/盘口估算时生效）
  strategy_priority:                 # 数值越大优先级越高（示例）
    meanrev_v2: 80
    breakout_v1: 70
    twap_alpha: 50
  scoring:                           # 净边际收益估分权重
    w_edge: 1.0
    w_cost: 1.0
    penalty_bp: 0.0                  # 可按回撤/行业集中度加惩罚（留空为 0）
```

> 说明：**每策略资金池上限**已经在我们第 3 步的 Reservation Ledger 落地。此处新增**每标的总上限**与**仲裁策略**。

## B) 数据结构（仲裁候选 & 活动集）

```python
from dataclasses import dataclass, field
from typing import Optional, Dict, List
import asyncio, time

def now_ms(): return int(time.time()*1000)

@dataclass
class ArbCandidate:
    decision_id: str
    strategy_id: str
    symbol: str
    dir: int                      # +1 多，-1 空
    target_qty: float
    exp_edge_bp: float            # 期望收益（bp），可由 signal_score*100 或模型直接给
    cost_bp: float                # 预估成本（滑点+费用+冲击 bp）
    priority: int
    ttl_ms: int
    ts_ms: int = field(default_factory=now_ms)

@dataclass
class ActiveSymbol:
    symbol: str
    dir: int                      # 当前活动方向（+1/-1）
    total_qty: float              # 同向合计量
    winners: Dict[str, float]     # strategy_id -> 批给的 qty
    ts_ms: int
    lock: asyncio.Lock = field(default_factory=asyncio.Lock)
```

## C) 仲裁引擎（同向共存 / 反向冲突择优 / 按上限裁剪）

```python
class ArbitrationEngine:
    def __init__(self, cfg, reserve_ledger, adv_provider, logger, metrics):
        self.cfg = cfg
        self.ledger = reserve_ledger        # 第3步的 ReserveLedger，用于看已占名义 & 释放
        self.adv = adv_provider             # 提供 ADV/盘口用于 participation（可为空）
        self.log = logger; self.m = metrics
        self._actives: Dict[str, ActiveSymbol] = {}
        self._locks: Dict[str, asyncio.Lock] = {}

    def _lock(self, sym): 
        if sym not in self._locks: self._locks[sym] = asyncio.Lock()
        return self._locks[sym]

    def _score(self, c: ArbCandidate) -> float:
        s = self.cfg["arbiter"]["scoring"]
        return s["w_edge"]*c.exp_edge_bp - s["w_cost"]*c.cost_bp - float(s.get("penalty_bp",0.0))

    async def _symbol_remaining_notional(self, symbol: str) -> float:
        cap = float(self.cfg["arbiter"]["symbol_cap"]["max_notional_usd"])
        snap = await self.ledger.snapshot()  # used/items
        # 估算该 symbol 已占名义（从 reservation.items 汇总）
        used = 0.0
        for r in snap["items"].values():
            if r["symbol"] == symbol:
                used += r["amount_remaining"]
        return max(0.0, cap - used)

    async def _participation_ok(self, symbol: str, add_notional: float) -> bool:
        cap_part = float(self.cfg["arbiter"]["symbol_cap"]["max_participation"])
        if cap_part <= 0: return True
        if not self.adv: return True
        adv = await self.adv.adv_usd(symbol)  # 没有可返回 None
        if not adv: return True
        return (add_notional/adv) <= cap_part + 1e-9

    async def admit(self, env) -> (bool, Optional[float], Dict):
        """
        输入：DecisionEnvelope（我们前面已定义）
        输出：(允许?, 建议的target_qty裁剪, reason/meta)
        注意：不修改 env，仅返回建议的 qty（调用方可重建一个裁剪后的 env）
        """
        sym = env.symbol
        dir_ = 1 if env.target_qty>0 else -1
        pri = int(self.cfg["arbiter"]["strategy_priority"].get(env.strategy_id, 50))
        edge_bp = float(env.extras.get("edge_bp", env.signal_score*100.0))
        cost_bp = float(env.cost_estimates.slippage_bp + env.cost_estimates.fees_bp + env.cost_estimates.impact_bp)
        cand = ArbCandidate(
            decision_id=env.decision_id, strategy_id=env.strategy_id, symbol=sym,
            dir=dir_, target_qty=abs(env.target_qty), exp_edge_bp=edge_bp, cost_bp=cost_bp,
            priority=pri, ttl_ms=int(self.cfg["arbiter"]["ttl_ms"])
        )
        async with self._lock(sym):
            active = self._actives.get(sym)
            # 1) 无活动：直接授予（按符号上限裁剪）
            if not active:
                allow_qty, meta = await self._clip_by_symbol_cap(env, cand)
                if allow_qty <= 0:
                    return False, None, {"reason":"symbol_cap_exhausted"}
                self._actives[sym] = ActiveSymbol(
                    symbol=sym, dir=dir_, total_qty=allow_qty, winners={env.strategy_id: allow_qty}, ts_ms=now_ms()
                )
                self.m.arb_wins_total.labels(reason="first").inc()
                return True, allow_qty, {"reason":"first"}
            # 2) 有活动且同向
            if active.dir == dir_ and self.cfg["arbiter"]["coexist_same_side"]:
                allow_qty, meta = await self._clip_by_symbol_cap(env, cand)
                if allow_qty <= 0:
                    return False, None, {"reason":"symbol_cap_exhausted"}
                # 叠加
                active.total_qty += allow_qty
                active.winners[env.strategy_id] = active.winners.get(env.strategy_id, 0.0) + allow_qty
                active.ts_ms = now_ms()
                self.m.arb_wins_total.labels(reason="coexist").inc()
                return True, allow_qty, {"reason":"coexist", **meta}
            # 3) 方向冲突：择优
            # 当前胜者（合并得分/按优先级）的“代表”是谁？我们定义代表为当前 winners 中优先级最高者
            cur_rep, cur_pri, cur_score = None, -1, -1e9
            for sid, qty in active.winners.items():
                p = int(self.cfg["arbiter"]["strategy_priority"].get(sid, 50))
                if p > cur_pri:
                    cur_rep = sid; cur_pri = p
            cur_score = cur_pri  # 代表解：优先级为主
            new_score = cand.priority if self.cfg["arbiter"]["policy"]=="priority_then_marginal" else self._score(cand)

            # 决策：是否允许“抢占”？
            preempt = self.cfg["arbiter"]["preempt"]
            should_preempt = (new_score > cur_score) and (preempt in ("always","price_better"))
            if should_preempt:
                # 安全起见：此处只“拒绝”现有以外的新意图上路；真正的抢占/撤单由上层 orchestrator 触发
                # 这里返回 False + reason=preempt_request，让上层执行“原子反手编舞”
                self.m.arb_preempt_suggest_total.inc()
                return False, None, {"reason":"preempt_request", "target": cur_rep}
            # 默认：不抢占 → 拒绝新意图
            self.m.arb_reject_total.labels(reason="conflict").inc()
            return False, None, {"reason":"conflict_with_active", "holder": cur_rep}

    async def _clip_by_symbol_cap(self, env, cand: ArbCandidate):
        """把请求裁剪到每标的名义上限/参与率上限内"""
        remaining = await self._symbol_remaining_notional(cand.symbol)
        ref_px = env.extras.get("ref_px") or None
        # 若无引用价，用 MarketState mid/last；这里保守留空由调用方保证
        # 估算此次名义：min(max_notional, target_qty*ref_px)
        ask_ref = ref_px if ref_px else None
        if not ask_ref:
            # 调用方应在 Translator/RiskService 提供 ref_px；这里兜底
            ask_ref = 0.0
        req_notional = cand.target_qty * ask_ref
        if remaining <= 1e-6 or req_notional <= 0:
            return 0.0, {"remaining": remaining}
        allow_notional = min(remaining, float(env.max_notional))
        # participation 约束（若提供了 ADV）
        if not await self._participation_ok(cand.symbol, allow_notional):
            return 0.0, {"remaining": remaining, "reason":"participation_cap"}
        # 反推允许的 qty
        allow_qty = cand.target_qty if ask_ref<=0 else min(cand.target_qty, allow_notional/max(ask_ref,1e-9))
        return max(0.0, allow_qty), {"remaining": remaining}

    async def finalize(self, env, status: str):
        """
        调用时机：
          - 通过风控并成功提交/拒绝/过期，都应通知仲裁器释放“临时名额”
        """
        sym = env.symbol
        async with self._lock(sym):
            active = self._actives.get(sym)
            if not active: return
            if env.strategy_id in active.winners:
                q = active.winners.pop(env.strategy_id)
                active.total_qty = max(0.0, active.total_qty - q)
                if not active.winners:
                    self._actives.pop(sym, None)
            # 统计
            self.m.arb_finalize_total.labels(status=status).inc()
```

## D) 策略引擎中的接线（批准链前）

> 把我们前几步里的占位 `arbiter.admit(env)` 换成下面的调用方式，并**按裁剪后的 qty** 重建一个新的 Envelope（或在 Translator 前直接修改 `env.target_qty`）。

```python
ok, allow_qty, meta = await arbiter.admit(env)
if not ok:
    audit.log(decision_id=env.decision_id, status="DEFER", reasons=[meta.get("reason","arbiter_reject")], extras=meta)
    return

# 如需要，裁剪 target_qty（保持方向不变）
if abs(allow_qty - abs(env.target_qty)) > 1e-9:
    env = DecisionEnvelope(
        **{**env.__dict__, "target_qty": allow_qty if env.target_qty>0 else -allow_qty}
    )
```

**在任何一个“落幕”出口**（风控拒/过期/下单失败/提交成功）调用：

```python
await arbiter.finalize(env, status="reject"|"expired"|"submitted")
```

> 注意：**submitted** 只是“进入执行”；真正的名义硬约束已由 **ReserveLedger** 执行（预留→部分成交收缩→终态释放），与仲裁器互不冲突。

## E) 与 Reservation（第 3 步）的协作

* 仲裁器只是**路闸**，不占用资金；**真正的硬约束**在 `RiskService.approve()` 调用 `ReserveLedger.reserve()` 时执行。
* 仲裁器防止**同标的相反策略同时上路**；ReserveLedger防止**同策略资金池越界**与**全局 symbol_cap 越界**（你也可把 symbol_cap 的检查放在 `ReserveLedger` 里一并执行）。

## G) 自测/回放小剧本（10 分钟）

1. **同标的相反方向**

   * A（优先级 80）多 100，B（优先级 50）空 200 → B 被 `reason=conflict_with_active` 拒。
2. **同向共存 + 裁剪**

   * A 多 300，B 多 400，symbol_cap=500@$100 → 第二笔裁剪到 200，`reason=coexist`；两者合计不超过 500。
3. **抢占建议**（将 `preempt=price_better/always`）

   * 先上低优先级；随后高优先级到达 → 返回 `reason=preempt_request`；上层 orchestrator 执行“原子反手编舞”。
4. **TTL 过期**

   * 仲裁通过后不进入风控/下单，超过 `ttl_ms` → 在调用方触发 `finalize(env,"expired")`（或你也可在仲裁器内部定时清理）。
5. **与预留联动**

   * 仲裁通过→风控预留失败（cap_exceeded）→ `finalize(...,"reject")`；名额释放。

## H) 落地建议与常见坑

* **ref_px**：仲裁裁剪需要一个参考价（mid/last）；请在 Envelope 的 `extras.ref_px` 里带上，或在 Translator 前补齐。
* **参与率**：若暂无 ADV/盘口提供器，先将 `max_participation` 设为 0 或忽略；上线前再补齐。
* **抢占策略**：生产初期推荐 `preempt=never`，避免“反手风暴”。成熟后可升级为 `price_better`（仅当新意图价格/得分显著更优时才抢占）。
* **一致性**：任何出口都要 `finalize()`，避免“名额泄漏”。
* **与风控顺序**：强烈建议**先仲裁，再风控**（Reg-Lite/Reserve），减少无效计算与占用。

### 一句话总结

* 这一步让系统在**多策略并行**时始终保持**同标的方向一致**、**同向不越界**、**策略池独立**；
* 仲裁只是“闸门”，真正的资金硬约束仍由 **ReserveLedger** 执行；
* 全流程**可观测、可回滚**，为小流量生产扫清“互踩”与“超限”的两大风险。

如果确认无误，我们继续 **第 6 步：决策新鲜度 SLO（bar→intent p95≤800ms）实装 & 过期作废（TTL）**，把第 1 步里设计的 **Freshness/TTL** 真正接进你的调度器和执行器，并给出**延迟分布指标**与**过期拒单**的接线。
