下面给你一套“**可直接跑的参数校准方案**”：目标是把**开收盘限速**和**盘口熔断（spread/imbalance）**定到“既安全又不过度拦”的区间；方法完全基于你现有表（`lake.bbo_1s_features`, `lake.quotes_l1`, `trading.signals_1m`, `trading.fills`, `monitor.risk_guard_events`），不改代码，只跑 SQL/脚本就能得到建议值。

---

# 校准目标（先定指标，后定阈值）

1. **风控拦截率**（RTH 内）：5%–20% 的分钟被拦（视标的流动性分层）。
2. **开收盘限速影响**：开盘前 5 分钟、收盘前 5 分钟，下单量≤全天的 10%–15%。
3. **拦截收益性**：被拦分钟的**后 1 分钟滑点/不利变动**显著高于放行分钟（≥1σ）。
4. **交易覆盖率**：启用风控后，成交笔数/名义额下滑幅度 **≤30%**（先安全后效率）。

> 有了这四条，你就知道“拦得够不够、亏钱分钟拦到了没、整体交易节律有没有被过度压制”。

# A. 盘口熔断阈值（spread_bps_max / imbalance_abs_max）

## A1) 先看分布（最近 10 个交易日，RTH）

```sql
-- 每只票近10日的1s spread分布（RTH）
WITH rth AS (
  SELECT *
  FROM lake.bbo_1s_features
  WHERE ts >= today() - 14 AND toTimezone(ts, 'America/New_York') BETWEEN toDateTime(concat(toDate(toTimezone(ts,'America/New_York')),' 09:30:00'),'America/New_York')
                                                                      AND toDateTime(concat(toDate(toTimezone(ts,'America/New_York')),' 16:00:00'),'America/New_York')
)
SELECT symbol,
       quantileExact(0.90)(spread_bps) AS p90,
       quantileExact(0.95)(spread_bps) AS p95,
       quantileExact(0.99)(spread_bps) AS p99,
       quantileExact(0.95)(abs(imbalance)) AS imb_p95
FROM rth
GROUP BY symbol
ORDER BY p95 DESC
LIMIT 50;
```

**解读与初值：**

* 大票（AAPL/MSFT/AMZN/NVDA/TSLA）在 RTH 的 `p95` 常在 **2–6 bps**；
* 建议：

  * `spread_bps_max = min( max(5, median(p95_by_symbol) + 1), 10 )`；
  * `imbalance_abs_max` 从 `max(0.55, median(imb_p95_by_symbol))` 起步（通常 **0.55–0.65**）。

## A2) 看“30s P95”的代理（与在线规则一致）

```sql
-- 以分钟对齐，窗口=30s，近10日
WITH base AS (
  SELECT symbol,
         toStartOfMinute(ts) AS m,
         quantileExact(0.95)(spread_bps) AS p95_30s,
         anyLast(imbalance) AS last_imb
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
  GROUP BY symbol, m
)
SELECT symbol,
       quantileExact(0.95)(p95_30s) AS p95_of_p95,
       quantileExact(0.99)(p95_30s) AS p99_of_p95,
       quantileExact(0.95)(abs(last_imb)) AS imb95
FROM base
GROUP BY symbol
ORDER BY p95_of_p95 DESC
LIMIT 50;
```

**建议**：用 `p95_of_p95` 做**更保守**的参考。如果你担心开盘噪声，把 `spread_bps_max` 初值定为 **`min(8, p95_of_p95 + 1)`**。

## A3) 评估拦截率（模拟熔断覆盖度）

```sql
-- 在“分钟粒度”上模拟：p95_30s>阈值 或 |imb|>阈值 的分钟占比
WITH s AS (
  SELECT symbol, toStartOfMinute(ts) AS m,
         quantileExact(0.95)(spread_bps) AS p95_30s,
         anyLast(imbalance) AS last_imb
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
  GROUP BY symbol, m
)
SELECT
  symbol,
  avg(p95_30s > {spread_bps_max:Float64}) AS block_by_spread_rate,
  avg(abs(last_imb) > {imb_abs_max:Float64}) AS block_by_imb_rate,
  avg( (p95_30s > {spread_bps_max:Float64}) OR (abs(last_imb) > {imb_abs_max:Float64}) ) AS block_any_rate
FROM s
GROUP BY symbol
ORDER BY block_any_rate DESC
LIMIT 50;
```

把 `{spread_bps_max}` / `{imb_abs_max}` 换成候选值（例如 6 / 0.6）。目标：**block_any_rate ≈ 0.05–0.20**。

## A4) 评估“被拦分钟是否更差”（后一分钟不利变动）

```sql
-- 用 bars_1m，比较被拦分钟的“下一分钟回报”分布
WITH micro AS (
  SELECT symbol, toStartOfMinute(ts) AS m,
         quantileExact(0.95)(spread_bps) AS p95_30s,
         anyLast(imbalance) AS last_imb
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
  GROUP BY symbol, m
),
bars AS (
  SELECT symbol, ts_start AS m, close, lead(close) OVER (PARTITION BY symbol ORDER BY ts_start) AS next_close
  FROM trading.bars_1m_current
  WHERE d >= today()-14
)
SELECT
  b.symbol,
  avgIf( (next_close - close)/close, (m.p95_30s > {spread} OR abs(m.last_imb)>{imb}) )   AS ret_next_blocked,
  avgIf( (next_close - close)/close, (m.p95_30s <= {spread} AND abs(m.last_imb)<={imb}) ) AS ret_next_allowed,
  countIf( (m.p95_30s > {spread} OR abs(m.last_imb)>{imb}) ) AS blocked_mins,
  count() AS total_mins
FROM bars b
LEFT JOIN micro m USING(symbol, m)
GROUP BY b.symbol
ORDER BY blocked_mins DESC
LIMIT 50;
```

**期望**：`ret_next_blocked < ret_next_allowed`（对做多策略而言）。如果不显著，就把阈值放宽（少拦）。

# B. 动态阈值 `alpha_per_bps`（自动抬升 `threshold` 的斜率）

目标：**高 spread 的分钟少下单**，但**总体放行率**不低于目标（比如 70%）。用 CH 做个“小网格”：

```sql
-- 计算每条信号对应的 30s P95 spread，并在 SQL 中对一组 alpha 网格模拟“是否放行”
WITH feat AS (
  SELECT symbol, toStartOfMinute(ts) AS m,
         quantileExact(0.95)(spread_bps) AS p95_30s
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
  GROUP BY symbol, m
),
sig AS (
  SELECT symbol, ts AS m, prob
  FROM trading.signals_1m
  WHERE d >= today()-14
),
grid AS (
  SELECT arrayJoin([0.004,0.006,0.008,0.010,0.012]) AS alpha
)
SELECT
  s.symbol, g.alpha,
  avg( s.prob >= ( {base_thr:Float64} + g.alpha * greatest(f.p95_30s,0) ) ) AS pass_rate
FROM sig s
LEFT JOIN feat f USING(symbol, m)
CROSS JOIN grid g
GROUP BY s.symbol, g.alpha
ORDER BY s.symbol, g.alpha;
```

* 把 `{base_thr}` 设为你配置里的基础阈值（比如 0.55）。
* 选择使 `pass_rate` 贴近你的目标（比如 0.70–0.85）的 `alpha`；
* 如果某些票 `pass_rate` 掉得太狠，可以给它们单独的 `alpha`（做成 per-symbol 配置，或在视图里维护一张参数表）。

# C. 开/收盘限速（窗口 & 限速参数）

## C1) 找“噪声窗口”的证据

```sql
-- 开/收盘各分钟的 spread/imbalance 特征
WITH b AS (
  SELECT symbol,
         toTimezone(ts,'America/New_York') AS ts_ny,
         spread_bps, abs(imbalance) AS imb
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
)
SELECT
  toHour(ts_ny) AS hh, toMinute(ts_ny) AS mm,
  quantileExact(0.95)(spread_bps) AS p95_spread,
  quantileExact(0.95)(imb) AS imb95,
  avg(spread_bps) AS avg_spread,
  count() AS n
FROM b
GROUP BY hh, mm
ORDER BY hh, mm;
```

通常你会看到 **09:30–09:35**、**15:55–16:00** 的 `p95_spread/imb95` 显著更高 → 就把窗口先定在这两个区间。

## C2) 冷却与目标仓位的建议

* 开盘窗口 **`cool_sec = 20–30`**；收盘窗口 **`cool_sec = 15–20`**；
* 开/收盘窗口 **`max_pos_qty = 正常上限的 15%–30%`**；
* 如果你的策略在开盘极易反转，直接把开盘窗口 `mode: block`（先挡 3–5 分钟）。

# D. “一次性综合评估”快表（看改动对交易覆盖度/收益的影响）

把模拟熔断+动态阈值合在一起，用历史信号估算“放行率/潜在成交量变化”：

```sql
WITH micro AS (
  SELECT symbol, toStartOfMinute(ts) AS m,
         quantileExact(0.95)(spread_bps) AS p95_30s,
         anyLast(imbalance) AS last_imb
  FROM lake.bbo_1s_features
  WHERE ts >= today()-14
  GROUP BY symbol, m
),
sig AS (
  SELECT symbol, ts AS m, prob
  FROM trading.signals_1m
  WHERE d >= today()-14
),
grid AS (
  SELECT
    arrayJoin([0.006,0.008,0.010]) AS alpha,
    {spread:Float64} AS spread_max,
    {imb:Float64} AS imb_max
)
SELECT
  s.symbol, g.alpha,
  -- 动态阈值是否通过
  avg( s.prob >= ({base:Float64} + g.alpha * greatest(m.p95_30s,0)) )                                         AS pass_dyn,
  -- 熔断是否拦截
  avg( (m.p95_30s > g.spread_max) OR (abs(m.last_imb) > g.imb_max) )                                         AS block_micro,
  -- 两者合成后的总体放行率（先过动态阈值，且未被熔断）
  avg( (s.prob >= ({base:Float64} + g.alpha * greatest(m.p95_30s,0))) AND NOT ((m.p95_30s>g.spread_max) OR (abs(m.last_imb)>g.imb_max)) ) AS pass_final
FROM sig s
LEFT JOIN micro m USING(symbol, m)
CROSS JOIN grid g
GROUP BY s.symbol, g.alpha
ORDER BY s.symbol, g.alpha;
```

把 `{base}`、`{spread}`、`{imb}` 换成候选（如 0.55 / 8 / 0.6）。
**挑选**：对大票，`pass_final` ≥ 0.70；对中小票 ≥ 0.60 作为起步。

# E. 建议的“默认起跑线”（如果你想先用一组稳健值）

* `spread_bps_max = 8.0`（**大票**）；`= 10.0–12.0`（**中/小票** or 高波动票）
* `imbalance_abs_max = 0.60`（若太紧，可放到 0.65）
* `lookback_sec = 30`
* 开盘：`09:30–09:35 mode: throttle`（`cool_sec=20`, `max_pos_qty=20%`）；
  收盘：`15:55–16:00 mode: throttle`（`cool_sec=15`, `max_pos_qty=30%`）；
* 动态阈值：`base=0.55, alpha_per_bps=0.008, min=0.52, max=0.80`。
* 如果开盘仍脏：把 **开盘窗口改 block**（3–5 分钟），或暂时把 `alpha_per_bps` 提到 `0.010`。

# F. 监控与回看（上线后一周重点盯这些）

```sql
-- 1) 风控触发频率与原因
SELECT reason, count() AS c
FROM monitor.risk_guard_events
WHERE d >= today()-7
GROUP BY reason ORDER BY c DESC;

-- 2) 被拦分钟 vs 放行分钟 的下分钟回报
-- （与 A4 同，但限制 d>=today()-7）

-- 3) 放行率与成交额变化（日度）
SELECT toDate(ts) AS d, count() AS signals, sumIf(1, signal=1) AS pass,
       pass/signals AS pass_rate
FROM trading.signals_1m
WHERE d >= today()-7
GROUP BY d ORDER BY d;
```

# 落地顺序建议

1. 跑 **A1/A2** 拿到你家票池的分布 → 先按“默认起跑线”落参数；
2. 用 **A3/A4** 验证拦截率与“被拦分钟更差”假说；
3. 跑 **B/D** 做 `alpha` 网格，挑一档满足覆盖度目标的斜率；
4. 小流量灰度（2–3 只大票），观察 **一周**，基于 **F** 的面板微调；
5. 扩大到全票池，再做 **分层参数**（大/中/小票不同 `spread_bps_max` 与 `alpha`）。
