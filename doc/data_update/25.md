# 1) ClickHouse：参数变更审计/注解表（追加到 `ch_init.sql`）

```sql
CREATE DATABASE IF NOT EXISTS monitor;

CREATE TABLE IF NOT EXISTS monitor.param_change_annot
(
  ts             DateTime,                 -- 变更发生/生效时间
  symbol         String,
  actor          String,                   -- 谁触发（GitHub actor / CLI user）
  fields_changed Array(String),            -- ["spread_bps_max","alpha_per_bps", ...]
  message        String,                   -- 人类可读摘要
  payload_json   String,                   -- 完整行（便于排障）
  ver            UInt64,
  d              Date DEFAULT toDate(ts)
)
ENGINE = ReplacingMergeTree(ver)
PARTITION BY d
ORDER BY (d, symbol, ts);
```

> 我们用它做**审计** + **Grafana 注解数据源**。不影响生产链路。

### 2.2 推送完毕后，写审计&注解

在 `push()` 里 `await producer.stop()` 之前，追加：

```python
    # --- after sending to Kafka, write audit rows into ClickHouse
    db = ClickHouseDB()
    ts_us = int(time.time()*1_000_000)
    ver = int(ts_us // 1000)
    audit_rows = []
    for r in rows:
        # 生成“改了哪些字段”的摘要（如果是覆盖更新就把所有显式字段记上）
        changed = [k for k in ["alpha_per_bps","base_threshold","spread_bps_max","imbalance_abs_max",
                               "oc_mode","oc_cool_sec","oc_max_pos_pct","enabled"] if k in r]
        msg = f"{r['symbol']}: " + ", ".join([f"{k}={r[k]}" for k in changed])
        audit_rows.append({
            "ts": datetime.fromisoformat(str(r["effective_from"]).replace("Z","+00:00")).replace(tzinfo=None),
            "symbol": r["symbol"],
            "actor": config.runtime.get("actor", "cli"),   # 可在 CI 里注入
            "fields_changed": changed,
            "message": msg,
            "payload_json": json.dumps(r, ensure_ascii=False),
            "ver": ver
        })
    if audit_rows:
        db.insert("monitor.param_change_annot", audit_rows,
                  ["ts","symbol","actor","fields_changed","message","payload_json","ver"])
```

> 这样每次推参，Grafana 就自动有“调参打点与摘要”。

# 3) Makefile 目标（追加）

```makefile
.PHONY: param-dry param-push
PARAM_FILE ?= tools/params.yml
EFFECTIVE  ?= $(shell date -u +"%Y-%m-%dT%H:%M:%SZ")
ACTOR      ?= $(shell whoami)

param-dry:
	@ACTOR=$(ACTOR) python -m tools.push_symbol_params --yaml $(PARAM_FILE) --dry-run

param-push:
	@echo "Pushing params from $(PARAM_FILE) effective $(EFFECTIVE) by $(ACTOR)"
	@ACTOR=$(ACTOR) python -m tools.push_symbol_params --yaml $(PARAM_FILE) --effective-from "$(EFFECTIVE)"
```

> `ACTOR` 会写进审计表的 `actor` 字段。

# 4) GitHub Actions（PR 校验 + 合并发布）

新建 `.github/workflows/push-params.yml`（你可以直接拷贝）：

```yaml
name: Push Risk Params

on:
  pull_request:
    paths: [ "tools/params.yml" ]
  push:
    branches: [ "main" ]
    paths: [ "tools/params.yml" ]
  workflow_dispatch:
    inputs:
      effective_from:
        description: "ISO time (UTC) e.g. 2025-10-07T13:30:00Z"
        required: false
        default: ""

jobs:
  validate:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - name: Install deps
        run: |
          python -m pip install -U pip
          pip install -r requirements.txt
      - name: Dry-run check
        env:
          ACTOR: ${{ github.actor }}
        run: |
          python -m tools.push_symbol_params --yaml tools/params.yml --dry-run

  deploy:
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    environment: production   # 可配保护规则，需要批准才执行
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - name: Install deps
        run: |
          python -m pip install -U pip
          pip install -r requirements.txt
      - name: Push params to Kafka + audit CH
        env:
          ACTOR: ${{ github.actor }}
        run: |
          EFF="${{ inputs.effective_from }}"
          if [ -z "$EFF" ]; then EFF=$(date -u +"%Y-%m-%dT%H:%M:%SZ"); fi
          python -m tools.push_symbol_params --yaml tools/params.yml --effective-from "$EFF"
```

> 依赖：`requirements.txt` 里确保有 `aiokafka`, `pyyaml`, 以及你 ClickHouse 客户端（你的 `libs.db.clickhouse` 所需）。
> 通过 **Protected Environment** 控制“合并即推参”的审批；也可把 `push` 阶段改为 `manual`（仅 workflow_dispatch）。

# 5) Grafana 注解接入（两步）

1. 打开你任意看板 → **Dashboard settings** → **Annotations** → **Add new**：

   * **Datasource**：ClickHouse
   * **Query**：

     ```sql
     SELECT
       ts as time,
       message as text,
       [symbol, actor] as tags
     FROM monitor.param_change_annot
     WHERE $__timeFilter(ts)
     ORDER BY ts
     ```
   * 勾选 “Show in all panels” / 或按需.

2. 保存。之后每次推参，图上会自动出现纵向注解线，文本是 `message`，tag 里有 `symbol/actor`。
