# P13｜风控参数注册表 & 热更新（最小落地）

## 1) ClickHouse 配置表（支持全局默认 & 按 symbol 覆盖）

**追加到 `ch_init.sql`（只做加法）**

```sql
CREATE DATABASE IF NOT EXISTS config;

CREATE TABLE IF NOT EXISTS config.symbol_risk_params
(
  symbol                 String,                      -- 允许用 '*' 作为全局默认
  alpha_per_bps          Float64   DEFAULT 0.008,     -- 动态阈值斜率
  base_threshold         Float64   DEFAULT 0.55,      -- 动态阈值基础值
  spread_bps_max         Float64   DEFAULT 8.0,       -- 盘口熔断：30s P95 上限
  imbalance_abs_max      Float64   DEFAULT 0.60,      -- 盘口熔断：|imb| 上限
  oc_mode                LowCardinality(String) DEFAULT 'throttle', -- open/close 窗口：block/throttle/none
  oc_cool_sec            Float64   DEFAULT 20,        -- throttle 时冷却秒
  oc_max_pos_pct         Float64   DEFAULT 0.20,      -- throttle 时仓位上限（相对正常上限）
  enabled                UInt8     DEFAULT 1,
  effective_from         DateTime  DEFAULT now(),     -- 生效时间（支持预置未来）
  note                   String    DEFAULT '',
  ver                    UInt64,                      -- metadata.ts_us // 1000
  d                      Date      DEFAULT toDate(effective_from)
)
ENGINE = ReplacingMergeTree(ver)
PARTITION BY d
ORDER BY (symbol, effective_from);

-- 当前生效视图：同 symbol 取最新 effective_from（<= now()）且 ver 最大
CREATE OR REPLACE VIEW config.symbol_risk_params_current AS
SELECT *
FROM
(
  SELECT *
  FROM config.symbol_risk_params
  WHERE effective_from <= now() AND enabled = 1
  ORDER BY symbol, effective_from DESC, ver DESC
)
GROUP BY symbol
ORDER BY symbol;
```

> 约定：若没有某只票的行，就读取 `symbol='*'` 的全局默认。

## 2) Kafka Writer（配置中心也统一走 Kafka，可热更）

`config.yml` 里追加一个通用 writer（沿用你在 P9 做的 `GenericCHWriter`）：

```yaml
generic_writers:
  - name: risk_params_writer
    enabled: true
    topic: "config.symbol_risk_params.v1"
    table: "config.symbol_risk_params"
    group_id: "risk_params_writer.v1"
    columns:
      ["symbol","alpha_per_bps","base_threshold","spread_bps_max","imbalance_abs_max",
       "oc_mode","oc_cool_sec","oc_max_pos_pct","enabled","effective_from","note","ver"]
```

> 后续我们推一条 Kafka 消息就能“上新参数”，CH 视图自动切到最新版本（幂等 by `ReplacingMergeTree(ver)`）。

## 4) 执行器 & Broker 热读参数（60s 缓存）

**SignalExecutor**（增量逻辑）：

* 在 `_dynamic_threshold()` 里优先查 `config.symbol_risk_params_current`：

  ```sql
  SELECT alpha_per_bps, base_threshold
  FROM config.symbol_risk_params_current
  WHERE symbol IN (%(sym)s, '*')
  ORDER BY symbol != '*'  -- 精确匹配优先
  LIMIT 1
  ```
* 在 `_micro_check()` 里拉 `spread_bps_max`/`imbalance_abs_max`；
* 在 `_in_open_close_window()` 里拉 `oc_mode/oc_cool_sec/oc_max_pos_pct`；
* 结果放入 `LRU + TTL=60s` 缓存，过期自动刷新；异常读表时回退到本地 config。

**IBKRBroker** 同样套用（作兜底），查询同一视图，TTL=60s。

> 这样你在 Grafana 校准好阈值 → 用 `push_symbol_params.py` 发一条 Kafka→表即生效 → 执行器/券商侧 1 分钟内热更新，无需重启。

```sql
INSERT INTO config.symbol_risk_params
(symbol, alpha_per_bps, base_threshold, spread_bps_max, imbalance_abs_max, oc_mode, oc_cool_sec, oc_max_pos_pct, enabled, effective_from, note, ver)
VALUES
('*', 0.008, 0.55, 8.0, 0.60, 'throttle', 20, 0.20, 1, now(), 'global default', toUInt64(toUnixTimestamp64Milli(now())));
```

然后针对你的白名单票（如 TSLA/NVDA）各插一行覆盖值（根据我们校准看板的读数）。

## 6) 快速验收 SQL

```sql
-- 当前生效参数（含全局 '*')
SELECT * FROM config.symbol_risk_params_current WHERE symbol IN ('*','TSLA','NVDA') ORDER BY symbol;

-- 执行器/券商侧是否在用新阈值（你在 signals_1m 中会看到新的 threshold）
SELECT ts, symbol, prob, threshold FROM trading.signals_1m
WHERE d = today() AND symbol IN ('TSLA','NVDA')
ORDER BY ts DESC LIMIT 40;

-- 风控事件是否收敛到新阈值区间
SELECT reason, count() FROM monitor.risk_guard_events
WHERE d >= today()-1 GROUP BY reason ORDER BY count() DESC;
```
