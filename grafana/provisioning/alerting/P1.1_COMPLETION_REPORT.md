## 🔍 **告警规则详情**

### P0 Alert #1: Data Staleness

**Query**:
```sql
SELECT round((now() - max(ts_ny)) / 60, 0) as minutes_ago
FROM llm.ibkr_account_realtime
```

**Trigger**: minutes_ago > 60
**For**: 5 minutes
**Severity**: 🔴 critical

**Purpose**: 防止交易员基于过期数据做决策

---

### P0 Alert #2: System Status Critical

**Query**: 综合检查（数据年龄 + 今日成交）

**Trigger**:
- Data > 6小时 old OR
- 市场时间内 0 fills

**For**: 10 minutes
**Severity**: 🔴 critical

**Purpose**: 整体系统健康检查

---

### P1 Alert #3: Zombie Sessions

**Query**:
```sql
SELECT count(*) as zombie_count
FROM llm.llm_sessions
WHERE status = 'RUNNING' AND (now() - start_ts_ny) > 86400
```

**Trigger**: zombie_count > 10
**For**: 15 minutes
**Severity**: 🟠 warning

**Purpose**: 防止资源泄漏

---

### P1 Alert #4: AI Brain P95 Latency

**Query**: 最近1小时 P95延迟

**Trigger**: p95_latency > 60s
**For**: 30 minutes
**Severity**: 🟡 warning

**Purpose**: 性能下降检测

---

### P1 Alert #5: Slow Calls Spike

**Query**: 最近1小时 >60s 调用数

**Trigger**: slow_count > 20
**For**: 15 minutes
**Severity**: 🟡 warning

**Purpose**: 异常性能尖峰检测

---

### P1 Alert #6: No Fills During Market Hours

**Query**: 最近2小时成交数

**Trigger**: fill_count = 0

## 🎯 **告警触发逻辑**

### Alert Evaluation Flow

```
每 1 分钟 (interval: 1m)
  ↓
执行 ClickHouse 查询
  ↓
评估条件 (Condition C)
  ↓
满足阈值?
  ├─ No  → 重置计时器
  └─ Yes → 开始计时 (For 时间)
           ↓
           持续满足 For 时间?
           ├─ No  → 重置计时器
           └─ Yes → 🚨 **FIRE ALERT**
                    ↓
                    发送到 Contact Point
                    ↓
                    等待 Repeat Interval (4h)
                    ↓
                    如果仍满足条件，再次发送
```

**Example**: Data Staleness Alert
```
t=0:    数据年龄 = 65 min (> 60) → 开始计时
t=1min: 数据年龄 = 66 min (> 60) → 计时继续
t=2min: 数据年龄 = 67 min (> 60) → 计时继续
t=3min: 数据年龄 = 68 min (> 60) → 计时继续
t=4min: 数据年龄 = 69 min (> 60) → 计时继续
t=5min: 数据年龄 = 70 min (> 60) → 🚨 FIRE! (For 时间满足)
```

## 🛠️ **故障排查**

### Problem: 告警规则未出现

**Solution**:
```bash

docker logs trading_grafana | grep -i alert
```

## 💡 **最佳实践**

### 1. 合理的 "For" 时间

✅ **Good**:
- P0 Critical: 5-10 分钟 (快速响应)
- P1 Warning: 15-30 分钟 (避免短暂尖峰)

❌ **Bad**:
- For = 0 (任何短暂波动都告警 → 告警疲劳)
- For = 2h (问题已经很严重才告警)

---

### 2. 避免告警风暴

✅ **Good**:
- 使用 `group_wait` 和 `group_interval` 聚合告警
- 设置合理的 `repeat_interval` (4-12小时)

❌ **Bad**:
- 每分钟重复发送相同告警
- 10个相关告警各自发送（应该聚合）

---

### 3. 可操作的告警描述

✅ **Good**:
```yaml
summary: "Data is {{ $values.A.Value }} minutes old (> 60)"
description: |
  **Action Required**:
  1. Check data ingestion service
  2. Verify ClickHouse connection
  3. Run: python scripts/restart_ingestion.py

  **Runbook**: https://wiki/runbooks/data-staleness
```

❌ **Bad**:
```yaml
summary: "Alert triggered"
description: "Something is wrong"
```
