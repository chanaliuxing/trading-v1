### 1. 数据库迁移脚本
**文件**: `scripts/migrations/clickhouse/20251101_add_error_tracking_to_brain_calls.sql`
**内容**:
```sql
-- Add new columns to existing table
ALTER TABLE llm.ai_brain_calls
    ADD COLUMN IF NOT EXISTS success UInt8 DEFAULT 1,
    ADD COLUMN IF NOT EXISTS error_type String DEFAULT '',
    ADD COLUMN IF NOT EXISTS error_message String DEFAULT '',
    ADD COLUMN IF NOT EXISTS fallback_used UInt8 DEFAULT 0,
    ADD COLUMN IF NOT EXISTS providers_attempted Array(String) DEFAULT [];
```

**字段说明**:
- `success`: 1 = 成功, 0 = 失败
- `error_type`: 错误类型 (`''` | `'timeout'` | `'api_error'` | `'json_parse_error'` | `'all_providers_failed'`)
- `error_message`: 详细错误信息
- `fallback_used`: 1 = 使用了 fallback, 0 = primary provider 成功
- `providers_attempted`: 尝试过的 provider 列表 (e.g., `['deepseek_nvidia', 'gemini']`)

**执行结果**: ✅ 5 个字段成功添加

### 2. ProviderPool 更新
**文件**: `scripts/ai_trader/brain/provider_fallback.py`
**修改**: 添加 LLMCallResult NamedTuple, 更新 call_with_fallback 返回类型

**Before**:
```python
async def call_with_fallback(...) -> Tuple[Dict[str, Any], str, str]:
    # Returns: (data, raw, provider_used)
    return data, raw, provider_name
```

**After**:
```python
class LLMCallResult(NamedTuple):
    data: Dict[str, Any]
    raw: str
    provider_used: str
    success: bool
    error_type: str
    error_message: str
    fallback_used: bool
    providers_attempted: List[str]

async def call_with_fallback(...) -> LLMCallResult:
    # Returns detailed result with error tracking
    return LLMCallResult(
        data=data,
        raw=raw,
        provider_used=provider_name,
        success=True,
        error_type="",
        error_message="",
        fallback_used=is_fallback,
        providers_attempted=providers_attempted
    )
```

**关键改进**:
- 不再抛出异常 (all providers failed 时返回 success=False)
- 记录所有尝试过的 providers
- 分类错误类型 (timeout/api_error/json_parse_error)

async def _ask(...) -> LLMCallResult:

### 错误类型定义

| error_type | 含义 | 示例场景 |
|------------|------|----------|
| `''` (empty) | 成功 | Provider 正常返回 JSON |
| `'timeout'` | 超时 | Provider 调用超过 timeout 时间 |
| `'api_error'` | API 错误 | Provider API 返回 4xx/5xx |
| `'json_parse_error'` | JSON 解析失败 | 响应不是有效 JSON |
| `'all_providers_failed'` | 所有 provider 失败 | fallback chain 全部失败 |
| `'unexpected_error'` | 意外错误 | 其他未预期的异常 |

### 2. 存储成本

**新增字段存储开销**:
- `success` (UInt8): 1 byte/record
- `error_type` (String): ~10 bytes/record (average)
- `error_message` (String): ~50 bytes/record (average, only when failed)
- `fallback_used` (UInt8): 1 byte/record
- `providers_attempted` (Array(String)): ~20 bytes/record (average)

**总计**: ~82 bytes/record

**估算**:
- 100 calls/day → 8.2 KB/day → 3 MB/year
- 1000 calls/day → 82 KB/day → 30 MB/year

**结论**: 存储成本可忽略

---

### 3. 查询性能

**新字段已添加到表**: ✅
**但未添加到 ORDER BY**: ⚠️

**影响**:
- 按 `success` 或 `error_type` 过滤需要全表扫描
- 对于大数据量 (>100M 记录), 可能较慢
