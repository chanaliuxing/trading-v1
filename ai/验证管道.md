Below is a concrete end-to-end validation script for the ML brain loop/auto loop. It walks the pipeline in order (data →
  features → labels → preflight/heal → OOF/HPO → evaluation/reflection) with real data, and spells out commands, what to look
  for, and pass/fail criteria. Run from repo root; keep env vars as shown.

  0. Environment prep (one-time)

  - Ensure ClickHouse reachable: clickhouse-client -q "SELECT 1" (expect 1).
  - Set LLM to local: export LLM_BASE_URL=http://localhost:11434 LLM_MODEL=qwen2.5vl:latest
    LLM_LOCAL_MODELS=qwen2.5vl:latest,my-deepseek-uncensored:latest,fast-local-1:latest,fast-local-2:latest CRITIC_ENABLED=1.
  - Optional: enable nightly evolver sandbox while testing: export ENABLE_EVOLVER_SANDBOX=0 (keep off until data passes).

  1. Bar/backfill health

  - Command: python tool/load_hist_multi.py --symbols TSLA NVDA --days 3 --bar-size 1m --fill-mode backfill --skip-covered-days
    --use-rth
  - Expect: no gap_scan_clickhouse_failed/MEMORY_LIMIT_EXCEEDED in stdout; inserted row counts > 0.
  - Verify CH: clickhouse-client -q "SELECT symbol, max(ts_start) FROM trading.bars_1m_ibkr WHERE symbol IN ('TSLA','NVDA')
    GROUP BY symbol"

  2. Features computation

  - Command: python pipelines/rebuild_features_1m.py --symbols TSLA NVDA --start $(date -v-3d +%Y-%m-%d) --end $(date +
    %Y-%m-%d)
  - Expect: no errors; rows written logged.
  - Verify CH: clickhouse-client -q "SELECT symbol, count() FROM trading.features_1m WHERE symbol IN ('TSLA','NVDA') AND ts >=
    now()-INTERVAL 3 DAY GROUP BY symbol"

  3. Labels generation sanity

  - Command: python tools/recompute_labels_1m.py --symbols TSLA,NVDA --start "$(date -v-3d '+%Y-%m-%d 00:00:00')" --end "$(date
    '+%Y-%m-%d 23:59:59')" --horizon-min 30 --table trading.features_1m_with_labels
  - Expect: no TABLE_ALREADY_EXISTS/column mismatch; counts > 0.
  - Verify null ratio: clickhouse-client -q "SELECT symbol, count() cnt, countIf(label_h30 IS NULL) nulls, nulls/cnt null_ratio
    FROM trading.features_1m_with_labels WHERE symbol IN ('TSLA','NVDA') AND ts >= now()-INTERVAL 3 DAY GROUP BY symbol"

  4. Preflight + healer

  - Command: python scripts/ai_trader/brain/preflight.py TSLA NVDA
  - Expect: OVERALL READY: True or if not, report blocking issues without exceptions.
  - If not ready: run healer: python - <<'PY'\nfrom services.data.data_healer import DataHealer\nh=DataHealer('runs/
    ai_trader')\nprint(h.ensure_labels_ready(['TSLA','NVDA'], horizons=[30]))\nPY
  - Verify no preflight_label_heal_failed in logs.

  5. Critic/heuristics wiring

  - Populate heuristics (simple rule): python scripts/ai_trader/memory/consolidate_knowledge.py --lookback-days 30 --min-sample
    30 --sharpe-threshold -0.2
  - Verify CH: clickhouse-client -q "SELECT advice, confidence FROM trading.knowledge_heuristics ORDER BY created_at DESC LIMIT
    5"
  - Trigger brain plan: python scripts/ai_trader/brain/brain.py (or your entry) with a minimal context containing regime and
    strategy. Expect either a normal plan or blocked_by_critic when should_block=True; no KeyErrors.

  6. OOF/HPO run (light smoke)

  - Command: python scripts/ai_trader/ml_scheduler.py --job-type oof --mode light --symbols TSLA,NVDA --window-days 30
  - Expect: horizon grid [30,60,120] logged; no zero n_train; no high_nulls blocking; no ClickHouse schema errors.
  - Check run logs: runs/ai_trader/*/oof_flow_status.json and ml_events.jsonl for the job_id; ensure ok:true and metrics
    present.

  7. Label diagnostics (regression of earlier failures)

  - Command: python scripts/ai_trader/ml_scheduler.py --job-type label_diagnostics --symbols TSLA,NVDA
  - Expect: no Unknown identifier y or column mismatch; metrics show nonzero rows; null_labels reasonable.

  8. Evolution pipeline logging (optional, after ML success)

  - Manually trigger sandbox evolver: ENABLE_EVOLVER_SANDBOX=1 python scripts/automation/evening_review.sh
  - Expect: runs/ai_trader/evolver_*.json and evolution_experiments.jsonl appended; scripts/ai_trader/evolvers/
    import_evolution_experiments.py runs (hooked in evening_review) and CH table trading.evolution_experiments gets new
    rows: clickhouse-client -q "SELECT experiment_id, target_skill, test_result FROM trading.evolution_experiments ORDER BY
    created_at DESC LIMIT 5"

  9. LLM local model sanity

  - Ollama direct: curl http://localhost:11434/api/generate -H "Content-Type: application/json" -d
    '{"model":"qwen2.5vl:latest","prompt":"{\"msg\":\"hello\"}","stream":false}' (expect 200, response text).
  - Client parse: LLM_BASE_URL=http://localhost:11434 LLM_LOCAL_MODELS=qwen2.5vl:latest,my-deepseek-uncensored:latest,fast-
    {'msg':'hello'} parsed, not offline fallback).

  10. Full ML brain loop smoke (end-to-end)

  - Command: python ml_brain_loop.py --once (or your auto loop entry) with CRITIC_ENABLED=1 and local LLM env set.
  - Monitor logs: ensure sequence executes without uncaught exceptions: preflight → healer (if needed) → feature/label
    readiness → OOF/HPO → evaluation → reflection. Check runs/ai_trader/<date>/ml_events.jsonl for final ok:true and no
    preflight_label_heal_failed / label_diagnostics_failed / oof_diagnosis_failed.

  Pass/fail summary for Gemini:

  - Fail if any step produces schema/KeyError, memory limit errors, zero training rows, or offline LLM fallback when Ollama
    is reachable.
  - Pass when each command completes without errors and the ClickHouse checks show expected rows/ratios, and plans/train runs
    produce metrics.
